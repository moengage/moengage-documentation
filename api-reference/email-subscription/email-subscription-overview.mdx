## Overview

The MoEngage Email Subscription Management APIs allow you to update email preferences for your users directly within the MoEngage platform. This suite enables you to synchronize resubscription status with external Email Service Providers (ESPs) and manage granular category-level opt-ins to ensure compliance and a better user experience

<Info>
  The **Update User Email Opt-in Preferences** API is currently an **Early Access** feature. Contact your MoEngage Customer Success Manager (CSM) or the Support team to enable it for your account.
</Info>

## Email Subscription Endpoints

This suite consists of the following key management APIs:

- [Bulk Resubscribe Users](/api-reference/emails/bulk-resubscribe) - Resubscribe users and optionally update ESP suppression lists.
- [Update User Email Opt-in Preferences](/api-reference/emails/opt-in-management) - Update overall opt-in status and category-specific preferences.

## Implementation Notes

<Note>
  **ESP Support:** The Resubscription API currently supports **SendGrid** only. When `update_esp` is set to `true`, MoEngage automatically removes the email addresses from your SendGrid suppression list.
</Note>

<Note>
  **Identity Management for Opt-in:**

  - **PII Tokenization:** You must pass the `customer_id`. MoEngage uses this to locate the user as the email ID is not stored.
  - **PII Encryption:** Pass either the `customer_id` or the decrypted `email_id`. If only the email ID is passed, all users associated with that email will be updated.
</Note>

## FAQs

### Resubscription

<AccordionGroup>
  <Accordion title="What happens if an email address matches multiple profiles during resubscription?">
    If an email address matches multiple profiles, all associated profiles will be marked as resubscribed (the unsubscribe flag will be set to false) on the MoEngage dashboard.
  </Accordion>
  <Accordion title="How do I verify the status of a bulk resubscribe request?">
    The Bulk Resubscribe API processes requests asynchronously. Upon success, it returns a 202 Accepted status with a `response_id`.
  </Accordion>
</AccordionGroup>

### Opt-in & Categories

<AccordionGroup>
  <Accordion title="How do category preferences interact with the overall opt-in status?">
    MoEngage prioritizes category-level information. If you pass a list of categories where all values are `false`, the overall `opt_in_status` will be updated to **OPTED_OUT**, even if you explicitly passed **DOUBLE_OPTED_IN** in the same request.
  </Accordion>
  <Accordion title="What happens if I include an inactive category in the request?">
    If even one category passed in the `categories` object is invalid or inactive in your MoEngage Workspace, the entire API request will fail with a 400 Bad Request error.
  </Accordion>
  <Accordion title="Can I manage channels other than email?">
    Currently, the Opt-in Management API only supports the **email** channel.
  </Accordion>
</AccordionGroup>
