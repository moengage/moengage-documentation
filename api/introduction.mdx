The MoEngage REST APIs let you manage user data, campaigns, segments, content, and integrations without the dashboard. Every endpoint uses standard HTTP methods, Basic Authentication, and JSON request and response bodies.

This reference covers the available API categories, along with the data centers, base URLs, authentication, rate limits, and error handling that apply across them.

## Data Centers

MoEngage maintains multiple data centers. You are assigned to a specific data center when you sign up. You can identify your data center from your dashboard URL.

| Data Center | Dashboard URL | REST API Host |
| --- | --- | --- |
| DC-01 | `https://dashboard-01.moengage.com` | `https://api-01.moengage.com` |
| DC-02 | `https://dashboard-02.moengage.com` | `https://api-02.moengage.com` |
| DC-03 | `https://dashboard-03.moengage.com` | `https://api-03.moengage.com` |
| DC-04 | `https://dashboard-04.moengage.com` | `https://api-04.moengage.com` |
| DC-05 | `https://dashboard-05.moengage.com` | `https://api-05.moengage.com` |
| DC-06 | `https://dashboard-06.moengage.com` | `https://api-06.moengage.com` |
| DC-101 | `https://dashboard-101.moengage.com` | `https://api-101.moengage.com` |

### Choosing a Data Center

If you have data privacy requirements to store user data in a specific geographical region:

- **US region**: Sign up with DC-01 or DC-04
- **EU region**: Sign up with DC-02
- **India region**: Sign up with DC-03
- **Singapore region**: Sign up with DC-05
- **Indonesia region**: Sign up with DC-06

<Warning>
  After data is captured in a workspace, it cannot be migrated to a different data center. Always use the REST API endpoint matching your registered data center.
</Warning>

## Base URL

All API requests are made to:

```text
https://api-{dc}.moengage.com
```

Replace `{dc}` with your data center number (e.g., `01`, `02`, `03`). You can identify your data center from your Dashboard URL.

<Note>
  Each API may have additional path segments (e.g., `/v1`, `/core-services/v1`). Refer to the specific API documentation for the complete endpoint path.
</Note>

## Authentication

MoEngage REST APIs use HTTP Basic Authentication. Send your **Workspace ID** as the username and an **API key** as the password, Base64-encoded in the `Authorization` header of every request.

### Required Headers

```http
Authorization: Basic {base64_encoded_credentials}
Content-Type: application/json
```

The `Authorization` header value is the Base64 encoding of `workspace_id:api_key`:

```bash Encoding Credentials
echo -n "YOUR_WORKSPACE_ID:YOUR_API_KEY" | base64
```

<Note>
  Some endpoints also require a `MOE-APPKEY` header set to your Workspace ID. For Data APIs, this header is required only for File Import APIs and the Test Connection API. It is not required for core Data APIs such as Track User, Get User, Track Event, Merge User, Delete User, and Track Device. Check the reference page for the endpoint you are calling.
</Note>

### Getting Your Credentials

Create and manage API keys from the API key dashboard. Each key is scoped to the APIs you select, so you can issue separate keys for different integrations or teams.

<Steps>
  <Step title="Open the API key dashboard">
    In the [MoEngage dashboard](https://dashboard.moengage.com), go to **Settings** \> **Account** \> **API keys**. Copy the **Workspace ID** shown on this page — it is the same for every key in the workspace.
  </Step>

  <Step title="Create a key">
    Click **\+ Create new key**, enter a **Key name** that identifies where the key is used, and select the APIs the key can call under **Select APIs for access**. Click **Save**.

    ![The Create new key page with a Key name field and the Select APIs for access checkbox list](/images/moengage_685ea1.png)

    The key is listed under **Active API keys** with an **API Access** value of **Full** if it covers every listed API, or **Partial** if it covers a subset.
  </Step>

  <Step title="Copy the key value">
    Click <Icon icon="ellipsis-stroke-vertical" /> for the key and select **View key details** to copy the key. Store it in your secret manager and treat it like a password.
  </Step>
</Steps>

A key works only for the APIs selected on it. A request sent with a key that does not cover the API you are calling fails with `401` or `403`. To change what a key covers, open **View key details** and select **Edit key details**.

You can also authenticate from a client such as Postman by entering the Workspace ID as the username and the API key as the password under Basic Auth:

![Postman Basic Auth configuration with the Workspace ID as the username and the API key as the password](/images/authorization.png)

### Rotating a Key

Regenerating a key invalidates the old value immediately, so every caller using it starts failing. To rotate without downtime:

1. Create a second key with the same access.
2. Move your integrations to the new key.
3. Archive the old key. Archiving is permanent — a key cannot be unarchived.

For key details, regeneration, archiving, legacy keys, and the audit log of key actions, refer to [API Key Dashboard](/user-guide/settings/account/api-and-api-keys/api-key-dashboard).

### If You Are Not on the API Key Dashboard Yet

The API key dashboard is an Early Access feature. To enable it for your account, contact your MoEngage Customer Success Manager (CSM) or the Support team.

Until it is enabled, get your credentials from **Settings** \> **Account** \> **APIs**. That page holds one key per feature instead of scoped keys:

| API | API key |
| --- | --- |
| Data | Data |
| Push | Push |
| Inform | Inform |
| Campaigns and Catalog | Campaign report/Business events/Custom templates/Catalog API/Inform Report |
| Personalize | Personalize |

Regenerating a key on this page invalidates the old key immediately, and there is no second active key to fall back on. Update every caller before you regenerate.

## Rate Limits

MoEngage enforces per-workspace rate limits and payload caps on its REST APIs. Requests that exceed a rate limit receive an `HTTP 429` response; oversized payloads receive `HTTP 413` (or `400`). Rate-limited responses include `x-ratelimit-limit`, `x-ratelimit-remaining`, and `x-ratelimit-reset` headers so you can track remaining capacity in real time.

For the full per-endpoint breakdown — rate limits, payload size caps, monitoring headers, and how to request an increase — see [Rate Limits](/api/rate-limits).

## Error Handling

Most MoEngage APIs return errors in the standard format below.

### Standard Error Format

```json wrap
{
  "status": "fail",
  "error": {
    "message": "The request parameters are invalid",
    "type": "Bad Request",
    "request_id": "abc123xyz"
  }
}
```

<Note>
  Newer v5 APIs, such as [Flows](/api/flows/flows-overview), use a different error envelope: `{ response_id, error: { code, message, target, details } }`. Refer to the specific API's reference for its exact error shape.
</Note>

### HTTP Status Codes

| Code | Description |
| --- | --- |
| `200` | Success |
| `201` | Created |
| `202` | Accepted (async processing) |
| `400` | Bad Request - Invalid parameters |
| `401` | Unauthorized - Invalid credentials |
| `403` | Forbidden - Access denied |
| `404` | Not Found - Resource doesn't exist |
| `409` | Conflict - Duplicate resource |
| `413` | Payload Too Large |
| `429` | Rate Limit Exceeded |
| `500` | Internal Server Error |
