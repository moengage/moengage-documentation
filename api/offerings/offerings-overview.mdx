Use the Offerings API to manage offerings programmatically. You can create time-bounded promotions and personalized content, update scheduling or targeting on existing offerings, list offerings for reporting or orchestration workflows, and list the personalization templates available for offering content.

<Info>
  If this API is not enabled for your account, contact your MoEngage Customer Success Manager (CSM) or the Support team to request enablement.
</Info>

## Endpoints

The Offerings API includes the following endpoints:

- [List Offerings](/api/public-offerings/list-offerings): Returns a paginated list of offerings, with filtering by ID, name, status, tags, date range, and creator.
- [Create Offering](/api/public-offerings/create-offering): Creates an offering in your workspace, including content, scheduling, segmentation, and variation configuration.
- [Update Offering](/api/public-offerings/update-offering): Partially updates an existing offering. Only the fields in the request body are changed.
- [List Templates](/api/public-offerings/list-templates): Returns a paginated list of the personalization templates available in your workspace. Use a template `id` as `meta.templateId` in offering content.

## Authentication

All endpoints use Basic Auth. Pass your MoEngage Workspace ID (App ID) as the username and your API key (from the **Personalize** tile) as the password.

## Idempotency

The Create and Update endpoints require an `Idempotency-Key` header (UUID v4). Reusing the same key within 24 hours returns the original response without re-running the operation, so retries on network failures are safe.

## Rate Limits

Rate limits are 100 requests per minute, 300 per hour, and 600 per day, per workspace. Each response includes `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` (the UTC epoch second when the current window resets). If a limit is exceeded, the API returns `429` with a `Retry-After` header. The `429` response does not count against your quota.
