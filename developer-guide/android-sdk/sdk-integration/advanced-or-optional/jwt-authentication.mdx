Without backend enablement, all event sync requests will return **502 Bad Gateway** errors and data collection will completely fail. Contact your MoEngage account manager or support team to enable JWT Authentication on your workspace before proceeding with the steps below.
</Warning>

## Overview

JWT (JSON Web Token) authentication is a standard method for securely verifying user identity. By implementing JWT authentication, you add a critical layer of security to your data collection process with MoEngage.

The feature ensures that the data sent on behalf of your identified users is authentic and is not tampered with. This security is achieved by requiring a token that is cryptographically signed by your own server, which prevents unauthorized users from impersonating your legitimate users.

<Check>
  Before you begin the implementation, ensure you meet the following requirements:

  - Your application must use the MoEngage Android SDK version **14.04.00** or higher to access the JWT authentication feature.
  - You must have access to your MoEngage dashboard to manage public keys and configure the feature's enforcement settings.
</Check>

## Integration

Perform the following to integrate JWT authentication into your Android application:

### Step 1: Enable JWT Authentication

You can enable JWT authentication during [SDK initialization](/developer-guide/android-sdk/sdk-integration/basic-integration/sdk-initialization) by configuring the `NetworkAuthorizationConfig` property on the `MoEngage.Builder` object.

<CodeGroup>

```kotlin Kotlin wrap
import com.moengage.core.DataCenter
import com.moengage.core.MoEngage
import com.moengage.core.config.network.NetworkAuthorizationConfig
import com.moengage.core.config.network.NetworkRequestConfig

val moEngage = MoEngage.Builder(
        application = application,
        appId = "YOUR_WORKSPACE_ID",
        dataCenter = DataCenter.DATA_CENTER_<YOUR_REGION>
    )
    .configureNetworkRequest(NetworkRequestConfig(NetworkAuthorizationConfig(isJwtEnabled = true)))
    .build()
MoEngage.initialiseDefaultInstance(moEngage)
```


```java Java
import com.moengage.core.DataCenter;
import com.moengage.core.MoEngage;
import com.moengage.core.config.network.NetworkAuthorizationConfig;
import com.moengage.core.config.network.NetworkRequestConfig;

MoEngage moEngage = new MoEngage.Builder(application, "YOUR_WORKSPACE_ID", DataCenter.DATA_CENTER_<YOUR_REGION>)
    .configureNetworkRequest(new NetworkRequestConfig(new NetworkAuthorizationConfig(true)))
    .build();
MoEngage.initialiseDefaultInstance(moEngage);
```

</CodeGroup>

### Step 2: Pass the JWT to the SDK

Your application is responsible for managing the JWT lifecycle. The recommended flow is to fetch a token upon user login and pass the token to the SDK. You should also check if the token has expired on subsequent app launches and fetch a new one if necessary. 

Use the [**_MoECoreHelper.passAuthenticationDetails()_**](https://moengage.github.io/android-api-reference/core/com.moengage.core/-mo-e-core-helper/pass-authentication-details.html) to provide the token to the SDK.

<CodeGroup>

```kotlin Kotlin wrap
import com.moengage.core.MoECoreHelper
import com.moengage.core.model.authentication.AuthenticationData

val data = AuthenticationData.Jwt("YOUR_JWT_TOKEN", "USER_IDENTIFIER")
MoECoreHelper.passAuthenticationDetails(context, data)
```


```java Java
import com.moengage.core.MoECoreHelper;
import com.moengage.core.model.authentication.AuthenticationData;

AuthenticationData data = new AuthenticationData.Jwt("YOUR_JWT_TOKEN", "USER_IDENTIFIER");
MoECoreHelper.INSTANCE.passAuthenticationDetails(application.getApplicationContext(), data);
```

</CodeGroup>

### Step 3: Handle Authentication Errors

To handle token validation errors that the MoEngage server returns, register an [**_OnAuthenticationError_**](https://moengage.github.io/android-api-reference/core/com.moengage.core.model.authentication/-on-authentication-error/index.html) listener. The SDK invokes this listener when an authentication error occurs, which allows your application to fetch and provide a new token. Register the listener in a global scope, such as the `onCreate()` of your `Application` class, to ensure your application always receives callbacks.

<CodeGroup>

```kotlin Kotlin wrap
import com.moengage.core.MoECoreHelper
import com.moengage.core.model.authentication.AuthenticationError
import com.moengage.core.model.authentication.ErrorData
import com.moengage.core.model.authentication.JwtError
import com.moengage.core.model.authentication.OnAuthenticationError

// Register in Application.onCreate(), after MoEngage.initialiseDefaultInstance()
val authErrorListener = OnAuthenticationError { error ->
  when (error.data) {
    is ErrorData.Jwt -> {
       val errorData = error.data as ErrorData.Jwt
       val jwtError = errorData.code
       val message = errorData.message
       // Fetch a new token and call MoECoreHelper.passAuthenticationDetails() with the refreshed token
    }
  }
}
MoECoreHelper.registerAuthenticationListener(authErrorListener)
```


```java Java
import androidx.annotation.NonNull;
import com.moengage.core.MoECoreHelper;
import com.moengage.core.model.authentication.AuthenticationError;
import com.moengage.core.model.authentication.ErrorData;
import com.moengage.core.model.authentication.JwtError;
import com.moengage.core.model.authentication.OnAuthenticationError;

// Register in Application.onCreate(), after MoEngage.initialiseDefaultInstance()
OnAuthenticationError errorListener = new OnAuthenticationError() {
  @Override
  public void onError(@NonNull AuthenticationError error) {
      switch (error.getType()) {
          case JWT:
              ErrorData.Jwt jwtError = (ErrorData.Jwt) error.getData();
              JwtError jwtErrorType = jwtError.getCode();
              String message = jwtError.getMessage();
              // Fetch a new token and call MoECoreHelper.INSTANCE.passAuthenticationDetails() with the refreshed token
              break;
      }
  }
};
MoECoreHelper.INSTANCE.registerAuthenticationListener(errorListener);
```

</CodeGroup>

<Info>
  - If an API request fails due to an authentication error, the SDK will not retry the request until your application provides a new token.
  - After 10 consecutive authentication failures in a single session, the SDK will stop attempting to sync data until the next session begins. This counter resets after any successful sync.
  - Upon user logout, if a data sync fails due to a JWT error, the pending data will be deleted, and no retry will be attempted.
</Info>

## Verify the Integration

To confirm JWT authentication is working:

1. Build and run the app on a device or emulator.
2. Trigger a user identification call (for example, call `MoECoreHelper.passAuthenticationDetails()` after login).
3. Check logcat for a successful sync log. If JWT is misconfigured, you will see a `502 Bad Gateway` error in the logs.
4. To test the error callback, pass an expired or invalid token and confirm your `OnAuthenticationError` listener fires.

If you see repeated `502` errors, confirm that JWT Authentication has been enabled on your workspace by the MoEngage support team.
