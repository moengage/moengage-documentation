---
title: "Deprecation for Older Platform Versions"
description: "Review deprecated Android API levels and iOS versions in MoEngage SDK releases after April 2025."
---

Starting April 26, 2025 for Android and May 27, 2025 for iOS, MoEngage SDK releases require a minimum of Android API level 23 and iOS 13. Releases before these dates continue to support [Android API level](https://source.android.com/docs/setup/reference/build-numbers) 21 and 22 (Android 5, Lollipop) and iOS 12.

The minimum supported versions after these dates are:

- Android API level 21 and 22 → API level 23 (Android 6, Marshmallow)
- iOS 12 → iOS 13

## Why Is Support Being Discontinued for API Level 21, 22, and iOS 12?

### For Android

Android 5 (Lollipop) is over 8 years old and represents a very small percentage of active Android devices. Many developers have already raised the minimum API level in their apps to use newer platform capabilities. Raising the minimum supported API level allows MoEngage to develop and ship SDK features more efficiently.

### For iOS

iOS 12 is over 6 years old and represents a very small percentage of active iOS devices. Dropping support for iOS 12 allows MoEngage to use APIs and frameworks that are unavailable on that version.

## What This Means for Your App

SDK versions released before April 26, 2025 (Android) and May 27, 2025 (iOS) continue to work on Lollipop and iOS 12 devices as before.

When upgrading to SDK versions released after those dates, you will not encounter any issues if your app already supports:

- Android API level 23 or greater (set as `minSdkVersion` in `build.gradle`)
- iOS 13 or greater

If your app targets a lower API level or iOS version, a build error will occur. To resolve this, choose one of the following options.

### For iOS

To raise the minimum iOS version in your project:

1. Open your target in Xcode and go to the **General** tab.
2. In the **Deployment Info** section, select **iOS 13** or higher from the **Deployment Target** drop-down.
3. If your app targets multiple device types (iPhone, iPad, and so on), set the minimum iOS version for each.

### For Android

**Option 1 — Raise the minimum API level (recommended)**

Update `minSdkVersion` in your app's `build.gradle` to at least `23`. Users on devices below that API level will not receive the update from the Play Store but can continue using the last compatible version of your app.

**Option 2 — Build multiple APKs (not recommended)**

If a significant portion of your users are on devices below API level 23, you can use [multiple APK support](https://developer.android.com/training/multiple-apks/api.html) to deliver separate APKs for different API levels, each using a different version of the MoEngage SDK.

Use [build variants](https://developer.android.com/studio/build/build-variants.html) in Gradle to define product flavors for legacy and current API levels. For example:

<CodeGroup>

```kotlin build.gradle
productFlavors {
    legacy {
        minSdkVersion 21
        versionCode 2101 // Min API level 21, v01
    }
    current {
        minSdkVersion 23
        versionCode 2301 // Min API level 23, v01
    }
}
dependencies {
    legacyImplementation 'com.moengage:moe-android-sdk:<legacy-version>'
    currentImplementation 'com.moengage:moe-android-sdk:<current-version>'
}
```

</CodeGroup>

If the newer SDK version exposes APIs unavailable in the legacy version, create a compatibility library that abstracts those calls:

1. Define a Java interface that exposes the functionality you need.
2. Build two Android libraries that implement the interface — one using the newer SDK APIs, one that no-ops or falls back gracefully.
3. Compile each library into the appropriate flavor using `legacyImplementation` and `currentImplementation`.
4. In your app code, call through the compatibility library wherever newer SDK APIs are required.

Publish both APKs to the Play Store. Each device will receive the most appropriate version. For more information, see [multiple APK support in the Play Store](https://developer.android.com/google/play/publishing/multiple-apks).
