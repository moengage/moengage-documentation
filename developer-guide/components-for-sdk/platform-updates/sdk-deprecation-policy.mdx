MoEngage SDKs evolve continuously to improve performance, message reachability and deliverability, SDK footprint, and compatibility with current operating system and app store requirements. As newer versions ship, older versions are deprecated. This page explains how that process works and what it means for you.

<Note>
  For minimum supported OS and platform versions, see [Deprecation for Older Platform Versions](/developer-guide/components-for-sdk/platform-updates/deprecation-for-older-platform-versions).
</Note>

## Rationale for SDK Version Deprecation

Newer SDK versions bring performance improvements, better message reachability and deliverability, a smaller SDK footprint, and support for the operating system and platform requirements that Apple, Google, and the app stores continue to raise. Older versions cannot maintain parity with these requirements over time.

Deprecation defines which versions MoEngage actively supports, so the SDK running in your app stays current. Maintaining an unbounded set of old versions slows the improvements MoEngage can ship and leaves customers on older versions without fixes and capabilities they would benefit from.

MoEngage deprecates older versions to keep investing in the versions you should be on, and to give you a clear signal when to upgrade, with advance notice ahead of the effective date.

## Impact of SDK Deprecations on Your App

### Data Flow

Deprecation does not stop your app from sending data, and it does not stop MoEngage from receiving it. MoEngage does not block traffic on deprecated versions. Push, in-app, and analytics continue to function to the extent the version you are on supports them.

Apps already installed on your users' devices continue to run. The SDK binary is already built into those apps. The app itself does not crash or freeze.

### Support

Once a version is deprecated, MoEngage no longer debugs, fixes, or provides support for issues specific to that version. If you raise an issue on a deprecated version, the recommended first step is to upgrade to a supported version, where the fix is available.

### Bug Fixes and Security Patches

When MoEngage resolves an issue, the fix ships in the current and supported major versions. Deprecated versions do not receive fixes. To receive a fix, upgrade to the current or a supported version. Where an upgrade requires integration changes, a migration guide is provided; where it is straightforward, your Customer Success Manager and the Support team can help you through it.

### New Development

Apps already in production continue to work. When you ship a new app build, use a supported SDK version. Deprecated versions might not remain available on public package registries or store tooling, and supported versions carry current fixes and capabilities.

## Deprecation Notifications

MoEngage notifies you before a version is deprecated. When a version is scheduled for deprecation, you receive notice 6 to 12 months ahead of the date, so you can plan the upgrade as part of your normal release cycle.

Notifications are sent through multiple channels:

- **Quarterly SDK newsletter.** Deprecation announcements are included as part of regular SDK updates.
- **Email to workspace administrators.** The formal notice, sent ahead of the deprecation date and repeated as the date approaches.
- **In-dashboard notice.** An alert visible to people working in the MoEngage dashboard, so the notice reaches your team and not only the administrator inbox.
- **Release notes.** Each SDK release flags deprecation-related changes against the affected version.

To receive these notices, keep your workspace administrator email current and subscribe to the SDK newsletter.

## Deprecated Versions by Platform

The current list of supported and deprecated SDK versions is maintained per platform. For Android, see [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions).

Check the relevant list to confirm which versions are current, which are still supported, and which are deprecated. Each list is updated as versions move through their lifecycle and is the source of truth, ahead of any individual email or newsletter.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Does deprecation stop my app from sending data?">
    Deprecated versions continue to send and receive data normally. MoEngage does not block traffic on deprecated versions.
  </Accordion>
  <Accordion title="Can I receive bug fixes on a deprecated version?">
    Fixes ship in the current and supported major versions only and are not available on deprecated versions. To receive a fix, upgrade to the current or a supported version. Your Customer Success Manager (CSM) or the Support team can help you plan the upgrade.
  </Accordion>
  <Accordion title="How do I check whether my SDK version is deprecated?">
    Check the deprecated versions list for your platform. For Android, see [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions).
  </Accordion>
  <Accordion title="How much notice do I receive before a version is deprecated?">
    MoEngage sends advance notice 6 to 12 months before the end-of-support date. Notices are sent by email to workspace administrators, in the quarterly SDK newsletter, through in-dashboard alerts, and in SDK release notes.
  </Accordion>
  <Accordion title="Does this policy apply to server-side or REST API integrations?">
    This policy applies to client-side mobile and web SDKs only. Server-side and REST API integrations are governed separately. Contact your MoEngage Customer Success Manager (CSM) or the Support team for details.
  </Accordion>
</AccordionGroup>

## Next Steps

1. Check the deprecated versions list for your platform. For Android, see [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions).
2. If your version is deprecated or approaching deprecation, review the release notes for your platform:
   - Android: [release notes](/release-notes/sdks/android) · [android-dependency-catalog](https://github.com/moengage/android-dependency-catalog)
   - iOS: [release notes](/release-notes/sdks/ios) · [apple-sdk](https://github.com/moengage/apple-sdk)
   - Web: [release notes](/release-notes/sdks/web)
   - Flutter: [release notes](/release-notes/sdks/flutter) · [Flutter-SDK](https://github.com/moengage/Flutter-SDK/)
   - React Native: [release notes](/release-notes/sdks/react-native) · [React-Native](https://github.com/moengage/React-Native)
   - Unity: [MoEngage-Unity-SDK](https://github.com/moengage/MoEngage-Unity-SDK)
3. Use your platform's release checklist to plan and execute your upgrade. For Android, see the [Android SDK release checklist](/developer-guide/android-sdk/checklist/release-checklist).
4. For help, contact your MoEngage Customer Success Manager (CSM) or the Support team.
