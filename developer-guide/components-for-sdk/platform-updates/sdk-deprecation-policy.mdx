As newer SDK versions ship, older versions are deprecated. This page explains how that process works and what it means for your integration.

MoEngage uses three version status levels:

- **Current** — the latest major version. Receives new features, all fixes, and full engineering support.
- **Supported** — older major versions within their 3-year support window. Receive support.
- **Deprecated** — versions outside their support window. No longer receive fixes or support.

## Support Window

- MoEngage supports each major SDK version for a minimum of 3 years from its initial release.
- Deprecations take effect on an annual cycle in April — a major version is deprecated in the first April on or after the end of its 3-year support window.
- MoEngage gives 6 to 12 months' advance notice before the deprecation date; the exact date for each version is published on the platform's deprecated-versions page.

## Impact of SDK Deprecations on Your App

### Data Flow

Deprecation does not stop your app from sending data, and it does not stop MoEngage from receiving it. MoEngage does not block traffic on deprecated versions. Push, in-app, and analytics continue to function to the extent the version you are on supports them.

Apps already installed on your users' devices continue to send data.

### Bug Fixes and Security Patches

All fixes ship in the current major version only. Supported and deprecated versions do not receive patches — if something breaks on 14.x, the fix ships as part of 15.x. To receive a fix, upgrade to the current version.

### New Development

Apps already in production continue to work. When you ship a new app build, use the current SDK version to ensure you have the latest fixes and capabilities. Deprecated versions are not available on public package registries or store tooling.

## Deprecation Notifications

When a version is scheduled for deprecation, you receive notice 6 to 12 months ahead of the date, so you can plan the upgrade as part of your normal release cycle.

Notifications are sent through multiple channels:

- **Quarterly SDK newsletter.** Deprecation announcements are included as part of regular SDK updates.
- **Email to workspace administrators.** The formal notice, sent ahead of the deprecation date and repeated as the date approaches.
- **In-dashboard notice.** An alert visible in the MoEngage dashboard.
- **Release notes.** Each SDK release flags deprecation-related changes against the affected version.

To receive these notices, keep your workspace administrator email current and subscribe to the SDK newsletter.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="How long is each SDK version supported?">
    Each major version is supported for a minimum of 3 years from its initial release. Deprecations take effect each April, so a version is deprecated in the first April after its 3-year window closes. You receive 6 to 12 months' notice, and the exact date is listed on your platform's deprecated-versions page.
  </Accordion>
  <Accordion title="How much notice do I receive before a version is deprecated?">
    MoEngage sends advance notice 6 to 12 months before the deprecation date. Notices are sent by email to workspace administrators, in the quarterly SDK newsletter, through in-dashboard alerts, and in SDK release notes.
  </Accordion>
  <Accordion title="How do I check whether my SDK version is deprecated?">
    Check the deprecated versions list for your platform in the MoEngage developer documentation. For Android, see [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions).
  </Accordion>
  <Accordion title="Does this policy apply to server-side or REST API integrations?">
    This policy applies to client-side mobile and web SDKs only. Server-side and REST API integrations are governed separately. Contact your MoEngage Customer Success Manager (CSM) or the Support team for details.
  </Accordion>
</AccordionGroup>
