As newer SDK versions ship, older versions are deprecated. This page explains how that process works and what it means for your integration.

<Note>
  For minimum supported OS and platform versions, see [Deprecation for Older Platform Versions](/developer-guide/components-for-sdk/platform-updates/deprecation-for-older-platform-versions).
</Note>

## Impact on Your Integration

### Data Flow

Deprecation does not stop your app from sending data, and it does not stop MoEngage from receiving it. MoEngage does not block traffic on deprecated versions. Push, in-app, and analytics continue to function to the extent the version you are on supports them.

Apps already installed on your users' devices continue to run. The SDK binary is already built into those apps. Note that while the app does not crash, data flow stops after the end-of-support date when server-side enforcement becomes active.

### Support

Once a version is deprecated, MoEngage no longer debugs, fixes, or provides support for issues specific to that version. If you raise an issue on a deprecated version, the first step is to upgrade to a supported version, because that is where the fix exists.

### Bug Fixes and Security Patches

When MoEngage resolves an issue, the fix ships in the current major version only. MoEngage does not release patches onto deprecated versions. To receive a fix, upgrade to the current major version. Where an upgrade requires integration changes, a migration guide is provided for that version jump — see the [Android SDK migration guides](/developer-guide/android-sdk/migration/updating-to-12xxx-from-11xxx) as an example.

### New Development

Apps already in production continue to work. When you ship a new app build, use a supported SDK version. Deprecated versions may not remain available on public package registries or store tooling, and supported versions carry current fixes and capabilities.

## Deprecation Notifications

MoEngage notifies you before a version is deprecated. When a version is scheduled for deprecation, you receive notice 6 to 12 months ahead of the date, so you can plan the upgrade as part of your normal release cycle.

Notifications are sent through multiple channels:

- **Quarterly SDK newsletter.** Deprecation announcements are included as part of regular SDK updates.
- **Email to workspace administrators.** The formal notice, sent ahead of the deprecation date and repeated as the date approaches. Ask your workspace administrator to keep the account email current so these notices reach your team.
- **In-dashboard notice.** An alert visible to anyone working in the MoEngage dashboard.
- **Release notes.** Each SDK release flags deprecation-related changes against the affected version.

## Purpose of SDK Deprecation

Newer SDK versions bring performance improvements, better message reachability and deliverability, a smaller SDK footprint, and support for OS and platform requirements that Apple, Google, and the app stores continue to raise. Older versions fall behind on these over time.

Deprecation defines which versions MoEngage actively supports. It gives you a clear signal to upgrade, with advance notice ahead of the effective date.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="Does deprecation stop my app from sending data?">
    No. Deprecated versions continue to send and receive data normally until the enforcement date. MoEngage does not block traffic on deprecated versions.
  </Accordion>
  <Accordion title="Can I receive bug fixes on a deprecated version?">
    No. Fixes ship in the current major version only and are not back-ported. To receive a fix, upgrade to the current major version. Your Customer Success Manager (CSM) or the Support team can help you plan the upgrade.
  </Accordion>
  <Accordion title="How do I check whether my SDK version is deprecated?">
    Check the deprecated versions list for your platform. For Android, see [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions). Lists for iOS, Web, and plugin SDKs are planned.
  </Accordion>
  <Accordion title="How much notice do I receive before a version is deprecated?">
    MoEngage sends advance notice 6 to 12 months before the end-of-support date. Notices are sent by email to workspace administrators, in the quarterly SDK newsletter, through in-dashboard alerts, and in SDK release notes.
  </Accordion>
  <Accordion title="Does this policy apply to server-side or REST API integrations?">
    No. This policy applies to client-side mobile and web SDKs only. Server-side and REST API integrations are governed separately.
  </Accordion>
</AccordionGroup>

## Next Steps

1. Check the [Android SDK Deprecated Versions](/developer-guide/android-sdk/deprecated-versions/deprecated-versions) list to confirm your version status.
2. If your version is deprecated or approaching deprecation, review the [Android SDK release notes](/release-notes/sdks/android) for the current major version.
3. Use the [Android SDK release checklist](/developer-guide/android-sdk/checklist/release-checklist) to plan and execute your upgrade.
4. For help, contact your MoEngage Customer Success Manager (CSM) or the Support team.
