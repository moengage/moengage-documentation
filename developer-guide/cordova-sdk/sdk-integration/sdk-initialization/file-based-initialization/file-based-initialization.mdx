## Overview

<Info>
  Starting with [Core 10.1.0](/release-notes/sdks/cordova), the MoEngage Cordova SDK supports file-based initialization.
</Info>

File-based initialization lets you manage your Workspace ID and SDK configuration in native configuration files instead of in your application code. This keeps configuration separate from application logic and reduces initialization errors.

You configure two files:

- **Android**: an XML resource file, `moengage.xml`.
- **iOS**: a `MoEngage` dictionary in your `Info.plist`.

<Info>
  Alternatively, you can configure the SDK in code. For that approach, refer to [Android SDK Initialization](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/android-sdk-initialization) and [iOS SDK Initialization](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/ios-sdk-initialization).
</Info>

## Prerequisites

- Cordova SDK `cordova-moengage-core` version 10.1.0 or above.
- Your Workspace ID from **Dashboard → Settings → App → General**.

## Generate the Configuration

Use the form-based generator to produce validated configuration files.

<Steps>
  <Step title="Visit the Config Generator">
    Navigate to the [Initialization Website](https://app-cdn.moengage.com/sdk/integration/config/index.html).
  </Step>
  <Step title="Configure Parameters">
    Set the values your application requires. Refer to the configuration references below:

    - [Android Configuration Reference](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization#android-configuration-reference)
    - [iOS Configuration Reference](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization#ios-configuration-reference)
  </Step>
  <Step title="Generate">
    Click **Generate Code** at the bottom of the form.
  </Step>
</Steps>

## Android Configuration (XML)

For Android, the SDK reads configuration from an XML resource file in your application's resource directory.

### Android Configuration Reference

The following keys are available in `moengage.xml`.

<AccordionGroup>
  <Accordion title="Android Configuration Details">
    | Category | XML Key Name | Type | Description |
    | :-- | :-- | :-- | :-- |
    | **Core** | `com_moengage_core_workspace_id` | String | Specifies your Workspace ID. This field is mandatory. |
    |  | `com_moengage_core_file_based_initialisation_enabled` | Boolean | Set to `true` to enable this feature. |
    |  | `com_moengage_core_data_center` | Integer | Default: `1`. For more information, refer to [Data Center values](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization#data-center-values). |
    |  | `com_moengage_core_environment` | String | Supported values: `default`, `live`, or `test`. |
    |  | `com_moengage_core_custom_base_domain` | String | Specifies the base custom proxy domain to route SDK network traffic through your own subdomain. |
    |  | `com_moengage_core_integration_partner` | String | Specifies the core integration partner. For example, `segment` or `mparticle`. |
    | **Push** | `com_moengage_push_notification_small_icon` | Drawable | Resource ID for the small icon. |
    |  | `com_moengage_push_notification_large_icon` | Drawable | Resource ID for the large icon. |
    |  | `com_moengage_push_notification_color` | Color | Notification accent color. |
    |  | `com_moengage_push_notification_token_retry_interval` | Integer | Retry interval, in seconds, for token registration. |
    |  | `com_moengage_push_kit_registration_enabled` | Boolean | If `true`, the SDK registers for the push token. |
    | **Logs** | `com_moengage_core_log_level` | Integer | `0` (No Log) to `5` (Verbose). Default: `3`. |
    |  | `com_moengage_core_log_enabled_for_release_build` | Boolean | If `true`, prints logs in release builds. |
    | **Security** | `com_moengage_core_storage_encryption_enabled` | Boolean | Enables local storage encryption. |
    |  | `com_moengage_core_network_encryption_enabled` | Boolean | Enables payload encryption over the network. |
    | **Sync** | `com_moengage_core_periodic_data_sync_enabled` | Boolean | Enables periodic data sync in the foreground. |
    |  | `com_moengage_core_background_data_sync_enabled` | Boolean | Enables periodic data sync in the background. |
    | **In-App** | `com_moengage_inapp_show_in_new_activity_enabled` | Boolean | Required for specific TV and Android setups. |
  </Accordion>
</AccordionGroup>

<Warning>
  **Troubleshooting**

  If the XML file is missing or `com_moengage_core_workspace_id` is empty, the SDK throws a `ConfigurationMismatchError`.
</Warning>

### Add the Configuration File

Place the generated `moengage.xml` file in your Cordova Android platform at `platforms/android/app/src/main/res/values/`.

<Note>
  Cordova regenerates the `platforms/` directory when you remove and re-add a platform. Keep a source-controlled copy of `moengage.xml` outside `platforms/` and restore it as part of your build process so the configuration survives a platform rebuild.
</Note>

## iOS Configuration (Info.plist)

For iOS, the SDK reads configuration from a `MoEngage` dictionary in your `Info.plist`.

### iOS Configuration Reference

The following keys are available inside the `MoEngage` dictionary.

<AccordionGroup>
  <Accordion title="iOS Configuration Details">
    | Category | Plist Key | Type | Description |
    | :-- | :-- | :-- | :-- |
    | **Core** | `WorkspaceId` | String | Specifies your Workspace ID. This field is mandatory. |
    |  | `IsSdkAutoInitialisationEnabled` | Boolean | Set to `true` to enable SDK auto-initialisation. |
    |  | `DataCenter` | Integer | Specifies the Data Center value. This field is mandatory. Default: `1`. For more information, refer to [Data Center values](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization#data-center-values). |
    |  | `IsTestEnvironment` | String / Boolean | Default: `$(SWIFT_ACTIVE_COMPILATION_CONDITIONS)`. |
    |  | `CustomBaseDomain` | String | Specifies the base custom proxy domain to route SDK network traffic through your own subdomain. |
    |  | `IntegrationPartner` | String | Specifies your integration partner. For example, `segment` or `mparticle`. |
    |  | `AppGroupName` | String | Specifies the App Group name used for sharing SDK data. |
    | **Logs** | `IsLoggingEnabled` | Boolean | Set to `true` to enable SDK logs. |
    |  | `Loglevel` | Integer | `0` to `5`. Default: `2`. |
    | **Security** | `IsStorageEncryptionEnabled` | Boolean | Enables local storage encryption. Default: `false`. |
    |  | `KeychainGroupName` | String | Specifies the keychain group name used for storing encryption keys. This field is mandatory if `IsStorageEncryptionEnabled` is `true`. |
    |  | `IsNetworkEncryptionEnabled` | Boolean | Enables payload encryption. Default: `false`. |
    |  | `EncryptionEncodedTestKey` | String | Dashboard auto-populated string. Used if `IsNetworkEncryptionEnabled` is `true`. |
    |  | `EncryptionEncodedLiveKey` | String | Dashboard auto-populated string. Used if `IsNetworkEncryptionEnabled` is `true`. |
    | **Sync** | `AnalyticsEnablePeriodicFlush` | Boolean | Enables periodic data flush. Default: `true`. |
    |  | `AnalyticsPeriodicFlushDuration` | Integer | Flush interval in seconds. Default: `60`. |
    | **In-App** | `InAppDisplaySafeAreaInset` | Real | Decimal value representing safe area padding. Default: `0`. |
    |  | `InAppShouldProvideDeeplinkCallback` | Boolean | If `true`, provides a callback on deeplink. Default: `false`. |
  </Accordion>
</AccordionGroup>

### Update Info.plist

<Steps>
  <Step title="Open the Plist">
    Open your project's `Info.plist`, found at `platforms/ios/<YourAppName>/<YourAppName>-Info.plist`.
  </Step>
  <Step title="Create the MoEngage Dictionary">
    Create a top-level key named `MoEngage` of type `Dictionary`.
  </Step>
  <Step title="Configure">
    Add the configuration generated on the [Initialization Website](https://app-cdn.moengage.com/sdk/integration/config/index.html).
  </Step>
</Steps>

<Warning>
  The key `IsSdkAutoInitialisationEnabled` uses the British spelling. Use the exact key name shown, or initialization fails.
</Warning>

**XML snippet representation:**

<CodeGroup>

```xml Info.plist
<key>MoEngage</key>
<dict>
    <key>WorkspaceId</key>
    <string>YOUR_WORKSPACE_ID</string>
    <key>IsTestEnvironment</key>
    <string>$(SWIFT_ACTIVE_COMPILATION_CONDITIONS)|$(GCC_PREPROCESSOR_DEFINITIONS)</string>
    <key>DataCenter</key>
    <integer>1</integer>
    <key>CustomBaseDomain</key>
    <string>data.example.com</string>
    <key>IsLoggingEnabled</key>
    <true/>
</dict>
```

</CodeGroup>

## Framework Level Initialization

After you configure the native files, trigger initialization in your native wrappers and in your Cordova application.

### Android Native Setup

In your `Application` class, call the `initialiseDefaultInstance()` overload that accepts only the `Application` instance. This overload reads configuration from `moengage.xml` instead of a `MoEngage.Builder`.

<CodeGroup>

```java Java
import com.moengage.cordova.MoEInitializer;

@Override
public void onCreate() {
    super.onCreate();
    // ... existing code
    MoEInitializer.initialiseDefaultInstance(this);
}
```

</CodeGroup>

To control whether the SDK starts in an enabled or disabled state, use the overload that accepts an `SdkState`.

<CodeGroup>

```java Java
import com.moengage.cordova.MoEInitializer;
import com.moengage.core.model.SdkState;

MoEInitializer.initialiseDefaultInstance(this, SdkState.ENABLED);
```

</CodeGroup>

<Note>
  The method name uses the British spelling `initialiseDefaultInstance`. The file-based overload takes an `Application` instance, not a `Context`.
</Note>

### iOS Native Setup

In `AppDelegate`, call `initializeDefaultInstanceWithAdditionalCordovaConfig:` with a `MoEngageCordovaSDKDefaultInitializationConfig` instance. This reads configuration from your `Info.plist`.

<CodeGroup>

```objectivec Objective-C wrap
#import "AppDelegate.h"
#import "MainViewController.h"

// Make sure to import "AppDelegate+MoEngage.h"
#import "AppDelegate+MoEngage.h"

@implementation AppDelegate

- (BOOL)application:(UIApplication*)application didFinishLaunchingWithOptions:(NSDictionary*)launchOptions
{
    self.viewController = [[MainViewController alloc] init];

    MoEngageCordovaSDKDefaultInitializationConfig *config = [[MoEngageCordovaSDKDefaultInitializationConfig alloc] init];
    config.launchOptions = launchOptions;
    [self initializeDefaultInstanceWithAdditionalCordovaConfig:config];

    return [super application:application didFinishLaunchingWithOptions:launchOptions];
}

@end
```

</CodeGroup>

`MoEngageCordovaSDKDefaultInitializationConfig` exposes the following properties:

| Property | Type | Description |
| :-- | :-- | :-- |
| `launchOptions` | Dictionary | The app launch options. Defaults to `nil`. |
| `environment` | `MoEngageWorkspaceEnvironment` | The workspace environment to initialize with. Defaults to the environment set in `Info.plist`. |

### Initialize the Cordova Component

Initialize the MoEngage plugin in the `index.js` of your application by calling `MoECordova.init()` inside `onDeviceReady()`.

<CodeGroup>

```javascript JavaScript
var moe = MoECordova.init("YOUR_WORKSPACE_ID");
```

</CodeGroup>

## Environments (Test vs Live)

Configure the test and live environments in the same files:

- **Android**: use `<string name="com_moengage_core_environment">test</string>`.
- **iOS**: use `<key>IsTestEnvironment</key> <true/>`.
