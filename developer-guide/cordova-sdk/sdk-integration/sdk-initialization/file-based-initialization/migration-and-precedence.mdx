Use this page to move an existing Cordova integration from code-based initialization to [file-based initialization](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization), and to understand which configuration source the SDK uses when both exist.

## Prerequisites

Before you begin:

- Cordova SDK `cordova-moengage-core` [version 10.1.0](/release-notes/sdks/cordova#core-10-1-0) or later installed.
- A generated `moengage.xml` file and `MoEngage` plist dictionary. Refer to [File-Based Initialization](/developer-guide/cordova-sdk/sdk-integration/sdk-initialization/file-based-initialization/file-based-initialization).

## Android Migration Steps

<Steps>
  <Step title="Add the Configuration File">
    Place `moengage.xml` in `platforms/android/app/src/main/res/values/`.
  </Step>
  <Step title="Update the Application Class">
    In your `Application` class, remove the `MoEngage.Builder` setup and call the file-based overload of `initialiseDefaultInstance()` instead.
  </Step>
</Steps>

<CodeGroup>

```java Java
import com.moengage.cordova.MoEInitializer;

@Override
public void onCreate() {
    super.onCreate();
    // ... existing code
    MoEInitializer.initialiseDefaultInstance(this);
}
```

```kotlin Kotlin
import com.moengage.cordova.MoEInitializer

override fun onCreate() {
    super.onCreate()
    // ... existing code
    MoEInitializer.initialiseDefaultInstance(this)
}
```

</CodeGroup>

<Note>
  Both overloads share the name `initialiseDefaultInstance`. The file-based one takes only the `Application` instance; the code-based one also takes a `MoEngage.Builder`.
</Note>

## iOS Migration Steps

<Steps>
  <Step title="Update Info.plist">
    Add the MoEngage configuration keys, such as `WorkspaceId` and `DataCenter`, inside the `MoEngage` dictionary in `platforms/ios/<YourAppName>/<YourAppName>-Info.plist`.
  </Step>
  <Step title="Update AppDelegate">
    Remove the `MoEngageSDKConfig` setup from `application:didFinishLaunchingWithOptions:` and call the default instance initialization so the SDK reads from `Info.plist`.
  </Step>
</Steps>

<CodeGroup>

```objectivec Objective-C wrap
#import "AppDelegate+MoEngage.h"

MoEngageCordovaSDKDefaultInitializationConfig *config = [[MoEngageCordovaSDKDefaultInitializationConfig alloc] init];
config.launchOptions = launchOptions;
[self initializeDefaultInstanceWithAdditionalCordovaConfig:config];
```

</CodeGroup>

## Precedence Rules

The configuration source depends on which initialization method your native code calls.

### Android

| Method | Configuration source |
| :-- | :-- |
| `MoEInitializer.initialiseDefaultInstance(application)` | Reads `moengage.xml` from the resource directory. |
| `MoEInitializer.initialiseDefaultInstance(context, builder)` | Uses the `MoEngage.Builder` passed in, and ignores `moengage.xml` even if the file exists. |

### iOS

Auto-initialization from `Info.plist` runs first. If you subsequently call a manual initialization method with a configuration object, it updates the configuration of the current instance.

<Warning>
  Call only one initialization method per platform. Calling both the code-based and file-based methods leads to configuration that is difficult to trace.
</Warning>
