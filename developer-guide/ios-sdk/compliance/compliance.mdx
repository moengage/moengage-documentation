# Opt-Out of Data Tracking

To disable data tracking by the SDK use [_disableDataTracking()_](https://moengage.github.io/ios-api-reference/Classes/MoEngageSDKAnalytics.html#/c:@M@MoEngageAnalytics@objc\(cs\)MoEngageSDKAnalytics\(im\)disableDataTracking) method as shown below. Once you have opted out of data tracking you need to explicitly opt-in to start tracking any event OR attributes for the user.

<CodeGroup>

```swift Swift wrap
MoEngageSDKAnalytics.sharedInstance.disableDataTracking() //Opt out
MoEngageSDKAnalytics.sharedInstance.enableDataTracking()  //Opt in
```


```objective-c Objective C wrap
[[MoEngageSDKAnalytics sharedInstance] disableDataTracking]; //Opt out
[[MoEngageSDKAnalytics sharedInstance] enableDataTracking]; //Opt in
```

</CodeGroup>

# IDFA and IDFV OptOuts

SDK tracks [IDFA](https://developer.apple.com/documentation/adsupport/asidentifiermanager/1614151-advertisingidentifier)(Advertising Identifier) by default as a UserAttribute, it's tracked only if the AdSupport, AppTrackingTransparency frameworks is included in the project and if the User has not limited Ad Tracking. In case you would want to opt-out of IDFA Tracking call the opt-out method as shown below:

<CodeGroup>

```swift Swift wrap
MoEngageSDKAnalytics.sharedInstance.disableIDFATracking() //Opt out
MoEngageSDKAnalytics.sharedInstance.enableIDFATracking() //Opt in
```


```objective-c Objective C wrap
[[MoEngageSDKAnalytics sharedInstance] disableIDFATracking]; //Opt out
[[MoEngageSDKAnalytics sharedInstance] enableIDFATracking]; // Opt in
```

</CodeGroup>

<Warning>
  - Calling `MoEngageSDKAnalytics.sharedInstance.enableIDFATracking()` requires the `AdSupport` framework to be linked in your project. If the framework is missing, the SDK throws a fatal exception and crashes the app in `DEBUG` builds. In release builds, the call is dropped silently and IDFA is not tracked.
  - If you are upgrading an existing app and these strict `DEBUG` validations cause disruptive crashes while you refactor your tracking code, you can temporarily opt out by calling `disableIntegrationValidator()` during SDK initialization. Use this strictly as a stopgap for phased upgrades, and aim to remove the opt-out once your attribute call sites are properly validated.
</Warning>

SDK also tracks [IDFV](https://developer.apple.com/documentation/uikit/uidevice/1620059-identifierforvendor)(Identifier for Vendor) by default as a device Identifier. In case you would want to opt-out of IDFV Tracking call the opt-out method as shown below:

<CodeGroup>

```swift Swift wrap
MoEngageSDKAnalytics.sharedInstance.disableIDFVTracking() //Opt out
MoEngageSDKAnalytics.sharedInstance.enableIDFVTracking() //Opt in
```


```objective-c Objective C wrap
[[MoEngageSDKAnalytics sharedInstance] disableIDFVTracking]; //Opt out
[[MoEngageSDKAnalytics sharedInstance] enableIDFVTracking]; //Opt in
```

</CodeGroup>

IDFA and IDFV opt-outs are available from SDK version 6.1.1

<Note>
  Starting with iOS SDK [11.0.0](/release-notes/sdks/ios#22nd-july-2026), the data tracking, IDFA, and IDFV toggle methods return a typed task object ([`MoEngageTrackingToggleTask`](https://moengage.github.io/ios-api-reference/Classes/MoEngageTrackingToggleTask.html)) instead of `Void`. The return value is annotated `@discardableResult`, so direct calls like the ones above compile unchanged.
</Note>

Attach `onSuccess` and `onFailure` to the returned task to confirm the opt-out or opt-in was applied. Confirming this matters for consent flows, where you need to know the user's choice took effect:

<CodeGroup>

```swift Swift wrap
MoEngageSDKAnalytics.sharedInstance.disableDataTracking()
    .onSuccess { result in
        // Tracking is now opted out.
    }
    .onFailure { failure in
        print("Opt-out failed: \(failure.reason) - \(failure.message)")
    }
```

```objective-c Objective C wrap
MoEngageTrackingToggleTask *task = [[MoEngageSDKAnalytics sharedInstance] disableDataTracking];

[task onSuccess:^(id _Nonnull result) {
    // Tracking is now opted out.
}];

[task onFailure:^(MoEngageRequestFailure * _Nonnull failure) {
    NSLog(@"Opt-out failed: %@ - %@", failure.reason, failure.message);
}];
```

</CodeGroup>

Handlers run on the main thread, and registering a second handler of the same kind replaces the first. `onFailure` receives a [`MoEngageRequestFailure`](https://moengage.github.io/ios-api-reference/Classes/MoEngageRequestFailure.html): `reason.code` carries a [shared failure code](https://moengage.github.io/ios-api-reference/Classes/MoEngageRequestFailureReason/Code.html) — `sdkNotInitialized` and `featureDisabled` are the most likely here — and `message` describes the failure. Swift callers can `await` the task's `result()` method instead of attaching handlers.

# Enable/Disable SDK

If you don't want the MoEngage SDK to track any user information or send any data to the MoEngage System use the below method:

<CodeGroup>

```swift Swift
MoEngage.sharedInstance.disableSDK()
```


```objective-c Objective C
[[MoEngage sharedInstance] disableSDK];
```

</CodeGroup>

Once this API is called all the SDK APIs will be non-operational. SDK will be disabled until [_enableSDK()_](https://moengage.github.io/ios-api-reference/Classes/MoEngage.html#/c:@M@MoEngageSDK@objc\(cs\)MoEngage\(im\)enableSDK) is called.

Once you have the user's consent use the below API to enable the SDK.

<CodeGroup>

```swift Swift
MoEngage.sharedInstance.enableSDK()
```


```objective-c Objective C
[[MoEngage sharedInstance] enableSDK];
```

</CodeGroup>

Enable/Disable SDK methods are available from SDK version 6.3.0.
