Use this page when iOS push notifications fail to deliver, impressions aren't tracked, or rich templates don't render. Go to the section that matches your symptom. Code samples cover MoEngage iOS SDK versions 7.x, 8.x, and 9.x — use the block for your version and delete the others. If you haven't integrated push yet, start with the [iOS Push Integration Tutorial](/developer-guide/ios-sdk/push/basic/ios-push-integration-tutorial).

<Info>
  For push impressions to be tracked, turn on **Show iOS impressions** at **Settings > Channel > Push > iOS** on the MoEngage dashboard.

## Impressions Not Tracked, or Images Not Rendering

These symptoms usually mean the App Group ID isn't consistent, or the Notification Service Extension isn't set up. Work through the steps below (Notification Service Extension required for rich media and impression tracking).

<Note>
  Class names differ by SDK version: config is `MOSDKConfig` (7.x/8.x) or `MoEngageSDKConfig` (9.x); the rich-notification pod is `MoEngageRichNotification` (9.x) or `MORichNotification` (7.x).
</Note>

1. **Check `app_group_id` in your project's main target** for each configuration. Two apps with *different* Bundle Identifiers sharing the *same* `app_group_id` may fail on the same device.
2. **Check `app_group_id` during SDK initialisation** — in `Info.plist` (under the MoEngage key) if you initialise via plist, or in `sdkConfig` in `AppDelegate` if you initialise via config.

      <CodeGroup>
      ```swift Swift wrap
      var sdkConfig = MoEngageSDKConfig.init(appId: "XXXXXXXXXXXXXXXX", dataCenter: .data_center_0X)
      sdkConfig.appGroupID = "group.com.XXXXXXXXXXXXXXXX"
      ```
      ```objective-c Objective-C wrap
      MoEngageSDKConfig* sdkConfig = [[MoEngageSDKConfig alloc] initWithAppId:@"XXXXXXXXXXXXXXXX" dataCenter: MoEngageDataCenterData_center_0X];
      sdkConfig.appGroupID = @"group.com.XXXXXXXXXXXXXXXX";
      ```
      </CodeGroup>

3. **Add a Notification Service Extension target** — enable Push Notifications and add the App Group ID under Signing & Capabilities, and match its minimum deployment iOS version to the main app.
4. **Integrate the rich-notification framework** into the Notification Service Extension target via your Podfile.

   ```swift Swift
   target 'MoEngageDemo' do
     use_frameworks!
     pod 'MoEngage-iOS-SDK'
   end
   target 'MoEngageNotificationService' do
     use_frameworks! #use use_frameworks only if included in main target as in above scenario
     pod 'MoEngageRichNotification'
   end
   ```

5. **Set the App Group ID in `NotificationService.swift`.**

   ```swift Swift
   import UserNotifications
   import MoEngageRichNotification

   class NotificationService: UNNotificationServiceExtension {

       var contentHandler: ((UNNotificationContent) -> Void)?
       var bestAttemptContent: UNMutableNotificationContent?

       override func didReceive(_ request: UNNotificationRequest, withContentHandler contentHandler: @escaping (UNNotificationContent) -> Void) {	
         MoEngageSDKRichNotification.setAppGroupID("group.com.XXXXXXXXXXXXXXXX")
         self.contentHandler = contentHandler
         bestAttemptContent = (request.content.mutableCopy() as? UNMutableNotificationContent)
         MoEngageSDKRichNotification.handle(richNotificationRequest: request, withContentHandler: contentHandler)
       }

       override func serviceExtensionTimeWillExpire() {
           // Called just before the extension will be terminated by the system.
           // Use this as an opportunity to deliver your "best attempt" at modified content, otherwise the original push payload will be used.
           if let contentHandler = contentHandler, let bestAttemptContent =  bestAttemptContent {
               contentHandler(bestAttemptContent)
           }
       }
   }
   ```

6. **Check Build Phases** on the main app target — under Embed App Extensions, ensure **Copy only when installing** is unchecked.
7. **Keep `appGroupId` consistent** across all schemes/configurations (Debug/Release/QA/UAT), and align the Build Configuration of the main target and the extension.

## Rich Push Templates Not Rendering

If push templates (carousels, background/font colors) don't render, the fix depends on whether you've added a Notification Content Extension.

<Tabs>
  <Tab title="Content Extension not yet added">
    1. **Create a Notification Content Extension target.** Swift is recommended (it works with Objective-C projects too). Add the App Group ID under Signing & Capabilities, and match its minimum deployment iOS version to the main app.
    2. **Integrate the rich-notification framework** — add the Content Extension as a separate target in your Podfile.

      ```swift Swift
      target 'MoEngageDemo' do
      use_frameworks!
      pod 'MoEngage-iOS-SDK'
      end
      target 'MoEngageNotificationService' do
      use_frameworks! #use use_frameworks only if included in main target as in above scenario
      pod 'MoEngageRichNotification'
      end
      target 'MoegageRichContent" do
      use_frameworks! #use use_frameworks only if included in main target as in above scenario
      pod 'MoEngageRichNotification'
      end
      ```

    3. **Update `NotificationViewController.swift`** — set the App Group ID in `viewDidLoad` and add the push template in `didReceive`.

      ```swift Swift
      import UIKit
      import UserNotifications
      import UserNotificationsUI
      import MoEngageRichNotification
      class NotificationViewController: UIViewController, UNNotificationContentExtension {
          @IBOutlet var label: UILabel?

          override func viewDidLoad() {
              super.viewDidLoad()
              MoEngageSDKRichNotification.setAppGroupID("group.com.XXXXXXXXXXXXXXXX")
          }

          func didReceive(_ notification: UNNotification) {
              if #available(iOSApplicationExtension 12.0, *) {
                  MoEngageSDKRichNotification.addPushTemplate(toController: self, withNotification: notification) 
              } else {
                  // Fallback on earlier versions
              }
          }
      }
      ```

    4. **Edit `MainInterface.storyboard`** — remove the default label and set the View's background color to clear.
    5. **Add the `NSExtensionAttributes`** to the extension's `Info.plist`.

      ```swift Swift
      <key>NSExtensionAttributes</key> 
      <dict>
            <key>UNNotificationExtensionCategory</key>
            <string>MOE_PUSH_TEMPLATE</string>
            <key>UNNotificationExtensionDefaultContentHidden</key>
            <true/>
            <key>UNNotificationExtensionInitialContentSizeRatio</key>
            <real>1.2</real>
            <key>UNNotificationExtensionUserInteractionEnabled</key>
            <true/>
      </dict>
      ```

    6. **Check Build Phases, `appGroupId` consistency, and Build Configuration** as in the Impressions section above.
