# Android - Why are callbacks not working in the background or killed state?

MoEngage callbacks must be registered in your app.js or app.ts, and after setting them up, you must call the MoEngage Plugin's initialize () method. Read more about [it here](/developer-guide/react-native-sdk/push/basic/push-callback#push-click-callback)

Sample code for callbacks - [GitHub](https://github.com/moengage/React-Native/blob/master/SampleApp/App.js)

# Android - Why are inapp/nudge deep links not working?

MoEngage SDK doesn't handle in-app redirections by default except for rich landing pages; please refer to the documentation here. You must implement in-app click callback methods in your app.ts or app.js and call the moengage plugin initialise() method after you register for callbacks. In these callbacks, you will have to write code to extract navigation information and handle the redirection according to your preference. Callback documentation is [given here](/developer-guide/react-native-sdk/in-app-messages/inapp-nativ#inapp-callbacks).

Sample code for inapp/nudge callbacks - [GitHub](https://github.com/moengage/React-Native/blob/master/SampleApp/App.js)

# iOS - Why does the build fail with "Unsupported Swift Architecture" or "framework not found"?

Errors such as `Unsupported Swift Architecture`, `framework 'MoEngageKMMConditionEvaluator' not found`, or `framework 'MoEngageRichNotification' not found` typically indicate that the Xcode project excludes the `arm64` architecture or targets architectures that the MoEngage iOS SDK does not ship.

Start with the `Podfile`. Check its `post_install` hook for lines that set `EXCLUDED_ARCHS` or `ONLY_ACTIVE_ARCH`. The hook re-applies those settings on every `pod install`, so it overrides anything that you change in Xcode. To apply the correct settings to all Pods targets at once, use the following hook:

<CodeGroup>

```ruby Podfile
post_install do |installer|
  installer.pods_project.targets.each do |target|
    target.build_configurations.each do |config|
      config.build_settings['ONLY_ACTIVE_ARCH'] = 'YES'
      config.build_settings['EXCLUDED_ARCHS[sdk=iphonesimulator*]'] = ''
    end
  end
end
```

</CodeGroup>

Next, open `ios/YourApp.xcworkspace` in Xcode, not the `.xcodeproj`. In the **Project Navigator**, select your app project and apply the following settings to each of its targets, including the application target and the notification service and content extensions. Then select the **Pods** project and repeat for its targets:

- **Excluded Architectures (`EXCLUDED_ARCHS`)**: Remove `arm64`. MoEngage iOS SDK v10.x.x and later ship only `arm64` slices, which iPhone and iPad devices and Apple silicon simulators require.
- **Build Active Architecture Only (`ONLY_ACTIVE_ARCH`)**: Set `ONLY_ACTIVE_ARCH` to **Yes**. Xcode then builds only for the architecture of the selected device or simulator.
- **Architectures (`ARCHS`)**: Set `ARCHS` to `ARCHS_STANDARD`, or include `arm64` in the list.

After you change these settings, select **Product > Clean Build Folder** in Xcode, run `pod install` from the `ios` directory, and build again.

<Warning>
  Keep `MoEngageKMMConditionEvaluator` embedded. Setting `MoEngageKMMConditionEvaluator` to **Do Not Embed** appears to resolve a framework-not-found error, but this framework evaluates trigger conditions for trigger-based in-app messages and push campaigns, and removing the framework prevents those campaigns from displaying.
</Warning>

If the build fails on `arm64` in your CI pipeline but succeeds in Xcode on your own machine, check which version of Xcode the build agent uses. Build agents often run an older version than developers do. Install a current stable version of Xcode on the agent. It must be at least the version you build with locally.

For the full architecture configuration procedure, including Intel-based Mac limitations, see [Configuring Project for Architecture Compatibility](/developer-guide/ios-sdk/sdk-integration/basic/Configuring-Project-for-Architecture-Compatibility).

# iOS - Why does the build fail with "Use of undeclared identifier 'MoEngageInitializer'"?

This error occurs when the MoEngage import in `ios/YourApp/AppDelegate.m` or `AppDelegate.mm` sits inside or after the `#if RCT_NEW_ARCH_ENABLED` block. In an app that does not use the React Native new architecture, the condition evaluates to false, the compiler skips the import, and the build never sees the `MoEngageInitializer` declaration.

Move the import above the `#if RCT_NEW_ARCH_ENABLED` block:

<CodeGroup>

```objectivec AppDelegate.mm
#import "AppDelegate.h"
#import <ReactNativeMoEngage/MoEngageInitializer.h>
#import <MoEngageSDK/MoEngageSDK.h>

#if RCT_NEW_ARCH_ENABLED
// React Native new architecture imports
#endif
```

</CodeGroup>

# iOS - Why is the ReactNativeMoEngage header not found after a plugin upgrade?

Errors such as `'ReactNativeMoEngage/MoEngageInitializer.h' file not found` after upgrading the plugin have two common causes:

- **The header name differs across plugin versions.** Older plugin versions expose `MOReactInitializer.h`, and current versions expose `MoEngageInitializer.h`. Update the import in `ios/YourApp/AppDelegate.m` or `AppDelegate.mm` to match the version that you installed. See [iOS initialization](/developer-guide/react-native-sdk/sdk-integration/react-native/sdk-initialization/manual-initialization/ios) for the current import and initialization code.
- **The target cannot resolve the header path.** In **Build Settings** for the `ReactNativeMoEngage` target, confirm that `$(inherited)` appears in both **Header Search Paths** and **Library Search Paths**, so that the target picks up the paths that CocoaPods generates. Also confirm that the `ReactNativeMoEngage` pod appears in the `Pods` project after `pod install`. A missing pod indicates that the install did not link the plugin.

To re-link the plugin after upgrading, run the following commands from your project root:

<CodeGroup>

```shellscript Shell
rm -rf ios/Pods ios/Podfile.lock
npm install
cd ios && pod install --repo-update
```

</CodeGroup>

Then clean the build folder in Xcode and build again.
