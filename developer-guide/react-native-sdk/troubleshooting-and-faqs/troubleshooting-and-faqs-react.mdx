# Android - Why are callbacks not working in the background or killed state?

MoEngage callbacks must be registered in your app.js or app.ts, and after setting them up, you must call the MoEngage Plugin's initialize () method. Read more about [it here](/developer-guide/react-native-sdk/push/basic/push-callback#push-click-callback)

# Android - Why are inapp/nudge deep links not working?

MoEngage SDK doesn't handle in-app redirections by default except for rich landing pages; please refer to the documentation here. You must implement in-app click callback methods in your app.ts or app.js and call the moengage plugin initialise() method after you register for callbacks. In these callbacks, you will have to write code to extract navigation information and handle the redirection according to your preference. Callback documentation is [given here](/developer-guide/react-native-sdk/in-app-messages/inapp-nativ#inapp-callbacks).

Sample code for inapp/nudge callbacks - [GitHub](https://github.com/moengage/React-Native/blob/master/SampleApp/App.js)

# iOS - Why does the build fail with "Unsupported Swift Architecture" or "framework not found"?

Errors such as `Unsupported Swift Architecture`, `framework 'MoEngageKMMConditionEvaluator' not found`, or `framework 'MoEngageRichNotification' not found` usually mean the Xcode project excludes the `arm64` architecture or builds for architectures that the MoEngage iOS SDK does not ship.

In Xcode, open your project in the **Project Navigator** and apply these settings to every target, including the application target, notification service and content extensions, and Pods targets:

- **Excluded Architectures (`EXCLUDED_ARCHS`)**: Remove `arm64`. MoEngage iOS SDK v10.x.x and later ship only `arm64` slices, which iPhone and iPad devices and Apple silicon simulators need.
- **Build Active Architecture Only (`ONLY_ACTIVE_ARCH`)**: Set this to **Yes**. Xcode then builds only for the architecture of the selected device or simulator.
- **Architectures (`ARCHS`)**: Set this to `ARCHS_STANDARD`, or include `arm64`.

After changing the settings, clean the build folder, run `pod install` from the `ios` directory, and build again.

<Warning>
  Do not set `MoEngageKMMConditionEvaluator` to **Do Not Embed** to work around a framework-not-found error. This framework evaluates trigger conditions for trigger-based in-app messages and push campaigns, and removing it stops those campaigns from displaying.
</Warning>

If `arm64` compilation fails only on a CI pipeline while the same build succeeds from Xcode on a developer machine, check the Xcode version on the build agent. An agent running an older Xcode than the local machine is a common cause; match the agent to the Xcode version you build with locally.

For the full architecture configuration procedure, including Intel-based Mac limitations, see [Configuring Project for Architecture Compatibility](/developer-guide/ios-sdk/sdk-integration/basic/Configuring-Project-for-Architecture-Compatibility).

# iOS - Why does the build fail with "Use of undeclared identifier 'MoEngageInitializer'"?

This error occurs when the MoEngage import in `AppDelegate.m` or `AppDelegate.mm` sits inside or after the `#if RCT_NEW_ARCH_ENABLED` block. If your app does not use the React Native new architecture, the condition is not met, the compiler skips the import, and `MoEngageInitializer` is never declared.

Move the import above the `#if RCT_NEW_ARCH_ENABLED` block:

<CodeGroup>

```objectivec AppDelegate.mm
#import "AppDelegate.h"
#import <ReactNativeMoEngage/MoEngageInitializer.h>
#import <MoEngageSDK/MoEngageSDK.h>

#if RCT_NEW_ARCH_ENABLED
// React Native new architecture imports
#endif
```

</CodeGroup>

# iOS - Why is the ReactNativeMoEngage header not found after a plugin upgrade?

Errors such as `'ReactNativeMoEngage/MoEngageInitializer.h' file not found` after upgrading the plugin have two common causes:

- **The header name changed.** Older plugin versions exposed `MOReactInitializer.h`. Current versions expose `MoEngageInitializer.h`. Update the import in `AppDelegate.m` or `AppDelegate.mm` to match the version you installed. See [iOS initialization](/developer-guide/react-native-sdk/sdk-integration/react-native/sdk-initialization/manual-initialization/ios) for the current import and initialization code.
- **The target cannot resolve the header path.** In **Build Settings** for the `ReactNativeMoEngage` target, confirm that `$(inherited)` is present in both **Header Search Paths** and **Library Search Paths**, so the target picks up the paths CocoaPods generates. Also confirm the `ReactNativeMoEngage` pod appears in the `Pods` project after `pod install`; if it is missing, the plugin was not linked.

To re-link the plugin after upgrading, run the following commands from your project root:

<CodeGroup>

```shellscript Shell
rm -rf ios/Pods ios/Podfile.lock
npm install
cd ios && pod install --repo-update
```

</CodeGroup>

Then clean the build folder in Xcode and build again.
