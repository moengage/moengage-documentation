MoEngage AMP event analytics plugin helps in track user attributes and events, and run third-party javascript. MoEngage AMP event analytics plugin ensures to address the differences in AMP pages and HTML page restriction for tracking user attributes and events.

The MoEngage AMP event analytics plugin is different from the AMP analytics module.

To add event tracking and user attribute tracking to your AMP pages follow these steps-

## Add AMP Analytics Script

Ensure to include the script in all of your AMP pages in the `<head>` section of your .amp file where you want to use AMP analytics and track user attributes and events.

<CodeGroup>

```HTML HTML lines wrap
<script async custom-element="amp-analytics" src="https://cdn.ampproject.org/v0/amp-analytics-0.1.js"></script>
```

</CodeGroup>

### Add Anywhere in your HTML

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage" >
<script type="application/json">
{
  "vars": {
    "appId": "YOUR_WORKSPACE_ID",
    "dataCenter": "sdk-01"
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

<Info>
  Note

  Ensure to replace Your_Workspace_ID with the actual Workspace Id from MoEngage Dashboard -\> Settings -\> App -\> General Settings

  For dataCenter, please contact our support team to know more.
</Info>

<Info>
  Note

  To redirect data to test environment, append '\_DEBUG' to appId. For example, if your appId is \
  YOUR_WORKSPACE_ID then for test environment, it would be YOUR_WORKSPACE_ID_DEBUG
</Info>

## Tracking Users

All the users visiting your AMP pages will be tracked automatically once you followed the above steps.\
But these users will be anonymous users by default.\
However, if any user of your website who visited your normal HTML pages earlier and has not deleted their cookies, will be treated as the same user in AMP pages also.

## Tracking Events

Page Viewed event is tracked by default if you followed the above steps.\
However with AMP framework limitations on event tracking, only a few kinds of events can be tracked such as `Page Viewed`, `Element Clicked`, `Page Scroll`.

<Info>
  The MoEngage vendor config automatically includes `identifiers` and `meta` in every request. You do not need to add them to your trigger configurations. Only add a custom `identifiers` object when tracking login events, to associate the request with a specific logged-in user.
</Info>

For more information on the list of events, refer to [AMP Analytics Examples](https://amp.dev/documentation/examples/components/amp-analytics/).

### Example 1: Element Click Event

You can track a Click Event when an HTML element with id `test` is clicked as described:

<CodeGroup>

```HTML HTML lines wrap
<button id="test" data-vars-title="Example request title">
  Click here to generate an event
</button>

<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#test",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "amp example button click",
            "EVENT_ATTRS": {
              "title": "${title}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

 

| Parameter | Description |
| --------- | ----------- |
| `on` | Type of event |
| `selector` | Standard CSS selector |
| `request` | Should always be `eventV2` |
| `viewsCount` | Number of events in this request. Set to the number of objects in `viewsInfo`. |
| `viewsInfo` | Array containing the event object. |
| `viewsInfo[].EVENT_ACTION` | Event name. In this example, `"amp example button click"`. |
| `viewsInfo[].EVENT_ATTRS` | Event attributes as key-value pairs. Verify the variable `title` using `data-vars-title` from the button element. |
| `viewsInfo[].EVENT_G_TIME` | Global (UTC) timestamp of the event. Use `${timestamp}`. |
| `viewsInfo[].EVENT_L_TIME` | Local timestamp of the event. Use `${timestamp}`. |

### Example 2: Page Scroll Event

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "scrollPings": {
      "on": "scroll",
      "scrollSpec": {
        "verticalBoundaries": [25, 50, 90]
      },
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "PageScroll",
            "EVENT_ATTRS": {
              "scrolledUpto": "${scrollTop}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

The scroll event needs `scrollSpec` object, that contains `verticalBoundaries` and `horizontalBoundaries`. At least one of the two properties is required for a scroll event to fire. The values for both of the properties should be arrays of numbers containing the boundaries on which a scroll event is generated. For instance, in the following code snippet, the scroll event will be fired when the page is scrolled vertically by 25%, 50% and 90%. The attributes sent here is `scrolledUpto` which holds an inbuilt variable `scrollTop` that provides the number of pixels that the user has scrolled from the top.

For more information about the list of all supported variables, refer to [Supported Variables](https://github.com/ampproject/amphtml/blob/main/docs/spec/amp-var-substitutions.md).

### Example 3: Form Submit Event

<CodeGroup>

```HTML HTML lines wrap
<form id="testForm" method="post" action-xhr="YOUR_SUBMIT_URL" target="YOUR_TARGET_VALUE">
   <input type="text" name="name" placeholder="Name..." required>
   <input type="submit" value="Subscribe">
</form>

<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "formSubmit": {
      "on": "amp-form-submit",
      "request": "eventV2",
      "selector": "#testForm",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "FormSubmit",
            "EVENT_ATTRS": {
              "anyKey": "anyValue"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

In the above example, we are setting the id of the form as the selector value (**#testForm**). Inside `viewsInfo`, `EVENT_ACTION` is the event name and `EVENT_ATTRS` contains the key and the value which we want to track for this event.

## Tracking User Attributes

<Warning>
  Important

  If any user attribute is configured as an identity for your account, then track it as part of [login](#tracking-user-login-and-logout) instead of simply tracking it as a user attribute as it is shown in this section. Refer to [this document](https://www.moengage.com/docs/user-guide/data/user-data/unified-identity-identity-resolution) to learn more.
</Warning>

You can track user attributes using the `EVENT_ACTION_USER_ATTRIBUTE` event. For example, you have this button on your website:

<CodeGroup>

```HTML HTML lines
<button id="first-name" data-vars-first-name="someFirstName">  Click here to track first name</button>
```

</CodeGroup>

Then, track the first name (considering it to be the user's first name) like this:

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#first-name",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_USER_FIRST_NAME": "${firstName}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

Similarly, to track the user's email upon clicking the below button

<CodeGroup>

```HTML HTML lines
<button id="email" data-vars-email="someEmail">  Click here to track email</button>
```

</CodeGroup>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#email",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_USER_EMAIL": "${email}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

In the same way, you can track other **pre-defined user attributes**

<CodeGroup>

```HTML HTML lines wrap
<button id="btnId" data-vars-attribute-value="someValue">  Click here to track the user attribute</button>
```

</CodeGroup>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#btnId",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {
              "USER_ATTRIBUTE_NAME": "${attributeValue}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

Here, USER_ATTRIBUTE_NAME has to be replaced with one of the following

<CodeGroup>

```javascript JavaScript lines wrap
USER_ATTRIBUTE_USER_EMAIL //for user email - value needs to be string, eg: "dom@level5.com"
USER_ATTRIBUTE_USER_NAME //for user name - value needs to be string, eg: "Dominick (Dom) Cobb"
USER_ATTRIBUTE_USER_FIRST_NAME //for user first name - value needs to be string, eg: "Dominick"
USER_ATTRIBUTE_USER_LAST_NAME //for user last name - value needs to be string, eg: "Cobb"
USER_ATTRIBUTE_USER_MOBILE //for user mobile - value needs to be string, eg: "+12399999999"
USER_ATTRIBUTE_USER_GENDER //for user gender - value needs to be string, eg: "M"
USER_ATTRIBUTE_USER_BDAY //for user birthday - value needs to be in date format, eg: new Date(1980, 2, 31)
```

</CodeGroup>

To track a **custom user attribute**, in place of USER_ATTRIBUTE_NAME you have to use your own custom attribute name. For example-

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">

            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",

              "colors": ["blue", "green", "red"]
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

In the above example, we are tracking a custom attribute named "colors". This attribute's value is an array- `["blue","green","red"]`

## Tracking User Login and Logout

[Previous way of logging-in users](/developer-guide/web-sdk/other-supported-web-sdk-integration/user-login-in-amp-older-process) has been changed. The below method follows the User Identity Resolution feature of MoEngage. [Learn More](https://www.moengage.com/docs/user-guide/data/user-data/unified-identity-identity-resolution).

Ensure log in and log out of users are implemented correctly during the visit to your website and users are authenticated. 

<Warning>
  Important

  If the user log in and log out is not handled correctly, user data may get corrupted. Refer [this section](https://www.moengage.com/docs/developer-guide/web-sdk/data-tracking/web-sdk-user-attributes-tracking#User-Login-and-Logout) for more details.
</Warning>

### Track Login

<CodeGroup>

```HTML HTML lines wrap
<button id="login" data-vars-unique-id="someUniqueId" data-vars-user-email="emailValue@emailDomain.com">Click here to track user login</button>
```

</CodeGroup>

Here, we want to track ID "someUniqueId" and Email "[emailValue@emailDomain.com](mailto:emailValue@emailDomain.com)" as the identities for the user.

<Warning>
  Important

  If you are setting the ID, make sure to add/update its value in both `identifiers` -\> `moe_user_id` as well as inside `identifiers` -\> `user_identities`
</Warning>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#login",
      "request": "eventV2",
      "extraUrlParams": {
        "identifiers": {
          "moe_user_id": "${uniqueId}",
          "user_identities": {
            "uid": "${uniqueId}",
            "u_em": "${userEmail}"
          }
        },
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {},
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

Here, `uid` is ID and `u_em` is Email (Standard) attributes. Please refer to the below table for key names which need to be used to set standard user attributes as identities.

| User Attribute Name      | Key name to be used in user_identities |
| ------------------------ | -------------------------------------- |
| ID                       | uid                                    |
| Email (Standard)         | u_em                                   |
| Gender                   | u_gd                                   |
| Birthday                 | u_bd                                   |
| Name                     | u_n                                    |
| First Name               | u_fn                                   |
| Last Name                | u_ln                                   |
| Mobile Number (Standard) | u_mb                                   |

If we want to identify the user with just mobile number (for example)-

<CodeGroup>

```HTML HTML lines wrap
<button id="login" data-vars-user-mobile="7777777777">Click here to track user login</button>
```

</CodeGroup>

<CodeGroup>

```html HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "clickTrigger": {
      "on": "click",
      "selector": "#login",
      "request": "eventV2",
      "extraUrlParams": {
        "identifiers": {
          "user_identities": {
            "u_mb": "${userMobile}"
          }
        },
        "viewsCount": 1,
        "viewsInfo": [
          {
            "EVENT_ACTION": "EVENT_ACTION_USER_ATTRIBUTE",
            "EVENT_ATTRS": {},
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

<Info>
  Note

  Here, we do not have to send the value of mobile number in `identifiers` -\> `moe_user_id` as Mobile and ID are two different attributes of a user. Only while adding/updating ID, the value of the ID has to be sent in `moe_user_id` as well as in `user_identities`.
</Info>

<Warning>
  Important

  After you track the login, include the `identifiers` object (with `moe_user_id` and/or `user_identities`) in every subsequent trigger's `extraUrlParams`, until you perform a logout. The vendor config sends `identifiers: {}` (empty) by default, so you must override it with the user's actual identities in each post-login trigger. Otherwise, MoEngage does not associate those events with the logged-in user in your dashboard.
</Warning>

## Batching Events

You can send multiple events in a single HTTP request by placing them all inside one trigger's `viewsInfo` array. Set `viewsCount` to the number of events and add each event object to `viewsInfo`. Use this pattern for events that always co-occur — for example, when you track both `MOE_PAGE_VIEWED` and `SESSION_START` on page load in one request.

<Info>
  Note

  This approach works because you author both events inside a single trigger at config time. AMP fires the trigger once and sends all events together. This differs from automatic cross-trigger batching (grouping separate trigger firings into one request), which MoEngage does not support — see the note below.
</Info>

<CodeGroup>

```HTML HTML lines wrap
<amp-analytics type="moengage" id="moengage">
<script type="application/json">
{
  "vars": {
    "appId": "XXXXXXXXXXXXXXXX",
    "dataCenter": "sdk-01"
  },
  "triggers": {
    "pageLoadBundle": {
      "on": "visible",
      "request": "eventV2",
      "extraUrlParams": {
        "viewsCount": 2,
        "viewsInfo": [
          {
            "EVENT_ACTION": "MOE_PAGE_VIEWED",
            "EVENT_ATTRS": {
              "URL": "${sourceUrl}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          },
          {
            "EVENT_ACTION": "SESSION_START",
            "EVENT_ATTRS": {
              "referrer": "${documentReferrer}"
            },
            "EVENT_G_TIME": "${timestamp}",
            "EVENT_L_TIME": "${timestamp}"
          }
        ]
      }
    }
  }
}
</script>
</amp-analytics>
```

</CodeGroup>

MoEngage receives the following request body:

```json JSON lines wrap
{
  "viewsCount": 2,
  "viewsInfo": [
    { "EVENT_ACTION": "MOE_PAGE_VIEWED", "EVENT_ATTRS": { "URL": "..." }, "EVENT_G_TIME": "...", "EVENT_L_TIME": "..." },
    { "EVENT_ACTION": "SESSION_START", "EVENT_ATTRS": { "referrer": "..." }, "EVENT_G_TIME": "...", "EVENT_L_TIME": "..." }
  ],
  "identifiers": {},
  "meta": { "bid": "...", "request_time": "...", "integration_type": "AMP" }
}
```

<Warning>
  Automatic Cross-Trigger Batching Not Supported

  AMP's built-in `batchInterval` collects firings from separate triggers and flushes them as a top-level JSON array, with one object per firing. The MoEngage `/v2/sdk/report` endpoint does not accept a top-level array body — it expects a single JSON object. Do not use `batchInterval`, since it results in rejected requests. Use the manual multi-event trigger pattern above instead for events that always co-occur.
</Warning>
