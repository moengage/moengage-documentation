# Overview

This guide outlines how you can integrate the MoEngage WebSDK into ChatGPT custom applications. By Integrating MoEngage with your ChatGPT application you can:

- Track user behavior in real-time.
- Trigger On-Site Messaging (OSM).
- Expose MoEngage functionalities directly to ChatGPT AI via Model Context Protocol (MCP) tools.

<Tip>
  **Prerequisites**

  Before beginning the integration,  Ensure you have:

  - **ChatGPT Plus, Pro, or Business Account:** Required to enable Developer Mode and create custom apps/MCP connections.
  - **MoEngage Credentials:** Your MoEngage App ID and Data Center (DC) allocation.
  - **React-based UI/Widget:** A standard React application setup that serves as your ChatGPT widget iframe.
  - **Secure Environment:** An HTTPS domain or ngrok tunnel (ChatGPT requires a secure connection for the iframe and MCP).
  - **MCP Endpoint:** Deployed and accessible at (e.g., [https://your-domain.com/mcp](https://your-domain.com/mcp)).
</Tip>

# ChatGPT Setup and Configuration

Before implementing the SDK code, configure your custom GPT environment to recognize your application and MCP endpoint.

## Step 1: Enable Developer Mode

1. Go to: [https://chatgpt.com](https://chatgpt.com)
2. Click your profile icon (bottom-left) and select **Settings → Beta Features**.
3. Toggle **Developer Mode** ON.
4. Enable **Allow MCP Connections**. _(Note: Developer mode is only available in Plus/Pro/Business plans)._

## Step 2: Register App with ChatGPT

1. In ChatGPT, click **\+ Create → Create New GPT**.
2. Fill in the basic application info (e.g., Name: "Custom Assistant", Description: "App with AI interaction").
3. Click **Create**.

## Step 3: Configure MCP Transport

1. In the GPT editor, navigate to **Settings → Actions**.
2. Click **\+ Create New Action** or **\+ Add Action**.
3. Select transport: **"Model Context Protocol (HTTP)"**.
4. Enter your Server URL: [https://your-domain.com/mcp](https://your-domain.com/mcp).
5. Click **Test Connection**.

## Step 4: Review Tools in ChatGPT

After the connection test passes, ChatGPT displays your discovered tools (e.g., `view_menu`, `add_to_cart`, `track_event`, etc.).

## Step 5: Save and Test

Click **Save**. You now test mentions in the chat (e.g., @your-assistant do an action), prompting ChatGPT to call your tools and display results in the widget iframe.

# Implementation Steps

## 1. Install the MoEngage WebSDK

Both NPM and Standard WebSDK integration methods are supported. This guide focuses on the NPM WebSDK integration.

Run the following command in your project directory:

```shellscript NPM
npm install @moengage/web-sdk
```

## 2. Configure CSP Domain Whitelisting

The ChatGPT widget runs inside a strict internal iframe sandbox, standard CSP headers block the application by default. You must explicitly whitelist the CSP URL in your MCP server configuration. Ensure you whitelist both the MoEngage URLs (Base URLs, tracking endpoints, and OSM delivery URLs) and the sandbox URLs in your `connect-src` and `script-src` directives to prevent the browser from blocking requests.

## 3. Initialize the SDK and Inject Credentials

Initialize the SDK before your React component mounts. You will inject your MoEngage App ID and Data Center credentials into the widget HTML or environment variables.

Create a custom wrapper hook (`useMoEngage.js`) to cleanly manage initialization and expose SDK methods throughout your widget.


## 4. Register MCP Tools for ChatGPT AI

To allow the ChatGPT AI to understand and utilize MoEngage capabilities, register specific tools on your MCP server. Create custom tools that map to MoEngage functionalities. For example:

- `track_event`: Tracks a custom interaction.
- `identify_user`: Sets a unique user ID and custom attributes (First Name, Last Name, etc.).
- `track_page_view`: Manually logs a page/screen view.

When a user provides a prompt to ChatGPT (e.g., "Order a XYZ product"), ChatGPT communicates with the MCP server, determines which tool to use, and executes the bridge connection to your widget.

## 6. Track Events and Identify Users

With your `useMoEngage` hook and `handleToolResult` dispatcher in place, event tracking becomes a seamless part of your widget's interactive flow.

- Custom Events: When UI interactions occur (either via direct user clicks in the iframe or via ChatGPT prompts processed by the MCP), call your trackEvent function.
- OSM Dismissals: Because OSMs render custom DOM IDs, users must interact directly with the widget UI to accurately track dismissals or clicks.

💡 Tip: Shared Execution Path\*\* The integration is designed so that both manual UI interactions (like clicking an "Add to Cart" button) and Chat commands (via MCP) ultimately execute the exact same underlying JavaScript functions. The chat interface does not track events directly; it uses MCP to call the widget, which then fires the standard tracking events.

# Test and Verify Integration

To ensure the integration works as expected:

1. **Verify Initialization:** Open the ChatGPT widget and check the network tab. Ensure calls to MoEngage domains succeed and are not blocked by CSP errors.
2. **Test Custom Events:** Interact with the UI natively and via ChatGPT text prompts (e.g., ask the AI to open a specific menu item). Check the MoEngage dashboard to confirm the custom events log in real-time.
3. **Verify User Profiles:** Trigger the identification tool and check if user attributes (name, phone number, etc.) update properly in the MoEngage system.
4. **Test Ad Blockers:** Ensure that events successfully record even if standard browser extensions or blockers are active.
5. **Test Trigger-based OSMs:** Create a test OSM triggered by a specific custom event. Execute the event in the ChatGPT app and verify the OSM displays correctly within the widget iframe.

# FAQs

**Q: How do Chat commands interact with the UI widget?** A: Chat commands do not interact with the UI directly. Instead, the chat passes the intent to the MCP server. The MCP server processes this and sends a result back. The application then uses a `handle_tool_result` function to parse the MCP output and call the corresponding public JavaScript function on the widget.

**Q: Does the Chat/MCP integration automatically track events to MoEngage?** A: No. The chat interface cannot track events on its own. Behind the scenes, the developer maps the MCP commands to trigger standard SDK tracking functions. For example, if a user asks the chat to "add product," the MCP server tells the widget to execute the action, and the widget is responsible for calling the `track_event` function.

**Q: How do I dismiss an On-Site Message (OSM) via a chat command?** A: OSMs use custom IDs, you cannot dismiss them globally without context. You expose a public tool/function specifically for dismissing OSMs, and the chat command passes the specific OSM ID to that function to close it successfully.

**Q: Which MoEngage public functions are supported via the Chat Tools?** A: You create hooks/tools to access almost all global public functions. The most commonly used tools exposed to the chat interface include:

- `track_event` (with custom attributes)
- `track_page_view`
- `identify_user` (First name, last name, phone, gender, etc.)
- `set_user_attribute`
- `get_user`
- `logout`

**Q: How do marketers create campaigns if URL-based segmentation is blocked in the sandbox?** A: Marketers shift from URL-based segmentation to event-triggered campaigns. While they cannot target users based on the URL they view in the sandbox, they set OSMs and campaigns to trigger when specific custom events (e.g., `page_viewed`, `item_added`) are fired by the tools.

**Q: What is the prerequisite for setting up these custom Chat tools?** A: Before registering the app with the MCP server or creating custom chat hooks, you install and initialize the standard MoEngage Web SDK within your project (e.g., your React application).
