# Overview

This guide outlines how to integrate the MoEngage Web SDK into ChatGPT custom applications. By integrating MoEngage with your ChatGPT application, you can:

- Track user behavior in real-time.
- Trigger On-Site Messaging (OSM).
- Trigger Cards.
- Expose MoEngage functionalities directly to ChatGPT AI via Model Context Protocol (MCP) tools.

<Info>
  ChatGPT executes custom widgets within a secure iframe sandbox. As a result, the execution URL differs from your primary domain, and standard URL-based campaigns are not supported.

  However, you can seamlessly deliver targeted experiences by configuring your campaigns to fire on Custom Events instead. All trigger-based On-Site Messages (OSMs) and Cards remain fully supported for this integration.
</Info>

# ChatGPT Setup and Configuration

<Tip>
  **Prerequisites**

  Before beginning the integration, ensure you have:

  - **ChatGPT Plus, Pro, or Business Account:** Required to enable Developer Mode and create custom apps/MCP connections.
  - **MoEngage Credentials:** Your MoEngage App ID and Data Center (DC) allocation.
  - **React-based UI/Widget:** A standard React application setup that serves as your ChatGPT widget iframe.
  - **Secure Environment:** An HTTPS domain or ngrok tunnel (ChatGPT requires a secure connection for the iframe and MCP).
  - **MCP Endpoint:** Deployed and accessible at (e.g., [https://your-domain.com/mcp](https://your-domain.com/mcp)).
</Tip>

Follow the steps below to configure your custom GPT environment to recognize your application and MCP endpoint.

## Step 1: Enable Developer Mode

1. Navigate to  [https://chatgpt.com](https://chatgpt.com).
2. Click your profile icon and select **Settings → Beta Features**.
3. Turn on the  **Developer Mode** toggle.
4. Enable **Allow MCP Connections**.

## Step 2: Register App with ChatGPT

1. In ChatGPT, click **\+ Create → Create New GPT**.
2. Fill in the basic application info (e.g., Name: "Custom Assistant", Description: "App with AI interaction").
3. Click **Create**.

## Step 3: Configure MCP Transport

1. In the GPT editor, navigate to **Settings → Actions**.
2. Click **\+ Create New Action** or **\+ Add Action**.
3. Select transport: **"Model Context Protocol (HTTP)"**.
4. Enter your Server URL: [https://your-domain.com/mcp](https://your-domain.com/mcp).
5. Click **Test Connection**.

## Step 4: Review Tools in ChatGPT

After the connection test passes, ChatGPT displays your discovered tools (e.g., `view_menu`, `add_to_cart`, `track_event`, etc.).

## Step 5: Save and Test

Click **Save**. You now test mentions in the chat (e.g., @your-assistant do an action), prompting ChatGPT to call your tools and display results in the widget iframe.

# Implementation Steps

## 1. Install the MoEngage WebSDK

Both NPM and Standard WebSDK integration methods are supported. This guide focuses on the NPM WebSDK integration.

Run the following command in your project directory:

```shellscript NPM
npm install @moengage/web-sdk
```

## 2. Configure CSP Domain Whitelisting

The ChatGPT widget runs inside a strict internal iframe sandbox, standard CSP headers block the application by default. You must explicitly whitelist the CSP URL in your MCP server configuration. Ensure you whitelist both the MoEngage URLs (Base URLs, tracking endpoints, and OSM delivery URLs) and the sandbox URLs in your `connect-src` and `script-src` directives to prevent the browser from blocking requests.

## 3. Initialize the SDK and Inject Credentials

Initialize the SDK before your React component mounts. You will inject your MoEngage App ID and Data Center credentials into the widget HTML or environment variables.

Create a custom wrapper hook (`useMoEngage.js`) to cleanly manage initialization and expose SDK methods throughout your widget.

```javascript useMoEngage Hook
import { useEffect, useRef, useCallback } from 'react';
import * as moengage from '@moengage/web-sdk';

export default function useMoEngage() {
  const initRef = useRef(false);
  const sdkReadyRef = useRef(false);

  useEffect(() => {
    if (initRef.current) return;
    initRef.current = true;
    // You can directly use app_id or dataCenter.
    const appId = window.__MOENGAGE_APP_ID__;
    const dataCenter = window.__MOENGAGE_DATA_CENTER__;

    if (!appId || !dataCenter) {
      console.warn('[MoEngage] Missing credentials');
      return;
    }

    // Initialize SDK
    moengage.initialize({
      appId,
      cluster: getCluster(dataCenter),  // Maps dc_0 → DC_1, etc
      env: 'LIVE',
      logLevel: 0,  // No console logs in production
    });

    // Poll until SDK ready (max 10 iterations × 500ms = 5s)
    let attempts = 0;
    const poll = setInterval(() => {
      if (window.Moengage?.onsite) {
        clearInterval(poll);
        sdkReadyRef.current = true;
        moengage.trackEvent('app_opened', { source: 'widget' });
      }
      if (++attempts >= 10) clearInterval(poll);
    }, 500);

    return () => clearInterval(poll);
  }, []);

  // Wrapped callbacks safe for dependency arrays
  const trackEvent = useCallback((name, props = {}) => {
    if (!window.Moengage) {
      console.warn('[MoEngage] SDK not ready');
      return;
    }
    try {
      moengage.trackEvent(name, props);
    } catch (err) {
      console.error('[MoEngage] trackEvent error:', err);
    }
  }, []);

  const identifyUser = useCallback((userObj) => {
    if (!window.Moengage) return;
    try {
      moengage.add_unique_user_id(userObj.uid);
      if (userObj.attrs) {
        Object.entries(userObj.attrs).forEach(([k, v]) => {
          moengage.add_user_attribute(k, v);
        });
      }
    } catch (err) {
      console.error('[MoEngage] identifyUser error:', err);
    }
  }, []);

  const setEmailId = useCallback((email) => {
    if (!window.Moengage) return;
    try {
      moengage.setEmailId(email);
    } catch (err) {
      console.error('[MoEngage] setEmailId error:', err);
    }
  }, []);

  const setUserAttribute = useCallback((name, value) => {
    if (!window.Moengage) return;
    try {
      moengage.add_user_attribute(name, value);
    } catch (err) {
      console.error('[MoEngage] setUserAttribute error:', err);
    }
  }, []);

  const logout = useCallback(() => {
    if (!window.Moengage) return;
    try {
      moengage.logoutUser();
    } catch (err) {
      console.error('[MoEngage] logout error:', err);
    }
  }, []);

  return { trackEvent, identifyUser, setEmailId, setUserAttribute, logout };
}

function getCluster(dc) {
  const map = { dc_1: 'DC_1', dc_2: 'DC_2', dc_3: 'DC_3', dc_4: 'DC_4', dc_5: 'DC_5', dc_6: 'DC_6' };
  return map[dc] || 'DC_1';
}
```

## 4. Register MCP Tools for ChatGPT AI

To allow the ChatGPT AI to understand and utilize MoEngage capabilities, register specific tools on your MCP server. Create custom tools that map to MoEngage functionalities. For example:

- `track_event`: Tracks a custom interaction.
- `identify_user`: Sets a unique user ID and custom attributes (First Name, Last Name, etc.).
- `track_page_view`: Manually logs a page/screen view.

When a user provides a prompt to ChatGPT (e.g., "Order a XYZ product"), ChatGPT communicates with the MCP server, determines which tool to use, and executes the bridge connection to your widget.

## 5. Handle Tool Results (handleToolResult)

Once the widget catches the postMessage from the MCP server, set up a dispatcher function to handle these incoming commands, update the UI, and trigger the appropriate MoEngage SDK wrapper functions.

```javascript handleToolResult
const handleToolResult = useCallback((result) => {
  // Normalize response envelope (handles multiple nesting levels)
  let data = result?.structuredContent || 
             result?.result?.structuredContent || 
             result?.content?.structuredContent || 
             result;

  switch (data.action) {
    case 'update_cart':
      syncCart(data.cart);
      moe.trackEvent('item_added_to_cart', {...});
      break;
    case 'moe_track_event':
      moe.trackEvent(data.eventName, data.properties);
      break;
    // ... 15+ more cases
  }
}, [cart, clearCart, moe, syncCart]);
```

## 6. Track Events and Identify Users

With your `useMoEngage` hook and `handleToolResult` dispatcher in place, event tracking becomes a seamless part of your widget's interactive flow.

- **Custom Events**: When UI interactions occur (either via direct user clicks in the iframe or via ChatGPT prompts processed by the MCP), call your trackEvent function.
- **OSM Dismissals**: Because OSMs render custom DOM IDs, users must interact directly with the widget UI to accurately track dismissals or clicks.

<Info>
  The integration is designed so that both manual UI interactions (such as clicking an "Add to Cart" button) and Chat commands (via MCP) ultimately execute the same underlying JavaScript functions. The chat interface does not track events directly; it uses MCP to call the widget, which then fires the standard tracking events.
</Info>

# Test and Verify Integration

To ensure the integration works as expected:

1. **Verify Initialization:** Open the ChatGPT widget and check the network tab. Ensure calls to MoEngage domains succeed and are not blocked by CSP errors.
2. **Test Custom Events:** Interact with the UI natively and via ChatGPT text prompts (e.g., ask the AI to open a specific menu item). Check the MoEngage dashboard to confirm the custom events log in real-time.
3. **Verify User Profiles:** Trigger the identification tool and check if user attributes (name, phone number, etc.) update properly in the MoEngage system.
4. **Test Ad Blockers:** Ensure that events successfully record even if standard browser extensions or blockers are active.
5. **Test Trigger-based OSMs:** Create a test OSM triggered by a specific custom event. Execute the event in the ChatGPT app and verify the OSM displays correctly within the widget iframe.

# FAQs

<AccordionGroup>
  <Accordion title="How do Chat commands interact with the UI widget?">
    Chat commands do not interact with the UI directly. Instead, the chat passes the intent to the MCP server. The MCP server processes this and sends a result back. The application then uses a `handle_tool_result` function to parse the MCP output and call the corresponding public JavaScript function on the widget.
  </Accordion>

  <Accordion title="Does the Chat/MCP integration automatically track events to MoEngage?">
    No. The chat interface cannot track events on its own. The developer maps the MCP commands to trigger standard SDK tracking functions. For example, if a user asks the chat to "add product," the MCP server tells the widget to execute the action, and the widget is responsible for calling the `track_event` function.
  </Accordion>

  <Accordion title="How do I dismiss an On-Site Message (OSM) via a chat command?">
    OSMs use custom IDs, you cannot dismiss them globally without context. You expose a public tool/function specifically for dismissing OSMs, and the chat command passes the specific OSM ID to that function to close it successfully.
  </Accordion>

  <Accordion title="Which MoEngage public functions are supported via the Chat Tools? ">
    You can create hooks/tools to access almost all global public functions. The most commonly used tools exposed to the chat interface include:

    - `track_event` (with custom attributes)
    - `track_page_view`
    - `identify_user` (First name, last name, phone, gender, etc.)
    - `set_user_attribute`
    - `get_user`
    - `logout`
  </Accordion>

  <Accordion title="How do marketers create campaigns if URL-based segmentation is blocked in the sandbox?">
    Marketers must shift from URL-based segmentation to event-triggered campaigns. While they cannot target users based on the URL they view in the sandbox, they can set OSMs and campaigns to trigger when specific custom events (e.g., `page_viewed`, `item_added`) are fired by the tools.
  </Accordion>

  <Accordion title="What is the prerequisite for setting up these custom Chat tools?">
    Before registering the app with the MCP server or creating custom chat hooks, you must install and initialize the standard MoEngage Web SDK within your project (e.g., your React application).
  </Accordion>
</AccordionGroup>
