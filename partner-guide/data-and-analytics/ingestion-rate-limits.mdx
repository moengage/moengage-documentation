MoEngage applies an ingestion rate limit and a payload cap to the data that a partner sends into your workspace. The limit depends on the API that the integration is built on, so the same partner can have one limit for users and events and a different limit for cohorts.

## How MoEngage Assigns These Limits

Three APIs carry partner data into MoEngage, and each one has its own limit. The following table describes the API that governs each entity:

| API | Entities | Ingestion rate limit | Applies to |
| --- | --- | --- | --- |
| Data API | Users, Events | Varies by endpoint. Refer to the [Data API](/api/data/data-overview) reference. | Partners built on the standard MoEngage Data API. |
| Partner integration API | Users, Events | 500 RPS | Partners with a dedicated MoEngage integration, such as mParticle, Amplitude, and Zeotap. |
| Cohort API | Cohorts, Segments | 300 RPM | Partners that sync segments directly into MoEngage. |

To identify which limit applies to a partner that is not listed on this page, check the partner's integration guide. If the guide states that your segments are available in MoEngage without creating them again, that partner uses the Cohort API, and the 300 RPM cohort limit applies. Partners that sync audiences without using the Cohort API, such as Twilio Segment and Adobe Real-Time CDP, use 500 RPS for cohorts instead.

## Partner Import Limits

The following table describes the limit for each partner. Every limit in this table applies per workspace:

| Partner | Integration type | Users and events | Cohorts |
| --- | --- | --- | --- |
| mParticle | Partner integration API and Cohort API | 500 RPS | 300 RPM |
| Amplitude | Partner integration API and Cohort API | 500 RPS | 300 RPM |
| Zeotap | Partner integration API and Cohort API | 500 RPS | 300 RPM |
| AppsFlyer | Cohort API | 500 RPS | 300 RPM |
| Hightouch | Data API and Cohort API | Refer to the [Data API](/api/data/data-overview) reference. | 300 RPM |
| Twilio Segment | Partner integration API | 500 RPS | 500 RPS |
| Adobe Real-Time CDP | Partner integration API | 500 RPS | 500 RPS |
| Connected sources, such as Ventrata, RevenueCat, Zoho CRM, HubSpot CRM, Intercom, LeadSquared, Zendesk, and Olo | Partner integration API | 500 RPS | 500 RPS |

Every partner import in the preceding table carries a payload cap of 128 KB. When a partner exceeds its rate limit, MoEngage returns a `429 (Too Many Requests)` error, and the partner is expected to handle retries automatically.

<Note>
  These limits do not apply to MoEngage Source integrations. MoEngage Source forwards campaign interaction events from MoEngage out to a partner through MoEngage Streams, so no data is ingested into your workspace.
</Note>

## File Import Limits

These limits apply to imports from S3, SFTP, and manual uploads. The following table describes the hourly and daily limit for each entity:

| Entity | Hourly limit | Daily limit | On breach |
| --- | --- | --- | --- |
| Users | 600K | 14M | MoEngage queues the files until the limits reset. |
| Events | 5M | 40M | MoEngage queues the files until the limits reset. |

## Data Warehouse Import Limits

These limits apply to imports from Snowflake, Databricks, and BigQuery. Users and events share the same pool, so both entity types draw from one limit. The following table describes the hourly and daily limit:

| Entity | Hourly limit | Daily limit | On breach |
| --- | --- | --- | --- |
| Users and Events | 15M | 50M | MoEngage processes the import on a best-effort basis. |

<Note>
  If your ingestion volume regularly approaches any of these limits, contact your MoEngage Customer Success Manager (CSM) to discuss your requirements.
</Note>
