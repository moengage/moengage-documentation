# Introduction

[Oracle Hospitality](https://www.oracle.com/hospitality/hotel-property-management/hotel-pms-software/) OPERA Cloud is a cloud-based property management platform (PMS) built for the hospitality sector. It manages end-to-end hotel operations including reservations, guest profiles, check-in/check-out, room management, and billing.

## Use Cases

- Send a pre-arrival welcome message when a new reservation is created.
- Trigger an upsell campaign when a guest checks in.
- Launch a post-stay feedback journey on checkout.
- Update guest profile attributes in MoEngage when contact details change in OPERA Cloud.

<Info>
**Integration Architecture**

This integration is powered by the prebuilt [Oracle Hospitality Adapter](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/update-or-retrieve-information-opera-cloud.html) available within Oracle Integration Cloud (OIC). Configure it as the trigger or invoke block to securely capture events from OHIP, and use a REST adapter as the invoke block to push the event to MoEngage.
</Info>

# Prerequisites

Before setting up the integration, confirm the following are in place:

1. **Oracle Integration Cloud (OIC)** — An active OIC subscription with access to *Developer Services > Application Integration > Integrations*.
2. **OHIP Developer Portal account** — An account on the [Oracle Hospitality Integration Platform (OHIP) Developer Portal](https://docs.oracle.com/cd/F29336_01/).

For the complete prerequisites of the adapter, see [Prerequisites for Creating a Connection](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/prerequisites-creating-connection.html).

## Step 1: Register an Application on the OHIP Developer Portal

This is a one-time setup that generates the credentials needed to authenticate OIC with OHIP. Follow the steps at [Registering an Application](https://docs.oracle.com/en/industries/hospitality/integration-platform/ohipu/t_registering_an_application.htm).

At the end of registration, note down your **Application Key** from the application credentials page.

![OHIP application credentials page showing the Application Key](/images/oracle1.png)

## Step 2: Add an Environment and Gather Credentials

Add an environment to your application. Oracle recommends using the **OCIM (OPERA Cloud Identity Management)** environment type — the modern, OCI-native identity system using the standard OAuth 2.0 client credentials flow. Follow the steps at [Adding an Environment](https://docs.oracle.com/en/industries/hospitality/integration-platform/ohipu/t_adding_an_environment.htm).

<Tip>
**Oracle's Recommended Authentication: OCIM**

This integration uses OCIM — Oracle's recommended authentication method for OHIP APIs. OCIM environments provide Client ID, Secret, Scope, and Gateway URL directly, unlike the legacy SSD approach which does not support OCIM environment creation by customers. See [Migrating to the Client Credentials (OCIM) Authentication Scheme](https://docs.oracle.com/en/industries/hospitality/integration-platform/ohipu/t_migrating_to_client_credentials_based_authentication_scheme_ocim.htm).
</Tip>

Switch to the **Environments** tab, select your OCIM environment, and click **View Details** to gather the following:

![OHIP OCIM environment details with Client ID, Client Secret, and Scope](/images/oracle2.png)

| Credential | Where to find it |
| --- | --- |
| **Gateway URL** | OHIP OCIM Environment details (for example, `https://<env>.hospitality-api.<region>.ocs.oc-test.com`) |
| **Client ID** | OHIP OCIM Environment details |
| **Client Secret** | OHIP OCIM Environment details |
| **Scope** | OHIP OCIM Environment details — typically `urn:opc:hgbu:ws:__myscopes__` |
| **Application Key** | Application credentials page (from Step 1) |
| **Enterprise ID** | Your Oracle chain/enterprise code (for example, `OCR4ENT`) |
| **External System ID** | The external system code configured in OPERA Cloud for your MoEngage integration (for example, `MOENGAGEGLOBAL`) |
| **Chain Code** | Your Oracle chain code (for example, `OHIPLAB`) |

## Step 3: Create the Oracle Hospitality Connection in OIC

Follow the official guide: [Create a Connection — Oracle Hospitality Adapter](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/create-connection.html#GUID-10DBB72D-F6F9-4851-B2BA-9E593CF65F2E).

In Oracle Cloud, navigate to *Developer Services > Application Integration > Integrations* and open the OIC Console.

![Oracle Integration Cloud console](/images/oracle3.png)

Navigate to *Design > Connections > Create*, search and select the **Oracle Hospitality Adapter**. Fill in the credentials gathered in Step 2:

![Creating the Oracle Hospitality Adapter connection in OIC](/images/oracle4.png)

| Field | Value |
| --- | --- |
| **Connection URL** | Your OHIP gateway URL from Step 2 |
| **Client ID** | From your OHIP OCIM environment |
| **Client Secret** | From your OHIP OCIM environment |
| **Application Key** | From your OHIP application (Step 1) |
| **Scope** | `urn:opc:hgbu:ws:__myscopes__` — enter under *Optional Security* |
| **Enterprise ID** | Your Oracle chain/enterprise code — enter under *Optional Security* |

![Oracle Hospitality connection security settings](/images/oracle5.png)

Click **Test** to validate the connection, then **Save**. A *Configured* badge confirms the connection is ready.

<Info>
**Trigger or Invoke — How to decide?**

When adding this connection to an integration, the Oracle Hospitality Adapter can be placed as a **Trigger** (Connectivity Agent approach) or an **Invoke** (Scheduled Integration approach). The choice affects your integration type, polling frequency, and whether a local agent is needed. Review the comparison in Step 5 to decide before creating the integration.
</Info>

## Step 4: Create the MoEngage REST Connection in OIC

In OIC, navigate to *Design > Connections > Create* and select the **REST Adapter**:

![Creating the MoEngage REST connection in OIC](/images/oracle6.png)

| Field | Value |
| --- | --- |
| **Connection URL** | `https://api-0X.moengage.com` — replace `X` with your MoEngage datacenter (01, 02, 03, or 04) |
| **Security Policy** | Basic Authentication |
| **Username** | Your MoEngage App ID |
| **Password** | Your MoEngage DATA API key |

![MoEngage REST connection authentication settings](/images/step4restconnection2.png)

Click **Test**, then **Save**.

<Info>
**configName**

The MoEngage Partner API requires a `configName` query parameter on every request. This is a unique GUID identifying your MoEngage Oracle Hospitality configuration. Obtain this from your MoEngage account team — you will add it as an integration property in Step 5.
</Info>

## Step 5: Choose Your Approach and Build the Integration Flow

With both connections ready, create a new integration in OIC and wire it based on your polling requirements. Choose the approach that fits your infrastructure and latency needs:

| Approach | How it works | Min. interval | Connectivity agent required? |
| --- | --- | --- | --- |
| **Connectivity Agent (Trigger role)** | An agent process runs on a machine and polls OHIP at the configured interval. Lower latency, more frequent polling. | 5 seconds | Yes — agent must remain running |
| **Scheduled Integration (Invoke connection)** | OIC's built-in scheduler calls OHIP at the configured interval — no local agent required. Uses External System ID to fetch events for all hotels under the chain in a single call. | 10 minutes | No |

Read more on the [Polling API](https://docs.oracle.com/en/industries/hospitality/integration-platform/ohipu/t_polling_api.htm#PollingAPIpull-170089A2).

<Tabs>
  <Tab title="Connectivity Agent Approach">
    <Tip>
      **Lower Latency, Higher Frequency**

      Supports polling every 5 seconds with up to 20 events per call. Requires the connectivity agent to remain running on a stable machine. See [Download and Run the Connectivity Agent Installer](https://docs.oracle.com/en/cloud/paas/application-integration/integrations-user/downloading-and-running-premises-agent-installer.html#ICSUG-GUID-3F36A9CE-BE4E-4A74-AE7E-C6005CC97A12).
    </Tip>

    **Integration flow:** Trigger (OHIP) → Map (MoEngage request) → Invoke MoEngage

    1. Create a new **Application Integration** in OIC. For guidance on adding the Oracle Hospitality Adapter as a Trigger and configuring the Business Events page, refer to [Use the Connectivity Agent to Poll for Business Events from OHIP](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/fetch-business-events-from-opera-cloud.html#GUID-4341FB10-6408-4363-8D23-19FB6AA37F42__AAA).
    2. Add the **MoEngage REST connection** as an Invoke node. See [Configure the MoEngage Invoke](#configure-the-moengage-invoke) below for the full setup.
    3. A **Map** node will automatically appear before the MoEngage Invoke. Upload the mapper XSL file provided by MoEngage (three-dot menu → Import).
    4. Set the integration property `ConfigName` (see [Set Integration Properties](#set-integration-properties) below).
  </Tab>
  <Tab title="Scheduled Integration Approach">
    <Info>
      **No Infrastructure Overhead**

      Fully managed within OIC — no local agent required. Uses **External System ID** to fetch events for all hotels under the chain in a single API call, rather than polling per hotel. For full documentation, see [Fetch Business Events from OPERA Cloud](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/fetch-business-events-from-opera-cloud.html).
    </Info>

    **Integration flow:** Schedule → Map (OHIP request) → Invoke OHIP → Map (MoEngage request) → Invoke MoEngage

    1. Create a new **Schedule Integration** in OIC.
    2. Add the Oracle Hospitality connection as an **Invoke** node. Select **Integration Processor** as the module and `getBusinessEventsByExternalSystem` as the operation. For full guidance, see [Create a Schedule Integration to Poll for Business Events from OHIP](https://docs.oracle.com/en/cloud/paas/application-integration/hospitality-adapter/fetch-business-events-from-opera-cloud.html#GUID-4341FB10-6408-4363-8D23-19FB6AA37F42__BBB).
    3. A **Map** node will appear before the OHIP Invoke. Use the visual **Mapping canvas** to set the following fields — no XSL file is required for this mapper:
       - **X Externalsystem** → reference the `ExtSystemCode` integration property (for example, `MOENGAGEGLOBAL`).
       - **Limit** → `20` (OHIP hard cap per call).
    4. Add the **MoEngage REST connection** as an Invoke node after the OHIP Invoke. See [Configure the MoEngage Invoke](#configure-the-moengage-invoke) below for the full setup.
    5. A second **Map** node will appear before the MoEngage Invoke. Upload the mapper XSL file provided by MoEngage (three-dot menu → Import).
    6. Set both integration properties `ConfigName` and `ExtSystemCode` (see [Set Integration Properties](#set-integration-properties) below).
  </Tab>
</Tabs>

1. **Edit Basic Info**: Resource URI `/v1/partner/oracle-hospitality/events/`, HTTP Method **POST**. Check: *Add and review parameters*, *Configure a request payload*, *Configure this endpoint to receive the response*.

Once saved, a **Map** node will automatically appear before the MoEngage Invoke on the canvas.

### Upload the Mapper XSL File

The MoEngage team provides a mapper XSL file for the OHIP response to MoEngage transformation. This applies to **both** approaches — it is the mapper for the Map node before the MoEngage Invoke only. The Scheduled approach's first Map node (OHIP GET request) does not need a mapper file; use the visual Mapping canvas for that.

1. On the canvas, right-click or click the three-dot menu on the **Map** node before the MoEngage Invoke.
2. Select **Import**.
3. Upload the XSL file provided by MoEngage.

![Importing the mapper XSL file on the Map node in OIC](/images/mapper.png)

<Info>
**Need a different event module?**

The out-of-the-box mapper supports **Reservation** and **Profile** events. For other OHIP modules (for example, Housekeeping, Blocks, Rate Management), contact the MoEngage team — custom mapper and schema changes are required. Read more about [OHIP Business Events](https://docs.oracle.com/en/industries/hospitality/integration-platform/ohipu/c_business_events.htm).
</Info>

### Set Integration Properties

In the integration, navigate to *Settings > Integration Properties* and add the following. Both properties are required for the Scheduled approach; only `ConfigName` is required for the Trigger-based approach.

| Property name | Type | Required for | Value |
| --- | --- | --- | --- |
| `ConfigName` | String | Both approaches | The `configName` GUID from your MoEngage Oracle Hospitality partner configuration page |
| `ExtSystemCode` | String | Scheduled approach only | Your External System ID (for example, `MOENGAGEGLOBAL`) — used in the OHIP GET call to fetch events across all hotels in the chain |

Optionally, configure **Business Identifiers** for runtime tracking. Click the tracking icon on the canvas toolbar and assign source fields to the primary and secondary tracking variables. These appear as labels in *Observability > Instances*.

## Step 6: Test, Validate, and Activate

### 6a — Test the Mapper

1. Open the **Map** node before the MoEngage Invoke.
2. Click the **Play (▶)** button in the mapper toolbar — this runs the mapper against sample input and shows the generated output on the Target side.
3. Verify the output matches the expected MoEngage payload structure.
4. Click **Validate** to check for mapping errors.
5. Click **Save** and return to the integration canvas.

### 6b — Save and Activate

1. Click **Save** on the integration canvas.
2. Click **Activate** and select the appropriate tracing level:

| Level | What is logged and retained |
| --- | --- |
| **Production** | Activities outside loops and invoke/logger activity inside loops (up to 1000 iterations). Retained for **32 days**. Recommended for live traffic. |
| **Audit** | All of the above, plus wire payloads of trigger/invoke steps in the activity stream. Retained for **8 days**. Use during initial testing. |
| **Debug** | All payloads and all activities inside loops. Retained for **24 hours**, then auto-resets to Production. May slow the system and expose sensitive data. Use only for deep troubleshooting. |

<Tip>
**Recommended: Start with Audit**

Use **Audit** for initial testing — it shows full request and response payloads in the activity stream without the overhead or security risk of Debug. Once validated end-to-end, deactivate, switch to **Production**, and reactivate.
</Tip>

### 6c — Validate the Flow

1. Trigger a test event in OPERA Cloud (for example, create a new reservation).
2. Navigate to *Observability > Integrations* — confirm the instance counter shows Received, Processed, and Succeeded incrementing.
3. Click *Observability > Instances*, open the instance, and confirm each step in the activity stream completed successfully.
4. Verify the event appears in MoEngage under the guest profile matching the `customer_id` (Guest Name ID from OPERA Cloud).
5. On the OHIP Developer Portal under *Analytics*, confirm API calls are being received with a 100% success rate and 0 errors.

## Error Handling and Resubmission

<Info>
**Note: Manual Resubmission Required**

Oracle Integration Cloud does not support automatic retry of failed integration instances. All failed instances must be manually resubmitted from *Observability > Instances*.
</Info>

To resubmit a failed instance:

1. In OIC, navigate to *Observability > Instances* or *Observability > Errors*.
2. Locate the failed instance by business identifier.
3. Hover over the row and click the **Resubmit** icon.
4. Select tracing level — use *Debug* for troubleshooting or *Audit* for normal resubmission. This applies only to the resubmitted instance.
5. Click **Confirm**. The instance restarts from the point of failure.

For bulk resubmission, select multiple error rows and click **Resubmit** in the top-right corner.

<Warning>
**Resubmission Limits**

Each instance can be resubmitted a maximum of **10 times**. Do not discard an instance you intend to resubmit — discarded instances cannot be recovered.
</Warning>
