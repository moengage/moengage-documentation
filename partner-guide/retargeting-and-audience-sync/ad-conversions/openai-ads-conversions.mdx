# Introduction

The MoEngage and OpenAI Ads Conversions integration establishes a secure, server-to-server (S2S) connection. By bypassing browser-side obstacles such as cookie restrictions, Intelligent Tracking Prevention (ITP), and ad blockers, it captures conversions that client-side tracking often misses.

MoEngage provides a single omnichannel connector for OpenAI — **OpenAI Ads Conversions** — available through the **OpenAI Ads Conversions** app in the MoEngage App Marketplace. It sends conversion events captured across all your environments (website, mobile app, and physical store) directly into your OpenAI Ads Manager.

## Use Cases

Integrating OpenAI Ads Conversions with MoEngage allows you to sync event data to support the following use cases:

- **Signal resilience**: Recover "lost" conversions typically blocked by browser privacy settings and ad blockers.
- **Real-time attribution**: Send server-side signals directly to OpenAI to improve click-through and view-through attribution accuracy.
- **Return on Ad Spend (ROAS) optimization**: Send real-time conversion data to OpenAI to improve ad delivery, audience matching, and Cost Per Acquisition (CPA).
- **Multi-source tracking**: Capture purchases, subscriptions, sign-ups, appointments, and custom events from any channel, and attribute them to your OpenAI ad clicks.
- **Conversion reporting**: Report conversion volume and value in OpenAI Ads Manager to measure return on investment.

# Integration

## Step 1: Generate Credentials in OpenAI Ads Manager

To establish the connection, retrieve your Pixel ID and generate an API key in OpenAI Ads Manager.

### Step 1.1: Retrieve Your Pixel ID

To retrieve your Pixel ID, perform the following steps:

1. Log in to OpenAI Ads Manager.
2. Locate your Pixel ID, and then copy it.

Paste the value in a safe place for use in the [Step 2: Connect OpenAI Ads Conversions in the App Marketplace](/partner-guide/retargeting-and-audience-sync/ad-conversions/openai-ads-conversions#step-2-connect-openai-ads-conversions-in-the-app-marketplace) section.

<Note>
  If you have not set up the Conversions API yet, select **Conversions API Only** and follow the setup wizard. OpenAI generates your Pixel ID automatically.
</Note>

### Step 1.2: Generate a Conversions API Key

To generate a Conversions API key, perform the following steps:

1. Navigate to **Settings** \> **General**, and then locate the **Manage Conversion Keys** section.
2. Click **Generate New Key**.
3. Enter a name for your key (for example, MoEngage Integration).
4. Click **Generate** to create your API key.
5. Copy the key.

<Note>
  Save the API key in a secure place. It cannot be retrieved after you close the dialog box, so if you lose it, you must generate a new key.
</Note>

## Step 2: Connect OpenAI Ads Conversions in the App Marketplace

To connect OpenAI Ads Conversions in the App Marketplace, perform the following steps:

1. On the left navigation menu in the MoEngage UI, click **App marketplace**.
2. On the **App marketplace** page, search for **OpenAI Ads Conversions**.
3. Click the **OpenAI Ads Conversions** tile.
4. On the **OpenAI Ads Conversions** page, click the **Integrate** tab.
5. Enter the following details:

   | Field | Required | Description |
   | --- | --- | --- |
   | Connection Name | Yes | A unique internal name for the connection (for example, OpenAI Ads - Production). |
   | API Key | Yes | The Bearer token from your OpenAI Ads Manager, generated in the [Step 1.2: Generate a Conversions API Key](/partner-guide/retargeting-and-audience-sync/ad-conversions/openai-ads-conversions#step-1-2-generate-a-conversions-api-key) section. This authorizes API calls. |
   | Pixel ID | Yes | The Pixel ID from your OpenAI Ads Manager, retrieved in the [Step 1.1: Retrieve Your Pixel ID](/partner-guide/retargeting-and-audience-sync/ad-conversions/openai-ads-conversions#step-1-1-retrieve-your-pixel-id) section. This directs conversion signals to the correct dataset. |

6. Click **Test Connection** to validate and save the connection.

<Note>
  Changes to the connection can take up to 15 minutes to reflect in campaigns.
</Note>

## Step 3: Create an OpenAI Ads Conversions Campaign

To create an OpenAI Ads Conversions campaign, perform the following steps:

1. On the left navigation menu in the MoEngage UI, click **Engage**, and then click **Campaigns**.
2. On the **All campaigns** page, click **+ Create campaign**.
3. In the **Create campaign** dialog box, under **Connected Apps**, click **OpenAI Ads Conversions**, and then click the most suitable delivery type.
4. In **Step 1** (Target Users), select your audience.
5. In **Step 2** (Content), select your connector (**OpenAI Ads Conversions**) and your created connection.
6. Under **Conversion Goals**, select the following:

   | Field | Required | Description |
   | --- | --- | --- |
   | Event Type | Yes | The conversion event to track, from OpenAI's standard taxonomy. Default is `order_created`. |
   | Action Source | Yes | Defines the channel where the conversion originated: `web`, `mobile_app`, `offline`, `physical_store`, `phone_call`, `email`, or `other`. Default is `web`. |
   | Custom Event Name | Conditional | Required only when **Event Type** is `custom`. Enter 1–64 characters, using lowercase letters, numbers, underscores, and dashes. |
   | Event ID | Optional | Unique transaction, order, or event ID used for deduplication. Ensures only the first signal with this ID is recorded. Type `@` to personalize. |

   The **Action Source** drives omnichannel tracking, letting you attribute conversions to app interactions, web visits, or physical storefront purchases.

7. Under **Attribution**, enter the following:

   | Field | Required | Description |
   | --- | --- | --- |
   | Source URL | Optional | The URL where the conversion occurred (for example, `https://shop.example.com/checkout/confirmation`). Required for the `web` action source. |
   | IP Address | Optional | IPv4 or IPv6 address, used to improve user matching. Sent raw rather than hashed. Type `@` to personalize. |

   Include the **Source URL** wherever possible, because it improves click-through attribution accuracy for web events.

8. Under **User Matching**, map user identifiers. Identifiers help OpenAI link conversions to specific users. Sensitive data such as email addresses and internal user IDs is normalized and SHA-256 hashed automatically to protect privacy.

   | Key | Description |
   | --- | --- |
   | email | Maps to the user email. The system strips aliases and periods, lowercases the string, and applies SHA-256 hashing. Pre-filled from the standard attribute. |
   | external_id | Your internal customer or user ID (for example, `customer_12345`). Protected with SHA-256 hashing. |
   | country | Two-letter ISO 3166-1 country code (for example, `US`). Sent as-is. |
   | city | City name, lowercased automatically. Maximum 128 characters. |
   | zip_code | Postal or ZIP code. Sent as-is. Maximum 32 characters. |
   | ip_address | IPv4 or IPv6 address, used to improve user matching. Sent raw rather than hashed. |
   | user_agent | The browser's User-Agent string, which helps with cross-device attribution. |

9. Under **Event Content & Values**, map the conversion details:

   | Key | Applies To | Description |
   | --- | --- | --- |
   | amount | All events | Monetary value as an integer in minor units, following ISO 4217. For example, `4200` for $42.00 USD. |
   | currency | All events with `amount` | ISO 4217 currency code, such as `USD` or `EUR`. Required whenever `amount` is present. |
   | plan_id | Subscriptions, Custom | Your internal subscription or plan identifier (for example, `plan_starter`). |
   | item_id | Purchase, Subscriptions, Custom | Internal product or item identifier (for example, `sku_12345`). |
   | item_name | Purchase, Subscriptions, Custom | Product name (for example, Premium Subscription). |
   | item_quantity | Purchase, Subscriptions, Custom | Number of items, as an integer. |
   | content_type | Optional for all | Item category or type (for example, `product`). |
   | group_id | Optional for all | Product group or bundle identifier (for example, `bundle_summer_2024`). |
   | variant_dict.size | Optional for all | Product variant size (for example, `large`). |
   | variant_dict.color | Optional for all | Product variant color (for example, `blue`). |

10. Test your connector configuration, and then publish the campaign.

Test your connector in a staging environment before you publish to production.

## Custom Events

To track a conversion outside OpenAI's standard taxonomy, perform the following steps:

1. Under **Conversion Goals**, select `custom` in the **Event Type** list.
2. In the **Custom Event Name** box, enter a name of 1–64 characters, using lowercase letters, numbers, underscores, and dashes. Spaces are not supported.
3. Under **Event Content & Values**, map the parameters that apply to the event.

Valid custom event names include `video_completed`, `ebook_downloaded`, and `webinar_registered`.

## Usage Constraints

- **Monetary value format**: Send amounts as integers in the currency's minor units. For example, $42.00 USD is `4200`, €29.99 EUR is `2999`, £1.50 GBP is `150`, and ¥100 JPY is `10000`, because JPY has no decimal sub-units. The `currency` key is required whenever `amount` is present.
- **Deduplication hygiene**: Map a unique **Event ID**, such as a transaction or order ID, to prevent over-reporting. OpenAI records only the first occurrence of an Event ID and ignores duplicates.
- **User matching and privacy**: Map at least one user identifier for effective attribution. Pass raw values directly to the connector, because the system normalizes and SHA-256 hashes personally identifiable information (PII) natively.
- **Timestamp accuracy**: Event timestamps must fall within the last 7 days and cannot be more than 10 minutes in the future. MoEngage fills in the current timestamp when you omit it.
- **Rate limits and batch processing**: The OpenAI Conversions API accepts batches of up to 1,000 events per request. If one event in a batch fails schema validation, the entire batch fails, so verify data integrity across all events.

## FAQs

<AccordionGroup>
  <Accordion title="Can I send events from multiple channels in the same campaign?">
    Yes. Assign the appropriate **Action Source** for each event, and OpenAI attributes the conversions across channels.
  </Accordion>
  <Accordion title="What happens if I send the same Event ID twice?">
    OpenAI deduplicates events on the Event ID. Only the first instance it receives is recorded, and subsequent identical IDs are ignored.
  </Accordion>
  <Accordion title="Can I track revenue per item?">
    Yes. Under **Event Content & Values**, specify the overall purchase amount alongside the item-specific details. Use the `variant_dict` keys for item attributes such as size and color.
  </Accordion>
  <Accordion title="How do I handle multi-item orders?">
    Specify the total order value in `amount`, and use `item_quantity` for multi-unit items. For complex multi-product orders, either send individual item events or group them under a single bundle identifier.
  </Accordion>
</AccordionGroup>
