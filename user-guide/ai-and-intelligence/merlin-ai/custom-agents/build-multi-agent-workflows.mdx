A Custom Agent performs a single, well-defined job. Marketing workflows often span several jobs: pull campaign data, analyze it, draft a recommendation, and QC the result. To automate a workflow of this kind, attach existing agents to a **coordinator** agent as **sub-agents**. When you run the coordinator, it delegates each part of the task to the relevant sub-agent and consolidates the results into a single response.

<Note>
 If the **Sub Agents** section does not appear in the Agent Builder, contact your Customer Success Manager (CSM) to confirm availability for your workspace.
</Note>

## How Delegation Works

A coordinator is a regular Custom Agent that carries a roster of sub-agents alongside its tools. It follows the lifecycle you already use — create, configure, test, publish, edit, pause, and delete. For details, refer to [Create and Manage Custom Agents](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents).

Delegation follows these rules:

- **Delegation extends one level:** A coordinator delegates to the agents on its roster, and each sub-agent completes its assigned task directly. Rosters accept agents that carry no sub-agents of their own.
- **One session covers the whole workflow:** Running a coordinator opens a single session. MoEngage executes the delegated work inside that session and records it as one task in the **All tasks** history.
- **The running user's permissions apply:** Each sub-agent executes with the permissions and credentials of the user who starts the run. Delegation grants an agent exactly the access that user already holds.
- **Sub-agents work in parallel:** Sub-agents run at the same time, and the coordinator consolidates their output into a single response.

## Eligible Sub-Agents

An agent qualifies as a sub-agent when it is both **public** and **Live**. The picker lists every eligible agent.

The following agents remain ineligible:

- Draft, paused, and deleted agents.
- Agents that another user keeps private.
- The agent you currently edit. A coordinator references other agents, never itself.
- Agents that carry sub-agents of their own.

Each agent occupies a roster once.

## Assign Sub-Agents

To attach sub-agents to an agent:

1. Open the agent in the Agent Builder. For a new agent, refer to [Create a Custom Agent](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents#create-a-custom-agent). For an existing agent, go to **Manage** > **Edit** on the agent's detail page.
2. In the right panel, locate the **Sub Agents** section below **Tools**.
3. Search for an agent by name and select it.
4. To review a candidate before you add it, open its **Agent Info** view. Agent Info opens in a new browser tab and displays the agent's creator, its total number of runs, and the date of its last run.
5. Describe the delegation in the coordinator's instructions: name the sub-agent that handles each part of the task, and state how the coordinator combines the results. The coordinator relies on its instructions to decide what to delegate. For guidance, refer to [Configure your Agent's Instructions](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents#configure-your-agents-instructions).
6. Run a **Test agent** session to confirm each hand-off behaves as you expect, then click **Make live**.

<Note>
 A coordinator references a sub-agent rather than owning it. To change a sub-agent, open that agent directly — its creator retains sole permission to edit its configuration, change its visibility, or delete it.
</Note>

### Visibility Rules

A public coordinator references public sub-agents only. MoEngage blocks both of the following actions:

- Adding a private agent to a public coordinator's roster.
- Making a coordinator public while it references a private sub-agent.

For more on visibility, refer to [Set Visibility](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents#set-visibility).

### Keep a Roster Up to Date

When you save a coordinator, MoEngage captures the published version of each sub-agent on its roster. The coordinator continues to use those captured versions after someone republishes a sub-agent, so a live coordinator behaves consistently until you update it.

To adopt a sub-agent's newer version, open the coordinator in the builder, save it, and click **Make live**.

## Run a Coordinator

Start a coordinator the way you start any other agent — from the agent card, the agent's detail page, or **Test agent** in the builder. For the full run experience, refer to [Run and Manage Agent Sessions](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/run-and-manage-agent-sessions).

A delegated run behaves as follows:

- The transcript displays delegated activity inline as it happens, so you see which sub-agent handles which part of the task. MoEngage indents each sub-agent's messages under the coordinator's own steps.
- Sub-agents share the coordinator's session, its attached files, and its credentials.
- Files that a sub-agent produces appear in the parent session's outputs alongside the coordinator's own files. Refer to [Session Outputs Panel](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/run-and-manage-agent-sessions#session-outputs-panel).
- The **All tasks** history records the run as one task, with a single transcript covering the coordinator and every sub-agent it calls.

<Warning>
 Review the tools you assign to every agent on a roster before you publish the coordinator. Delegated work follows the same rules as any other run: an agent with write tools makes real changes to your workspace, in Test runs as well as Live runs.
</Warning>

## FAQs

<AccordionGroup>
  <Accordion title="Can a sub-agent have sub-agents of its own?">
    No. Delegation extends one level. A coordinator delegates to its sub-agents, and each sub-agent completes its task directly. When you build a roster, the picker lists only the agents that carry no sub-agents of their own.
  </Accordion>

  <Accordion title="Whose permissions does a sub-agent use?">
    The permissions of the user who starts the run. Each sub-agent executes with that user's access rather than its own creator's, so every delegated action stays within the running user's existing entitlements. For details, refer to [Custom Agent Essentials: Permissions and Security](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/custom-agents-essentials-permission-and-security).
  </Accordion>

  <Accordion title="I updated an agent that other coordinators use. Do those coordinators pick up my changes?">
    Not automatically. Each coordinator uses the sub-agent version captured at its last save. The creator of each coordinator opens it in the builder, saves it, and makes it live again to adopt your updated version.
  </Accordion>

  <Accordion title="Can I add a teammate's private agent to my agent's roster?">
    Rosters accept public, Live agents, which includes any public agent your teammates publish. To use the behavior of a private agent, duplicate an agent you have access to, or ask its creator to make the agent public.
  </Accordion>

  <Accordion title="Does a delegated run log differently from a normal run?">
    No. The delegation runs inside the coordinator's single session, and MoEngage logs it as one task in the **All tasks** history with one transcript covering the coordinator and every sub-agent it calls.
  </Accordion>
</AccordionGroup>
