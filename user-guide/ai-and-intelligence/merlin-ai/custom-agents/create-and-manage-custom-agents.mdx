## Create a Custom Agent

When building a new Custom Agent, you can choose from the following methods:

### Kickstart Using Templates
Use this option to select a pre-configured template as your starting point. Templates are not shared agents; they are configurations — nothing is created until you act on a template. MoEngage presents templates in a dedicated template gallery.

MoEngage provides four platform-curated templates to help you get started:

- **Campaign QC Agent**
- **Push Campaign Drafter**
- **Language Translation (Bulk)**
- **Marketing Analyst**

 <img alt="CA-create from templates.png"  src="/images/CA-create from templates.png"  />
As you browse the template gallery, the detail panel displays a preview of the associated instructions, tools, and trigger, letting you verify the agent's capabilities before making a selection. To create a custom agent from a template:
  1. On the left navigation menu in the MoEngage dashboard, go to **AI Agents** > **Custom Agents**.
  2. On the Custom agents page, click **+ New custom agent**. MoEngage opens the template gallery.
  3. Select a template from the gallery. The detail panel previews the associated instructions and tools.
  4. Click **Try now**. MoEngage prompts you to name the agent.
  5. Name the agent and confirm. MoEngage creates the agent, publishes the agent, and opens the Run panel so you can start using the agent immediately.

<Note>
 After you create an agent from a template, you can still edit its configuration at any time. See [Edit an Agent](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents#edit-an-agent). The created agent keeps no ongoing link to the source template — later changes to the template don't affect your agent.
</Note>
      
### Create from Scratch
Use this option to manually author the agent's instructions and select the required tools, or leverage Merlin AI to automatically draft the configuration based on your prompts. To create a custom agent from scratch:
  <img alt="CA-create from sratch.png"  src="/images/CA-create from sratch.png"  />
1. On the left navigation menu in the MoEngage dashboard, go to **AI Agents** > **Custom Agents**.
2. On the Custom agents page, click **+ New custom agent**. MoEngage opens the template gallery.
3. Click **Create from scratch** in the gallery. MoEngage opens the Agent Builder with a blank configuration.

Starting from a template gets your agent running immediately; starting from scratch opens the Agent Builder so you can author the agent's configuration before publishing.

## Configure your Custom Agent

Both creation paths open the unified Custom Agent Builder. Whether you are starting from a blank canvas or modifying a template, use the following interface and steps to finalize your agent's configuration.

<Note>
 MoEngage creates the agent's draft the first time you make a change in the builder — opening the builder alone doesn't create anything. From that point, MoEngage autosaves your progress as a draft, so you don't need to manually save while configuring the agent.
</Note>

* **Name the agent:** Click the agent name field located at the top of the configuration screen. By default, this field displays *Untitled* or the name of your selected template. Provide a clear, action-oriented name that helps your team quickly identify the agent's specific purpose (for example, `Pre-send Push QA` or `EMEA Email Translator`). The agent name supports up to 120 characters.
    <img alt="CA-name.png"  src="/images/CA-name.png"  />
* **Agent description:** MoEngage generates the agent's description automatically from your instructions, using the AI builder or the selected template. The description supports up to 500 characters. MoEngage does not provide a manual description editor.
The configuration interface consists of three primary components that control different aspects of the agent:
    <img alt="CA-agent builder.png"  src="/images/CA-agent builder.png"  />
* **Merlin AI Assistant:** An interactive AI chat interface designed to help you automatically generate instructions and recommend required tools based on your plain-text prompts.
* **Instructions Editor:** A plain-text editor where you define the agent's core operational parameters, including its specific role, objectives, procedural steps, and required output format.
* **Settings Panel:** Manage agent permissions (tools), select a model tier, set a run trigger and notifications, attach reference files, and define workspace access levels (Public or Private).

### Configure your Agent's Instructions

The Instructions editor serves as the agent's operational playbook. Written in plain English, these instructions define exactly how the agent behaves and executes tasks. The Instructions editor supports up to 50,000 characters. To configure your agent, you must provide instructions and tools. You can populate the instructions editor using three different approaches:
    <img alt="CA- Instructions.png"  src="/images/CA- Instructions.png" width="50%" />
* **By Template**: If you started with a template, the editor is pre-filled with a tested playbook. You can edit it or leave it as is.
* **[By Merlin AI Agent Builder](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/create-and-manage-custom-agents#use-the-merlin-ai-agent-builder-optional)**: Use the chat assistant to automatically draft the instructions and assign tools based on a plain-English prompt.
* **By Hand**: Write or edit the instructions manually directly within the text editor.

#### Core Components of a Well-Structured Agent
Whether you use a template, Merlin AI, or write them from scratch, your instructions must explicitly define the following elements to ensure the agent performs consistently:

* **Role:** Who the agent is and its specific area of expertise.
* **Objective and Workflow:** The primary goal of the task and a numbered, ordered list of steps the agent must follow to complete the job.
* **Rules and Guardrails:** Strict operational boundaries, detailing exactly what the agent must always do and what it must never do.
* **Output Format:** The exact structure the agent should use when returning its final response (for example, a formatted table, a bulleted list, or a summarized report).

#### Example Instruction Structure
Use the following structural framework as a baseline when authoring your agent's instructions:

```plaintext wrap
## Role
You are a [description] agent that specializes in [core capability].

## Objective
In each run, you will [state the primary goal].

## Rules
- Always [mandatory action].
- Never [restricted action].

## Steps
1. [First action]
2. [Second action]
3. [Third action]

## Output format
[Describe the expected output structure, e.g., "Return the findings in a two-column table."]
````
<Note>The more precise your instructions, the more reliably the agent will perform. Avoid vague directions such as "analyze data." Instead, provide exact parameters and expected actions, such as "fetch all Push campaigns from the last 30 days and compute the Click-Through Rate (CTR) for each.”</Note>

 #### Use the Merlin AI Agent Builder (Optional)
<Note> Using the Merlin AI assistant is optional. If you prefer, you can skip this step and manually author your agent's configuration directly in the Instructions Editor.</Note>

If you are unsure where to begin, you can leverage the Merlin AI chat interface in the left panel to automatically generate a baseline configuration for your agent.
To generate configurations using Merlin AI:
1. **Provide a Prompt**: In the text input field at the bottom of the left panel, type a sentence or two describing what you want your agent to accomplish using plain English.
  <Note> You can attach reference files directly to your message to help Merlin AI generate the initial instructions (for example, uploading an example output format you want the agent to mimic). However, these files are not persisted. Only the resulting text instructions are saved to the agent's core knowledge for future sessions.</Note>
2. **Generate Draft**: Submit your prompt. Merlin AI will process the request and automatically populate the center panel with drafted instructions and the right panel with recommended tools.
3. **Review and Refine**: Manually edit the generated instructions and tool selections to ensure they align perfectly with your exact use case.

**Quick-Action Prompts** 

If you need inspiration or immediate guidance, you can select one of the predefined quick-action chips located in the chat panel:
- Give me ideas to build
- Role of instructions and tools
- Explore capabilities
- How to proceed?

<Note>Merlin AI is a generative tool and can occasionally make mistakes. You must always thoroughly review the generated instructions and tool selections for accuracy before saving your configuration or making the agent Live.</Note>

### Assign Tools
Tools are pre-built capabilities that grant the agent specific permissions to access MoEngage data and perform actions. Based on your provided instructions and description, Merlin AI automatically assigns tools relevant to the task. However, you can manually adjust these assignments at any time. Each agent supports up to 128 tools. The tool picker lists each tool's name and description inline. For details on how tool permissions interact with your MoEngage role, refer to [Custom Agent Essentials: Permissions and Security](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/custom-agents-essentials-permission-and-security).
  <img alt="CA- tools.png"  src="/images/CA- tools.png" width="50%" />
In the **Tools** panel on the right side of the builder, click the + icon to open the tool picker. 

<Note> Only assign the tools that the agent strictly needs to complete its objective. Granting unnecessary tools increases the risk of unintended actions.</Note>

#### Add and Remove Tools

To grant your agent specific capabilities, you must assign tools using the tool picker:
        <img alt="CA- tools picker.png"  src="/images/CA- tools picker.png" width="400" />
1. Click the + icon next to the **Tools** heading on the right panel to open the tool picker dialog box. An agent you create from scratch starts with every available tool pre-selected; an agent you create from a template starts with that template's own tool selection.
2. Uncheck any tool the agent doesn't need, or select the checkbox next to a tool to add it (for example, ```Read campaign data``` or ```Read campaign analytics```).
  - Use the **Search to select bar** at the top of the dialog to quickly locate specific tools.
  - To remove every tool at once, click **Clear all**.
3. Click **Apply** to confirm and save your tool assignments. After selection, tools appear as individual chips within the Tools section of the configuration panel.
4. To remove an assigned tool, click the × icon on its corresponding chip.

<Note>
 If you select a tool you don't have permission to use, MoEngage removes the tool from the agent silently when you save. The agent's tool access always matches your own MoEngage permissions.
</Note>

<Warning>If you assign any tools that perform write operations, a warning banner appears in the configuration panel. This indicates that the agent has permission to modify real workspace data. Even in Test mode, an agent with write tools can create real drafts or alter existing campaigns. Review your tool selections carefully and only grant write access when it is strictly required for the agent's designated task.</Warning>

<Note>
 Beyond assigned tools, every agent has access to MoEngage's built-in document skills. Agents can read and generate spreadsheets, documents, slides, and PDFs without requiring an explicit tool assignment. Built-in skills apply automatically and require no configuration.
</Note>

### Select a Model

Use the **Model** section in the right panel to control the balance between response speed, cost, and analytical depth for your agent. Instead of choosing a specific AI model, you select from three capability tiers:

- **Fast:** The Fast tier handles lightweight, low-latency tasks, such as quick data lookups.
- **Balanced (Default):** The Balanced tier handles moderate-complexity tasks, such as campaign QC or segment analysis.
- **Expert:** The Expert tier handles tasks requiring deep, multi-step reasoning, such as in-depth performance analysis across multiple campaigns.

<Note>
 Some workspaces may occasionally encounter an authorization error when running an agent on the Expert tier. If you experience this, switch the agent to the Balanced tier, or contact MoEngage support.
</Note>

The Model dropdown lists tiers from lowest to highest cost. If you don't select a tier, your agent runs on **Balanced** by default.

<Note>
 MoEngage may update the AI model powering a tier over time to maintain quality and reliability, without requiring any action from you or changing any other part of your agent's configuration.
</Note>

### Set a Trigger

In the **Trigger** section of the right panel, choose how the agent runs:

- **Run manually (Default):** The agent only runs when you or a teammate clicks **Run**.
- **Run on schedule:** The agent runs automatically on a recurring schedule you define.

Configure a schedule using the following steps:
1. Select **Run on schedule**.
2. Choose a recurrence — **Daily**, **Weekly**, or **Monthly**. For a Daily recurrence, set the repeat interval from 1 to 999 days. Weekly and Monthly recurrences repeat every 1 week or 1 month; MoEngage does not support a longer repeat interval for these recurrences.
3. Set a start date and an end condition (never, on a specific date, or after a set number of occurrences).
4. Set the timezone for the schedule. The schedule's timezone defaults to your dashboard's timezone.

Each agent supports one schedule. After you set a schedule, the Trigger section displays a summary of the start date, end condition, and a **Next run on ‹date›** preview.

When a scheduled run fires, MoEngage sends the agent a standard prompt to start the run. MoEngage does not provide an option to customize the scheduled prompt.

<Note>
 Only the agent's creator can view and configure the agent's Trigger and Notifications settings. Because scheduled runs execute using the creator's own MoEngage credentials and permissions, teammates viewing a public agent see the Trigger and Notifications controls disabled.
</Note>

<Warning>
 Publishing a scheduled agent requires ready workspace credentials supporting scheduled execution. MoEngage blocks publishing until you resolve any credential issues.
</Warning>

### Attach Files

Use the **Files** section in the right panel to attach reference files that MoEngage includes with every run. Attached files support common document, spreadsheet, and image formats.

Attach a file using the following steps:
1. Click the **+** icon in the Files section.
2. Select a file from your device.

Each agent supports up to 5 files, with a 5 MB limit per file. MoEngage attaches every configured file to each Test and Live run automatically.

<Note>
 Files you attach in the Files section persist across every run. Files you attach directly to a Merlin AI Assistant prompt or a Test agent message apply only to that single conversation.
</Note>

### Set Visibility

In the **Visibility** section, use the **Private** toggle located in the right panel to control who can locate and execute the agent. You can modify this access level at any time.
       <img alt="CA- visibility.png"  src="/images/CA- visibility.png" width="50%" />
- **Private OFF (Default):** The agent is visible to all users in your workspace under the **Public agents** tab. Any teammate can run or duplicate the agent. Only you (the creator) can edit, pause, resume, or delete the agent.
- **Private ON:** The agent is restricted. Only you can view, access, and run the agent — MoEngage does not show the agent to any other user, or reveal that the agent exists.

<Note>
 The Private toggle applies only after you publish the agent. A draft agent remains visible only to the agent's creator regardless of the Private toggle setting.
</Note>

<Note>
 A public agent (Private toggle OFF) grants access only to users within your specific MoEngage workspace, never to anyone outside your organization.
</Note>

### Configure Notifications

In the **Notifications** section, toggle **Email** on or off to control whether you receive an email each time a scheduled run completes. The Email toggle defaults to on.

Each notification email includes the run's outcome, Task ID, start time, duration, and the next scheduled run. The notification email excludes the run's transcript and output content. MoEngage delivers notification emails on a best-effort basis, so a missed notification email never blocks or delays the underlying scheduled run.

<Note>
 Browser notifications are a separate feature from the Email toggle above. If you grant notification permission when prompted in an active session, your browser notifies you when that run finishes while its tab isn't focused. Browser notifications aren't tied to your Email setting, and MoEngage doesn't provide an in-app way to turn them off once granted — manage them through your browser's site settings instead.
</Note>

<Note>
 Only the agent's creator can edit Notifications settings. Teammates viewing a public agent see the settings, disabled.
</Note>

## Test Agent

Before making an agent live and sharing it with your team, you must run it in **Test agent** mode. This allows you to verify that the agent correctly interprets its instructions, utilizes the appropriate tools, and produces the expected output.

<Warning>
Test sessions execute against your real MoEngage workspace data; there is no sandbox environment. Read-only agents will query your actual campaigns and segments. If your agent has write tools assigned (such as Create campaign drafts or Edit campaigns), it will make real changes to your workspace during a test run. Treat a test session with the same caution as a Live session.
</Warning>

### Initiate a Test Run

To start a test run from the builder:
   <img alt="CA- test agent.png"  src="/images/CA- test agent.png"  />
1. Click **Test agent** in the action bar at the bottom right of the screen. The Test agent panel will slide open on the right side.
2. In the text box at the bottom of the panel, type a test scenario or select one of the suggested quick-start prompts:
   * **Run now:** Executes the agent immediately using its default instructions.
   * **Show capabilities:** Prompts the agent to summarize what it is configured to do.
   * **What tools can you access?:** Lists the tools currently assigned to the agent.
   * **Walk me through a scenario:** Asks the agent to narrate a sample execution.
3. Press **Enter** or click the send button to initiate the task.
     <img alt="CA- Initoate a test.png"  src="/images/CA- Initoate a test.png"  />
  In addition to sending prompts, the Test agent panel includes several interface features to help you manage and review your test sessions:
      <img alt="CA- New test 1.png"  src="/images/CA- New test 1.png"  />
  - **Start a New Test:** Click **+ New test** in the left sidebar of the test panel to clear the current chat window and initiate a fresh test session.
  - **Cancel a Running Test:** Click **Cancel** while a test is in progress to stop the run immediately.
  - **Review Past Test Runs:** The left sidebar logs your testing history under the **Past test runs** section, organized by date and time (for example, *20 May, 5:17 pm*). Click on any timestamp to reopen that specific test session and review the agent's previous responses or tool calls.
  - **Attach Test Files:** Click the **+** icon located inside the message input box at the bottom of the screen to attach up to 5 files to your test prompt. This allows you to provide the agent with sample data, specific documents, or reference files to process during the test run.
  - **Close the Test Panel:** To exit the testing environment and return to the configuration builder, click the **X** icon located near the top left of the main dashboard screen.

### Interprete Test Results

The test session functions exactly like a normal back-and-forth conversation. As the agent processes your request, the panel displays:

  - **Tool calls:** Each time the agent utilizes a tool, the interface displays the tool name, the context parameters (e.g., `get_campaign_meta context="Finding all sent/active campaigns"`), and the execution time.
  - **Agent reasoning:** Intermediate messages explaining the agent's logic as it works through the assigned steps.
  - **Final output:** The structured result returned upon completing the task.
  - **Iterate on Feedback:** If the agent calls the wrong tools or misinterprets your prompt, close the test panel, return to the Instructions editor, and clarify the steps. Be highly specific about what data the agent should fetch and how it should format it.


## Make the Agent Live

After you successfully test and confirm the agent's behavior, click **Make live** in the action bar at the bottom of the screen to publish the agent to your workspace.
   <img alt="CA- make live.png"  src="/images/CA- make live.png"  />

Publishing an agent requires a name and instructions. MoEngage warns you if you attempt to publish an agent with untested changes.

When an agent transitions to a Live state, MoEngage makes the agent available on the main Custom Agents dashboard. Locate the agent by clicking the **Live** filter. Depending on the agent's configured visibility, MoEngage also categorizes the agent under the **My agents** or **Public agents** filters.
 <Note>
  You can continue to modify a live agent's configuration. MoEngage holds your edits as pending changes until your next publish, so a live agent never changes for other users mid-session. Click **Make live** again to apply pending changes.
</Note>
To learn how to initiate test runs, interpret the transcript, and understand the functional differences between Live and Test modes, refer to [Run and Manage Agent Sessions](/user-guide/ai-and-intelligence/merlin-ai/custom-agents/run-and-manage-agent-sessions)

### Edit an Agent

To update an existing agent's configuration (including its status, instructions, assigned tools, name, or visibility):

1. From the Custom Agents dashboard, click anywhere on the agent's card (except the **Run (▶)** icon) to open its detail page.
2. Click the **Manage** dropdown menu located in the top-right corner and select **Edit**.
3. The configuration builder opens with all existing fields pre-populated. Make your required updates.
4. Review the instructions and run a **Test agent** session to verify its behavior.
5. Click **Make live** to save and deploy the changes.

<Note>
  * Modifications only apply to new sessions initiated after you save. Any sessions that are actively running when you save will continue and complete using the agent's previous configuration.
  * Only the original creator of an agent has permission to edit it. If you need to modify an agent created by a colleague, you must duplicate it first.
  * Agents currently in a **Draft** state cannot be executed for production tasks directly from the dashboard. To make a draft agent operational, you must finalize its configuration:

      1. Open the agent's detail page and navigate to **Manage** > **Edit** to open the builder.
      2. Run a test session to verify the agent's behavior.
      3. Click **Make live** to publish the agent for production use.

    The agent will seamlessly transition to the **Live** filter on your dashboard, and its status will update to enable you and your team to run production tasks.
</Note>    

### Pause or Resume an Agent

Pause a live agent to stop the agent from running while keeping the agent's configuration intact. To pause or resume an agent:

1. Open the agent's detail page.
2. Click the **Manage** dropdown menu and select **Pause** (or **Resume** for a paused agent).

<Note>
 Pausing a live agent stops scheduled runs; manual runs stay available even while the agent is paused. If the agent has a configured schedule, MoEngage does not cancel the schedule when you pause the agent — the schedule persists, and each scheduled fire is skipped for as long as the agent stays paused. Resuming a paused agent returns the agent to a Live state, and the existing schedule resumes firing with no reconfiguration required. Only the agent's creator can pause or resume an agent.
</Note>

### Duplicate an Agent

Duplicating an agent opens the builder pre-filled with the source agent's configuration as a new, independent Draft. This feature is ideal when you need to customize an agent built by another user, or when you want to fork an existing configuration for a similar task.

1. Open the agent's detail page.
2. Click the **Manage** dropdown menu and select **Duplicate**.

### Characteristics of a Duplicated Agent:
  - **Draft Status:** The duplicate opens in the builder as a Draft named `Duplicate_<Original name>` — rename it before you publish, if you'd like.
  - **Inheritance:** The duplicate inherits the source agent's instructions, assigned tools, visibility setting, and trigger configuration.
  - **Run History:** It begins with a fresh, empty session history.
  - **Eligibility:** You can duplicate any agent currently in a Draft or Live state. Deleted agents cannot be duplicated.

### Delete an Agent

If an agent is no longer required, you can retire the agent from your workspace to keep your dashboard organized. Only the agent's creator can delete an agent.

1. Open the agent's detail page.
2. Click the **Manage** dropdown menu and select **Delete**.

### Characteristics of an Deleted Agent:
  - **Visibility:** It is immediately removed from all dashboard filters (My agents, Public agents, Draft, and Live).
  - **Restrictions:** It can no longer be executed, edited, or duplicated.
  - **Audit Trail:** Its session history is preserved in the backend for auditing purposes, but the history is no longer accessible via the standard gallery interface.
  - **Memory:** MoEngage archives the agent's memory store along with its session history.

<Note>
  - Deleting an agent permanently cancels any of its scheduled or queued tasks. The system will display a warning prompt allowing you to confirm the cancellation before the delete action is finalized.
  - Currently, there is no recovery flow to restore a deleted agent. If there is a chance you may need to use the agent again in the future, do not delete the agent. Instead, edit the agent and turn the Private toggle ON. Turning Private ON hides the agent from your colleagues while keeping the agent safely accessible for your own use.
</Note>

## FAQs

<AccordionGroup>
  <Accordion title="Do Test runs operate in a safe sandbox environment?">
    No. Test runs execute against your real MoEngage workspace data. If an agent has write tools assigned (such as Create campaign drafts), it will make real changes to your workspace during a test session. Always verify tool configurations and instructions before initiating a test.
  </Accordion>

  <Accordion title="Can my teammates edit, pause, or delete an agent that I created?">
    No. Only the original creator of an agent can edit, pause, resume, or delete the agent. If a colleague needs to modify an agent you built, they must open the agent's detail page and select Manage > Duplicate to create an independently editable copy. Any teammate with access to a public agent can still run or duplicate it.
  </Accordion>

  <Accordion title="Can I delete an individual session or an entire agent?">
    Individual sessions cannot be deleted; they are permanently logged in the agent's history for auditing purposes. You can remove an agent from the dashboard by deleting it, but this action is permanent and cannot be undone. If you are unsure whether you will need an agent again, open the agent's configuration and turn the Private toggle ON instead of deleting the agent.
  </Accordion>
    <Accordion title="Do I need to know how to code to build an agent?">
    Not at all. You instruct the agent using plain English, just like you are writing a brief for a new marketing hire. If you get stuck, you can use the built-in Merlin AI chat assistant to automatically generate the right instructions and tool settings based on a simple description of what you want to achieve.
  </Accordion>

  <Accordion title="How do I share a great agent I built with the rest of the marketing team?">
    By default, a new agent is visible to your entire workspace once published — no action is required to share the agent. If you previously marked the agent Private, open the agent's configuration and turn the Private toggle OFF to make the agent visible again. Any teammate can run or duplicate a public agent, but only you (the creator) can edit, pause, resume, or delete the agent.
  </Accordion>

  <Accordion title="Can an agent automatically publish a campaign?">
    No. Custom Agents do not possess auto-publish capabilities. Even if an agent has write tools assigned, it is strictly restricted to creating, editing, or pausing campaign drafts. Final approval and deployment must always be executed manually through the standard MoEngage campaign builder.
  </Accordion>
</AccordionGroup>
