## Overview

The **All Campaigns** page is the central hub for viewing, organizing, and managing every campaign in your MoEngage account. From this page you can search for specific campaigns, filter and sort the campaign list, customize which information you see, and perform actions on one or many campaigns at once.

This guide covers every element on the page, including the new **Views**, **Dynamic Columns**, **Filters**, and **Bulk Actions** capabilities, along with step-by-step navigation instructions and common use cases.

## Use Cases

The All Campaigns page supports several recurring business needs for teams that run campaigns at scale:

- **Focus on the campaigns that matter to you**: When you own only a subset of channels or campaigns, a general list adds noise. Saved **Views** let you keep a personal, always-ready slice of the campaign list so you spend less time reapplying the same filters every day.
- **Keep a team aligned on the same set of campaigns**: Sharing a **Public** view across one or more teams gives everyone a common, consistent picture of the campaigns they're responsible for, without each member recreating it.
- **Tailor the information to a role**: Different roles care about different data. **Dynamic Columns** let each user surface the metrics relevant to their work and hide the rest, making the table easier to scan and act on.
- **Land on the right place every time**: Setting a **Default view** removes repetitive navigation, so the campaigns you monitor most are the first thing you see when you open the page.
- **Prepare for reviews and stakeholder updates quickly**: Bulk **Tag**, **Download**, and **Report** actions turn a large campaign list into a shareable summary or a detailed performance report in a few clicks, supporting recurring reporting cycles.
- **Manage many campaigns safely at scale**: Bulk **Pause**, **Stop**, and **Resume** apply an operation across many campaigns at once while respecting each campaign's eligibility, reducing manual, one-by-one effort and the risk of acting on the wrong campaign.
- **Declutter your workspace**: Pinning, unpinning, and reordering views keeps daily navigation focused on the tabs each user actually uses.

## Views

### What Is a View?

A **View** is a saved combination of **filters + columns + search term + visibility setting** that lets you define your own way of looking at the campaign list. Instead of re-applying the same filters every time you visit the page, you save them once as a View and select it whenever you want to see that specific slice of campaigns.

For example, a marketer who only cares about their own active Push and Email campaigns can create a View that always shows exactly that, without touching a filter again.

### System (Default) Views

When you load the All Campaigns page for the first time, MoEngage provides a set of built-in **system views**:

- **All**: every campaign, regardless of status.
- **Active**: campaigns currently running.
- **Schedule**: campaigns that are scheduled to send in the future.
- **Run Yesterday**: campaigns that executed the previous day.
- **Drafts**: campaigns saved but not yet activated.
- **Under Review/Rejected**: campaigns pending approval or rejected during review, if [Campaign Approval Workflow](/user-guide/settings/account/team-management/campaign-approval-workflow#enable-campaign-approval-workflow-for-campaigns) is enabled for your workspace.

These system views cannot be deleted, and the **All** view specifically cannot be unpinned/removed from your tab bar. For more information refer to [Managing Views](#managing-views).

### View Ownership: Private vs. Public

Views are created at the **individual user level**, every user can build their own set of views, and each view can be marked as one of two visibility types:

- **Private**: only visible to and editable by the user who created it. No one else in the workspace can see it.
- **Public (Team-based)**: shared with one or more teams. Every member of the selected team(s) will see this view appear on their own All Campaigns page.

<Note>
  If your workspace is **not** team-based, marking a view as Public shares it with everyone in the workspace.
</Note>

A single user can create and own **multiple** views. Refer to [View Limits](#view-limits) for the workspace-wide cap.

### Create a View

There are two ways to create a view:

**Method 1 — Create from an existing filter**

1. Go to any tab (for example, the **All** tab).
2. Apply your desired filters, search term, and/or column selection.
3. Click **Save as view**. You'll be prompted to configure the view (view the steps below).
      <img alt="all_campaigns_5a.gif"  src="/images/all_campaigns_5a.gif" width="50%" />

**Method 2 — Create from scratch**

1. Click the views dropdown (the down-arrow icon next to your tabs) and select **+ New view**.
2. This opens the **Create view** panel with a blank/default configuration.
3. Configure your filters, columns, and search term as needed, exactly as you would from an existing tab.
    <img alt="all_campaigns_6a.gif"  src="/images/all_campaigns_6a.gif" width="50%" />

**Configure the View (both methods):**

In the **Create view** panel, add the following details:
    <img alt="all_campaigns_7.png"  src="/images/all_campaigns_7.png" width="50%" />

| Field | Description |
|---|---|
| **View name** | A free-text name to identify your view. The **Create view** button stays disabled until a name is entered. |
| **View visibility** | Choose **Private** or **Public**. |
| — If Public (team-based workspace) | You'll be asked to select which team(s) to share the view with. The **shared list** reflects whichever teams you select here. |
| — If Public (non-team-based workspace) | The view becomes visible to everyone in the workspace. |
| **Columns** | Expand this section to review or edit which columns will appear in this view. For more information, refer to [Dynamic Columns](#dynamic-columns). Shown as a count, e.g., "Columns (7)". |
| **Filters** | Expand to review or add filters that will be applied whenever this view is loaded. Shown as a count, e.g., "Filters (0)". |
| **Search term** | Expand to review or set a saved search keyword for this view. Shown as a count, e.g., "Search term (0)". |

4. Once configured, click **Create view**.
5. The view is created and automatically loads, showing:
   - The view's name
   - The filters that are applied
   - The total number of campaigns matching the view

### Managing Views

Click **Manage views** (found in the views dropdown) to open a panel where you can control every view available to you — private, team-shared, and system views.

From **Manage views**, you can:

- **Search for a view** using the search box at the top.
- **Reorder views**: drag views using the handle icon to change the order in which they appear as tabs. This ordering is personal to you.
- **Pin/unpin views**: views under **Selected views** are the ones currently pinned as tabs on your main page. Views under **Other views** exist but are not pinned. Click the pin icon to move a view in or out of your pinned tab bar.
  - The **All** view is always pinned and cannot be unpinned.
  - All other views (including system views like Under Review/Rejected) can be freely pinned or unpinned based on your preference.
- **Set a default view**: use the three-dot (⋮) menu next to a view to mark it as **Default**. The default view is the one that automatically loads every time you navigate to the All Campaigns page (for example, after navigating away and returning). The current default is indicated with a **Default** badge.
- **Edit a view**: use the three-dot menu to modify a view's filters, columns, or visibility.
- **Delete a view**: also available from the three-dot menu (where applicable — system views cannot be deleted).
- Click **Apply changes** to save your pinning/reordering updates, or **Cancel** to discard them.

<Note>
  **Pinned views vs. session views:** If you temporarily bring up a view that isn't pinned (for instance, by applying a one-off filter), it will appear in your tab bar only for that session. Once you navigate away to another page and come back, only your pinned views (and your default view) will be shown again.
</Note>

### Editing an Existing View (View Actions)

If you modify the filters or columns of a view you've already saved (without creating a brand-new one), a **View actions** option appears with three choices:

| Action | What it does |
|---|---|
| **Update** | Saves your changes to the current view, overwriting its previous configuration. |
| **Save as new** | Creates a brand-new view with your changes, leaving the original view untouched. |
| **Reset** | Discards your unsaved changes and reverts the view back to its last saved configuration. |

### Changing Visibility (Private ↔ Public)

You can change a view's visibility at any time:

1. Open **Manage views**.
2. Select the view and choose to edit it.
3. Change the **View visibility** setting:
   - **Private → Public**: If your workspace uses teams, you'll need to select which team(s) to share it with. If there are no teams, the view becomes visible to the entire workspace.
   - **Public → Private**: The view becomes visible only to you again; other users lose access.
4. When switching to Public in a team-based workspace, all currently selected teams are pre-selected by default — you can deselect any team you no longer want to share the view with.

### View Limits

- A workspace can have a maximum of **100 views in total**, combined across all users.
- Once this limit is reached, no user in the workspace can create a new view until an existing one is deleted. You'll see a message indicating the workspace's view limit has been exhausted.

### Multi-Team Selection

Previously, users belonging to multiple teams could only view campaigns for **one** team at a time or **all** teams — there was no way to see a subset. This has been improved:

- You can now **select multiple specific teams** (rather than only "one" or "all") to filter the campaign list down to exactly the teams you care about.
- This is especially useful when building a view for a specific group of teams — for example, selecting Team A and Team B together, then saving that combination as a shared view for those teams.

## Dynamic Columns

Previously, every user saw the same fixed set of columns on the All Campaigns page. **Dynamic Columns** lets each user personalize exactly which data points they want displayed — this is a **per-user** setting.

### Managing Columns

1. Click the **column selection icon** near the filter bar to open the **Column selection** panel.
2. The panel is split into two lists:
   - **Selected columns**: currently visible on your table. Each has:
     - A **drag handle** (⠿) to reorder columns — the order here determines the left-to-right order in the table.
     - An **eye icon**: click to hide (remove) that column from the view.
   - **Available columns**: columns not currently shown. Each has a **crossed-out eye icon**: click to add (show) that column.
3. Use the **Search columns** box to quickly find a specific column by name.
4. Click **Apply** to save your column selection to the current view, or **Cancel** to discard changes.

### Available Column Options

Depending on your data, columns you can add include (non-exhaustive): Name, Channel, Status, First Send Date, Performance, Engagement, Last modified, Send, Delivery, Open Rate, Conversions, Approved by, Trigger event name, Custom segment, Scheduled on, Created on, Estimated audience count, and Team (visible only in team-based workspaces).

### Default Columns per Tab

Each system tab now ships with a **different, tab-relevant** default column set, rather than one identical set across all tabs. This makes each tab more readable and surfaces only the information that matters for that campaign state:

| Tab | Default Columns |
|---|---|
| **All** | Name, Channel, Status, First Send Date, (Team, if applicable), Performance, Engagement, Last modified |
| **Active** | Name, Channel, Status, Performance, Engagement, Last modified *(no "Send date" column, since only percentage/performance metrics matter here)* |
| **Schedule** | Name, Channel, Scheduled on, Created on, Estimated audience count *(Status is omitted, since every campaign in this tab is already known to be "Scheduled")* |
| **Under Review / Rejected** | Simplified set, excluding Performance/Engagement/Code-related columns, since these campaigns haven't gone live yet |

<Note>
  If you don't want the tailored column sets, you can toggle back to a simpler, unified view using the **switch** provided at the top of the table.
</Note>

## Understanding the Data Table Fields

The main table lists your campaigns as rows. Below is an explanation of the fields you may encounter (the exact columns shown depend on your active view/tab — see [Dynamic Columns](#dynamic-columns)):

| Field | Description |
|---|---|
| **Checkbox (row selector)** | Selects an individual campaign for [bulk actions](#bulk-actions). The checkbox in the header selects/deselects all visible campaigns. |
| **Name** | The campaign's name, shown as a clickable link that opens the campaign's detail page. |
| **Channel** | The messaging channel used (e.g., SMS, Email, Push), along with the delivery type in parentheses — for example, "SMS (Event Triggered)" or "SMS (One Time)". |
| **Status** | The current lifecycle state of the campaign (e.g., **Scheduled**, **Sent**, **Active**, **Draft**, **Under Review**, **Rejected**), shown with a status icon. |
| **First Send Date** | The date and time the campaign first sent (or "—" if it hasn't sent yet). An info icon (ⓘ) next to the header provides additional clarification on how this date is calculated. |
| **Performance** | A set of delivery-funnel metrics for the campaign, including: **Impressions**, **Sent**, **Delivered**, **Read**, and **Clicks**. |
| **Engagement** | Rate-based metrics derived from performance data, including: **Read rate**, **CTR** (Click-Through Rate), and **CVR** (Conversion Rate), typically shown as percentages. |
| **Last modified** | Date and time the campaign was last edited, along with the name of the user who made the change (e.g., "07 Jul 2026, 11:11 am by sanjay"). If a campaign has never been modified after creation, this reflects the **creation** date/time instead. An info icon (ⓘ) clarifies this behavior. |
| **Send / Delivery / Open Rate / Conversions** | Optional columns you can add via Dynamic Columns for more granular delivery and engagement detail. |
| **Approved by** | Optional column showing who approved the campaign. See [Campaign Approval Workflow](/user-guide/settings/account/team-management/campaign-approval-workflow#campaign-approval-workflow) for details. |
| **Trigger event name** | Optional column showing the event that triggers the campaign (relevant for event-triggered campaigns). |
| **Custom segment** | Optional column showing the audience segment targeted by the campaign. |
| **Scheduled on / Created on** | Optional date columns, primarily used in the Schedule tab. |
| **Estimated audience count** | Optional column showing the projected number of users the scheduled campaign will reach. |
| **Team** | Visible only in team-based workspaces; shows which team owns the campaign. |

### Default Sorting

Each tab is sorted by a default column relevant to that tab's use case, rather than a single sort order applied everywhere:

| Tab | Default Sort |
|---|---|
| **All** | Last modified |
| **Active** | Last modified |
| **Schedule** | Scheduled on *(so you can see which campaign is going live soonest)* |
| **Under Review** | Scheduled on |

<Note>
  Previously, every tab defaulted to sorting by "Created on," which has been replaced by more context-appropriate sorting, since a mix of campaign states benefits from different sort logic (e.g., knowing what's going live next is more useful than knowing what was created first).
</Note>

## Bulk Actions

Bulk Actions let you perform the same operation on multiple campaigns at once, instead of opening each campaign individually.

### Selecting Campaigns

1. Use the checkboxes on the left of each row to select one or more campaigns.
2. Once at least one campaign is selected, an action bar appears showing **Selected (X/Total)** along with the available actions.
3. Use **Show selected** (toggle) to filter the table down to only the campaigns you've currently selected — useful for reviewing your selection before running an action.
4. Use **Clear selection** to deselect all campaigns and reset the action bar.

### Available Bulk Actions

| Action | Description |
|---|---|
| **Tag** | Apply one or more tags to all selected campaigns at once. |
| **Download** | Downloads a CSV file containing the columns currently visible on your screen, for the selected campaigns. This is a quick export of only the on-screen data. |
| **Report** | Navigates you to the Reports page with the selected campaigns and their channels pre-loaded — no need to reselect campaigns. Reports include a much more detailed set of columns than Download, such as content and delivery-funnel details. |
| **Archive** | Archives all eligible selected campaigns. Campaigns not eligible for archiving are skipped. |
| **Pause** | Pauses all eligible selected campaigns (e.g., active campaigns). If some selected campaigns can't be paused (for example, they're already sent), only the eligible ones are paused, and you're shown how many will be affected before confirming (e.g., "3 of 6 campaigns can be paused"). |
| **Stop** | Stops all eligible selected campaigns, following the same eligibility logic as Pause. |
| **Resume** | Resumes previously paused campaigns, where eligible. |

### Tab-Dependent Availability

The set of actions available changes depending on which tab (view) you're in, since not every action makes sense for every campaign state. For example:

- In the **Schedule** tab, **Resume** is not available (a scheduled campaign hasn't started yet, so there's nothing to resume).
- **Report** is only meaningful once a campaign has gone live, since reporting data doesn't exist for campaigns that haven't sent.

**Difference between Download and Report:**
- **Download** gives you the basic set of columns you already see on the UI, in CSV format.
- **Report** gives you a full, detailed report — including content and delivery-funnel information — for the selected campaigns and channels.
