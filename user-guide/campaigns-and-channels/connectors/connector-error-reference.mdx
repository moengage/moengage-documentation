A Connector request can fail after a campaign qualifies a user. This article explains the most common failure scenarios, what causes them, and how to resolve or prevent them.

For more information about Connector campaign performance, refer to [Connector Campaign Analytics](/user-guide/campaigns-and-channels/connectors/analyze/connector-campaign-analytics).

## Timeouts and Retry Logic

MoEngage waits up to 5 seconds for a Connector endpoint to respond. A request is marked as failed if the endpoint:

- Does not respond within 5 seconds
- Returns any status code other than "200", including "202 Accepted"

<Info>
  Automatic retry is available for Connector requests in some workspaces. When enabled, MoEngage retries a failed request up to 3 times, with a fixed 5-second interval between attempts. Contact MoEngage Support to check whether automatic retry is enabled for your workspace.

  Automatic retry is different from the **Reattempt error codes** setting for OAuth-authenticated Connectors. For more information, refer to [OAuth Errors and Resolution](#oauth-errors-and-resolution).
</Info>

If your endpoint takes longer than 5 seconds to respond, optimize its response time, or configure it to acknowledge the request immediately and process it asynchronously.

## Hostname Validation

MoEngage validates the **Webhook URL**'s hostname when you create or test-send a Connector campaign. It does not validate the hostname for every scheduled send.

The request is rejected with "Provided hostname is not valid" (HTTP "400") if the hostname:

- Does not resolve to a valid address
- Resolves to a private or reserved IP range
- Points to a cloud metadata endpoint

All three conditions return the same error message.

<Info>
  MoEngage verifies the endpoint's TLS certificate by default. If requests fail because your endpoint uses a self-signed or non-standard certificate, contact MoEngage Support.
</Info>

## OAuth Errors and Resolution

For Connector campaigns that use OAuth 2.0 authentication, errors can occur in two different ways:

- If your endpoint returns an error code configured in the **Reattempt error codes** field, MoEngage refreshes the OAuth access token and retries the request once. For more information, refer to [Enable Authorization Settings](/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign#enable-authorization-settings).
- MoEngage can also return a generic "500" error when its own OAuth token-fetch step fails. This is different from an error returned by your endpoint and is not affected by the **Reattempt error codes** setting. If you encounter this error, retry the test send. If it persists, contact MoEngage Support.

## Batch Rerun and Duplicate Prevention

<Info>
  Applies to One Time and Periodic Connector campaigns.
</Info>

MoEngage may automatically rerun a Connector campaign batch because of infrastructure or network issues. If you do not configure a dedup key, a rerun can send the same request to a user more than once.

To prevent duplicate sends, configure **Remove duplicate users** using a stable user attribute as the dedup key, such as a standardized mobile number. For more information, refer to [Remove Duplicate Users](/user-guide/campaigns-and-channels/connectors/create/create-a-connector-campaign#remove-duplicate-users).
