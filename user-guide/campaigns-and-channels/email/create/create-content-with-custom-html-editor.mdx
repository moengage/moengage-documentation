# Edit/Paste HTML Template

You can craft email content using the HTML editor. The side-by-side view of the editor helps you visualize the impact of any changes made to the HTML code, regardless of its complexity.

With HTML editor, you can perform the following actions:

## Add HTML Code

<Info>
  If you have turned on the **Auto-format HTML code** toggle in the [Email settings](https://moengage-user-guide.mintlify.app/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-email-channel#general-settings-tab), Custom HTML editor of MoEngage performs some actions in the HTML templates. This offers a significant advantage through automatic HTML cleanup, ensuring semantic correctness and reliable rendering across browsers. For more information on these actions, refer to [Automatic Edits MoEngage Performs on an HTML Template](/user-guide/campaigns-and-channels/email/faqs-email/what-are-the-auto-formats-moengage-performs-on-an-html-template-added-in-the-moengage-email-editor-custom-html-editor).
</Info>

You can add an HTML code that you have prepared previously or create it with the editor. The editor supports the following editor tools to create HTML code:

- _Text editor and formatting_. This basic text editor tool allows you to type or modify the HTML code directly.
- _Table editor._ This editor allows you to easily create and customize HTML tables by specifying the number of rows and columns.
- _Hyperlink insertion._ The editor typically includes a tool for inserting hyperlinks. You can specify the URL, link text, and target window option.
- _Image editor._ This editor allows you to insert and manage images in your HTML code.
- _Undo/Redo._ Undo and redo buttons are available to easily revert or reapply changes to your HTML code. <img src="/images/moengage_614ea2.png" alt="side by side.png" />

## Add Dynamic Content

You can personalize your email content with attributes. Link and image personalisation is available in the HTML editor. You can save an HTML code as a template in the template library under **My saved templates** and use it later in your campaigns. Click **Save template** under **Template actions** to save your template.

# Upload an HTML Template in ZIP Format

You can craft your email content by uploading a ZIP file (containing an HTML file and images). MoEngage converts this ZIP file and displays your design in the Custom HTML Editor. You can then make further changes or [personalize the message](/user-guide/campaigns-and-channels/email/create/personalize-email-content).

## ZIP File Format

To upload a ZIP file, make sure to follow the specifications below:

- Limit your file size to 5 MB.
- The file name should not contain any special characters (such as  \*, / , , & ,~, ").
- The ZIP file should contain only one HTML file with inlined CSS. If you see an error regarding the file name, ensure that there is only one HTML file.
- Make sure the images are in the JPG, JPEG, PNG, or GIF formats.
- All images should be located on the relative path mentioned in HTML (with case sensitivity). If you encounter an error regarding the image location, ensure that all images are placed in the correct folders inside the ZIP.

## Steps to Upload an Email Template in ZIP Format

1. Log in to the MoEngage dashboard.
2. On the **All campaigns** page, click **\+ Create campaign** \> **Email**\> the required delivery type.
3. Define all the required details in Step 1 "Target users" and click **Next**.
4. In Step 2 "Content", click the **Custom HTML editor** tab.
5. Select **Upload HTML template in Zip format** as shown below.

# Known Limitations

The Custom HTML Editor renders the HTML/CSS you provide, but final rendering also depends on the recipient's email client — several of which (Outlook in particular) use limited, non-standard rendering engines. Review the limitations below before building complex templates to avoid surprises at send time.

## Unsupported or Partially Supported CSS Properties

| CSS Property | Support | Use Instead |
|---|---|---|
| `position: absolute` / `relative` / `fixed` | Not supported in Outlook (Word rendering engine); inconsistent elsewhere | Table-based layout with cell alignment |
| `float` | Not supported in Outlook | Tables with `align` attribute |
| `display: flex` / `grid` | Not supported in Outlook, Yahoo, and several mobile clients | Nested HTML tables |
| `z-index` | Not supported in Outlook | Reorder HTML elements instead of layering |
| `box-shadow` | Not supported in Outlook | Use a background image to simulate shadow, or omit |
| `background-size` / CSS gradients | Not supported in Outlook | Use a static background image sized to the container |
| `@font-face` (custom web fonts) | Not supported in Outlook, Gmail app; falls back to system font | Define a web-safe fallback font stack |
| CSS animations / transitions | Not supported in Outlook, Gmail, Yahoo | Use static content or an animated GIF |
| `max-width` on non-image elements | Inconsistent in Outlook | Set explicit `width` on tables/cells |
| Negative margins | Can break layout in Outlook | Avoid; use padding on parent element instead |

<Info>
  These are email-client rendering limitations, not MoEngage editor restrictions — the HTML editor will accept and save this CSS without an error, but the property may be silently ignored or rendered incorrectly on send, especially in Outlook.
</Info>

## Nested Tables and Outlook Compatibility

Outlook (desktop, 2007 onward) uses Microsoft Word's rendering engine rather than a browser engine. This causes specific issues with nested tables:

- Deeply nested tables (3+ levels) can render with unexpected spacing, misaligned columns, or collapsed layouts.
- Cell padding and spacing set via CSS (`padding`, `border-spacing`) may be ignored — use the HTML `cellpadding` and `cellspacing` attributes directly on the `<table>` tag instead.
- Percentage-based widths on nested tables can render inconsistently — use fixed pixel widths for nested tables where precise layout matters.
- Line-height and font rendering inside nested tables can differ from the outer table — explicitly set `font-family`, `font-size`, and `line-height` on each nested table's cells rather than relying on inheritance.

**Recommendation:** Keep nesting to a maximum of 2 levels where possible, and always validate the rendered output specifically in Outlook before sending.

## Test Before You Send

Because the builder preview reflects browser-based rendering, it does not guarantee how the email will appear across all clients. Before sending any template with custom CSS, nested tables, or advanced layout:

- [ ] Test in Outlook desktop (2016, 2019, 365) — most restrictive rendering engine
- [ ] Test in Gmail (web and mobile app)
- [ ] Test in Apple Mail (macOS and iOS)
- [ ] Test in Yahoo Mail
- [ ] Test on both desktop and mobile screen widths
- [ ] Confirm fallback fonts render acceptably if using custom fonts
- [ ] Use MoEngage's [Test Campaign](/user-guide/campaigns-and-channels/email/getting-started-with-email/test-email-campaign) feature to send test emails to real inboxes across these clients before scheduling

## Cross-Client Preview Tools

For a comprehensive rendering check across 90+ email clients and devices without manually testing each one, use a third-party pre-send testing tool such as [Litmus](https://www.litmus.com/) or [Email on Acid](https://www.emailonacid.com/). Paste your HTML into either tool to get client-by-client screenshots and CSS support warnings before sending your campaign in MoEngage.
