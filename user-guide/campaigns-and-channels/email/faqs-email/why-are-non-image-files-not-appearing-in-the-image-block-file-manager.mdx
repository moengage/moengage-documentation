---
title: "Why Are Non-Image Files Not Appearing in the Image Block File Manager?"
description: "Understand why PDFs and other non-image files uploaded via the email editor's Image content block don't appear, and how to get a public URL for them instead."
---

## Problem

The email editor's Image content block only accepts image files. When you try to upload a non-image file (e.g. `.pdf`) through the file manager opened from an Image block, no error is shown — the upload appears to succeed: a public URL is generated and the folder's file count increments — but the file does not actually appear in the file manager.

<Note>
  For a related case where the editor throws an explicit error instead of failing silently, see [Why Does Uploading .mp4 Files Fail?](/user-guide/campaigns-and-channels/email/faqs-email/why-does-uploading-mp4-files-fail)
</Note>

## Solution

The Image content block's file manager only accepts image files because of the third-party BEE editor's built-in filtering. If you need a public URL for a non-image file (e.g. a PDF to use elsewhere, such as in an in-app campaign), use the **Link File** / **Insert-Edit Link** action on a text element or button instead of the Image block — this file manager entry point isn't filtered, so the file uploads successfully and a public URL is generated.

Refer to [BEE's documentation on uploading a PDF and linking to it](https://support.beefree.io/hc/en-us/articles/360004494892--How-can-I-upload-a-pdf-and-insert-a-link-to-it-to-my-design) for more details.

<Warning>
  The Image content block's file manager only accepts image files. MoEngage does not support uploading video, PDF, or other non-image files through this block — even if the file manager appears to accept the upload.
</Warning>
