Use this reference to diagnose the errors shown in a push campaign's failure breakdown. Errors are grouped by platform. For end-to-end setup, see [Configure Mobile Push](/user-guide/campaigns-and-channels/mobile-push/getting-started-with-mobile-push/configure-mobile-push).

## iOS (APNs) Errors

| Error | Cause | Resolution |
| --- | --- | --- |
| **BadDeviceToken** | The build environment doesn't match the dashboard or certificate — for example, a Debug build sent from the Live dashboard, or a Release build tested from the Test dashboard. | Debug builds: use a Developer certificate with the Test dashboard. Release builds: use a Production or AdHoc certificate with the Live dashboard. |
| **TopicDisallowed** | The Bundle Identifier tied to the AuthKey (`.p8`) in Push settings doesn't match the app's Bundle Identifier. | Align the AuthKey's Bundle Identifier with the app's Bundle Identifier (development team). |
| **DeviceTokenNotForTopic** | The PEM or AuthKey (`.p8`) was uploaded with the wrong Bundle Identifier. | Re-upload the PEM/AuthKey with the correct Bundle Identifier. |
| **InvalidProviderToken** | The wrong Team ID or Key ID was provided for the AuthKey, or the AuthKey was revoked in the Apple Developer account. | Verify the Team ID and Key ID, then upload a valid AuthKey. |
| **APNS Client Connection** | The APNs certificate (PEM) or AuthKey has expired or been revoked. | Create a new PEM file or AuthKey and upload it to the dashboard. |
| **No Active Device Present for the User** | Push isn't configured in your workspace. | Configure at **Settings > Channels > Push > App push > iOS (APNS)**, then log out and back in. Delivery may take up to 30 minutes to start. |

## Android (FCM) Errors

| Error | Cause | Resolution |
| --- | --- | --- |
| **RequestedEntityWasNotFound** (NotRegistered) | The FCM token is no longer registered — usually because the app was uninstalled. | Treat it as a NotRegistered token: refresh tokens, and delete or update any unused tokens. |
| **INVALID_SERVER_CREDS** | The sender ID and server key belong to different FCM projects, or the wrong key was added. | Use a matching sender ID and server key. Upload the private key (`ServiceKey.json`) whose `project_id` matches your Firebase Project ID. |
| **MismatchSenderId** | Conflict between the private key on the dashboard and the `google-services.json` in the app (different projects, or mismatched package name). | Use the private key and `google-services.json` from the same Firebase project, and confirm the Project ID and package name match. |
| **Google Authentication Error** | The server key isn't valid — typically a legacy GCM key still used after the FCM migration. | Copy the current Server key from **Firebase Console > Project Settings > Cloud Messaging** and update it at **Settings > Channels > Push Settings > Mobile Push**. |
