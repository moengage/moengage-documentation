Use landing pages to build a preference center—a page where your users choose which email categories they want to receive. From the page, a user can:

- Subscribe to or unsubscribe from individual categories.
- Unsubscribe from all your email communication.

MoEngage stores these choices against the user's profile natively, so your future email campaigns are sent according to each user's preferences.

This page covers building the preference center in the drag-and-drop editor. For a fully custom HTML landing page, use the [JavaScript bridge methods](#use-a-fully-custom-html-landing-page) instead.

<Info>
  **Prerequisites**

  - Access to the _Landing Pages_ feature. If you don't have it, contact your MoEngage Customer Success Manager (CSM) or the Support team.
  - Subscription categories and groups configured for email. The landing page reads the categories and groups you have already defined. To set them up, see [Configure Subscription Categories](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories).
</Info>

# How It Works

## What You Build

In the landing page editor, you build the preference center using either the [Subscription Categories element](#use-the-subscription-categories-element) or a [custom form](#build-a-custom-form-mapped-to-categories) mapped to your categories, and then publish it. MoEngage connects the page directly to the email subscription categories you configured in settings.

## What Your Users See

When a user opens the page, it shows their current preferences with the categories they are subscribed to already selected. The user changes their selections and saves, and MoEngage stores the updates on their profile so that future email campaigns respect them.

<Info>
  For MoEngage to fetch and save a user's preferences, it must be able to identify the user (resolve their MoEngage ID). This is resolved automatically when the preference center link is delivered through a MoEngage channel, such as an email campaign. If the page is opened without this context, MoEngage can't identify the user, so it can't prefill or save preferences.
</Info>

You can build the preference center in two ways:

| Approach | When to use it |
| --- | --- |
| [Subscription Categories element](#use-the-subscription-categories-element) | You want to show all of your configured categories and groups. This is the most common use case and requires the least setup. |
| [Custom form mapped to categories](#build-a-custom-form-mapped-to-categories) | You want to collect preferences for only specific categories, or design the fields yourself. |

# Use the Subscription Categories Element

The **Subscription Categories** element pulls in every subscription category and group you have configured for email, so you don't have to recreate them on the page.

1. In the landing page editor, open the elements panel and scroll to the **Custom** section.

<img alt="Subscription Categories element highlighted in the Custom section of the landing page editor's Add Elements panel." src="/images/lp-subscription-categories-element.png" />

2. Drag the **Subscription Categories** element onto the canvas. All your configured categories appear automatically, each with its display name, description, and a checkbox.

You can't remove individual categories from the element—to change which categories exist, edit them in [Configure Subscription Categories](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories).

## Configure the Element

Select the element to open its settings. The settings have two tabs: **Subscription Categories** and **Styling**.

On the **Subscription Categories** tab, configure the content and appearance:

| Setting | Description |
| --- | --- |
| Preference layout | Choose how the categories are laid out. |
| Show category description | Show or hide the description under each category. |
| Button text | The label for the save button. The default is _Update Preferences_. |
| Unsubscribe all description | The description shown for the built-in _Unsubscribe from all_ option. |
| Background color | The background color of the element. |
| Button background color | The background color of the save button. |
| Button text color | The text color of the save button. |
| Button hover color | The button background color on hover. |

On the **Styling** tab, apply the [common styling options](/user-guide/content/landing-pages/create/landing-page-editor#common-styling-options-for-elements) such as showing the element on desktop, padding, and margins.

# Build a Custom Form Mapped to Categories

If you want to collect preferences for only specific categories—rather than showing the full list—build the fields yourself with the **Form** element and map each field to a subscription category.

1. In the elements panel, under **Essentials**, drag a **Form** element onto the canvas.

<img alt="Form element listed under the Essentials section of the landing page editor's Add Elements panel." src="/images/lp-form-element-essentials.png" />

2. Select a field in the form to open the field editor. On the **Field** tab, set the **Type** to **Radio** or **Checkbox**. These are the only two field types you can map to a subscription category.

<img alt="Field editor Type dropdown showing Radio and Checkbox options for a form field." src="/images/lp-form-field-type.png" />

3. Add a label for the field—for example, _Promotions_—and give it a single option, such as _Opt-in for Promotions_.

<img alt="Custom form with Promotions and Marketing labels, each with a single opt-in option." src="/images/lp-form-custom-labels.png" />

4. Select the field, open the field editor's **Advanced** tab, and in the **Subscription categories** list, select the category to map the field to.

<img alt="Mapping a radio field to a subscription category using the Subscription categories dropdown on the field editor's Advanced tab." src="/images/lp-form-advanced-subscription-categories.gif" />

When the user submits the form, MoEngage sets each mapped category based on the input:

- **Selected** (checked, or any value entered) sets the subscription to `true`.
- **Not selected** (unchecked, or left blank) sets the subscription to `false`.

<Warning>
  A custom form maps preferences correctly only when each label has exactly one option mapped to one category. Follow these rules:

  - **One option per label.** Use a single checkbox or radio option under each label, mapped to a single subscription category.
  - **Don't add multiple options under one label mapped to the same category.** If more than one option maps to the same category, the category is set to `true` whenever any option is selected, which produces an incorrect preference.
  - **Free-text inputs are treated as a boolean.** If a mapped text field is left blank, the category is set to `false`; if the user enters any value, it is set to `true`.
</Warning>

# Publish and Share the Preference Center

After you finish building the page, publish it and deliver it to your users so they can manage their preferences.

1. Publish your landing page and copy its URL.
2. Deliver the page through a MoEngage channel—for preference management, this is typically an [email campaign](/user-guide/campaigns-and-channels/email/create/create-an-email-campaign). For example, add the URL as the manage-preferences link in your email. Delivering through a channel lets MoEngage identify each user and personalize the page for them.

When a user opens the delivered page, they see their current preferences with their subscribed categories already selected. They change their selections and click the save button (by default, **Update Preferences**), and MoEngage updates the subscription categories on their profile.

# Use a Fully Custom HTML Landing Page

If you host a fully custom HTML landing page instead of building it in the drag-and-drop editor, use the MoEngage JavaScript bridge to read and write subscription categories:

- `Moengage.getEmailSubscription()` fetches the user's current preferences so you can pre-fill the form.
- `Moengage.updateEmailSubscription(<subscription_object>)` writes the user's updated preferences back to MoEngage.

```javascript JavaScript
Moengage.updateEmailSubscription({
  is_globally_unsubscribed: false,
  categories: {
    "New_Product_Launches": true,
    "Price_drop_alerts": false
  }
});
```

For the full method reference, argument shapes, and examples, see [JavaScript Bridge for On-Site Messaging and Landing Pages](/developer-guide/components-for-sdk/javascript-bridge/javascript-bridge-for-on-site-messaging-and-landing-pages#email-subscription-preferences).
