Use landing pages to build a preference center where users choose which email categories they want to receive. The landing page reads a user's current subscription categories, pre-fills their choices, and writes updates back to their MoEngage profile natively—so you no longer need a connector campaign to sync preferences.

This page covers building the preference center in the drag-and-drop editor. For a fully custom HTML landing page, use the [JavaScript bridge methods](#use-a-fully-custom-html-landing-page) instead.

<Info>
  **Prerequisites**

  - Access to the _Landing Pages_ feature. If you don't have it, contact your MoEngage Customer Success Manager (CSM) or the Support team.
  - Subscription categories and groups configured for email. The landing page reads the categories and groups you have already defined. To set them up, see [Configure Subscription Categories](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories).
</Info>

# How It Works

When you build a preference center with a landing page, MoEngage connects the page directly to your email subscription categories:

- **On open**, the page fetches the user's current subscription status for each category and pre-selects the ones they are subscribed to.
- **On save**, the page writes the user's choices back to the _Subscription Categories_ on their MoEngage profile.

Both actions require MoEngage to know which user is viewing the page. The page is personalized using the MoEngage ID that is passed when you send the page through a channel—typically email. For more information, see [Personalize and Prefill for a User](#personalize-and-prefill-for-a-user).

You can build the preference center in two ways:

| Approach | When to use it |
| --- | --- |
| [Subscription Preference element](#use-the-subscription-preference-element) | You want to show all of your configured categories and groups. This is the most common use case and requires the least setup. |
| [Custom form mapped to categories](#build-a-custom-form-mapped-to-categories) | You want to collect preferences for only specific categories, or design the fields yourself. |

# Use the Subscription Preference Element

The **Subscription preference** element pulls in every subscription category and group you have configured for email, so you don't have to recreate them on the page.

1. In the landing page editor, open the elements panel and scroll to the **Custom** section.
2. Drag the **Subscription preference** element onto the canvas.

{/* TODO: screenshot SS1/SS2 — Add Elements panel, Custom section, Subscription preference element (with tooltip). */}

3. All your configured categories appear automatically, each with its display name, description, and a checkbox. A built-in **Unsubscribe from all** option is included at the end.

{/* TODO: screenshot SS3 — Subscription preference element on the canvas listing all categories with checkboxes. */}

<Note>
  The element always reflects the categories and groups defined in your email subscription settings. You can't remove individual categories from the element—to change which categories exist, edit them in [Configure Subscription Categories](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories).
</Note>

## Configure the Element

Select the element to open its settings. The settings have two tabs: **Subscription preference** and **Styling**.

On the **Subscription preference** tab, configure the content and appearance:

| Setting | Description |
| --- | --- |
| Preference layout | Choose how the categories are laid out. |
| Show category description | Show or hide the description under each category. |
| Button text | The label for the save button. The default is _Update Preferences_. |
| Unsubscribe all description | The description shown for the built-in _Unsubscribe from all_ option. |
| Background color | The background color of the element. |
| Button background color | The background color of the save button. |
| Button text color | The text color of the save button. |
| Button hover color | The button background color on hover. |

# Build a Custom Form Mapped to Categories

If you want to collect preferences for only specific categories—rather than showing the full list—build the fields yourself with the **Form** element and map each field to a subscription category.

1. In the elements panel, under **Essentials**, drag a **Form** element onto the canvas.

{/* TODO: screenshot SS6 — searching "form" and the Form element under Essentials. */}

2. Select a field in the form to open the field editor. On the **Field** tab, set the **Type** to **Radio** or **Checkbox**.

{/* TODO: screenshot SS7 — field Type dropdown showing Radio and Checkbox. */}

3. Add a label for the field—for example, _Promotions_—and give it a single option, such as _Opt in for promotions_.

{/* TODO: screenshot SS9/SS10 — building the Promotions and Marketing offers labels, each with one option. */}

4. Open the field editor's **Advanced** tab. In the **Subscription categories** list, select the category to map the field to.

{/* TODO: screenshot SS8/SS12 — Advanced tab with the Subscription categories dropdown open, alongside UserAttribute. */}

When the user submits the form, MoEngage sets each mapped category based on the input:

- **Selected** (checked, or any value entered) sets the subscription to `true`.
- **Not selected** (unchecked, or left blank) sets the subscription to `false`.

<Warning>
  A custom form maps preferences correctly only when each label has exactly one option mapped to one category. Follow these rules:

  - **One option per label.** Use a single checkbox or radio option under each label, mapped to a single subscription category.
  - **Don't add multiple options under one label mapped to the same category.** If more than one option maps to the same category, the category is set to `true` whenever any option is selected, which produces an incorrect preference.
  - **Free-text inputs are treated as a boolean.** If a mapped text field is left blank, the category is set to `false`; if the user enters any value, it is set to `true`.
</Warning>

# Personalize and Prefill for a User

The preference center reads and writes preferences against a specific user, so MoEngage needs the user's MoEngage ID. The ID is passed automatically when you deliver the page through a channel.

1. Build and publish your landing page.
2. Send the landing page through a MoEngage channel—for preference management, this is typically an [email campaign](/user-guide/campaigns-and-channels/email/create/create-an-email-campaign). MoEngage passes the user's MoEngage ID with the page.
3. When the user opens the page, MoEngage personalizes it: it fetches the user's current subscription status and pre-selects the categories they are subscribed to.
4. When the user updates their choices and saves, MoEngage stores the values against that user's subscription categories.

<Note>
  If the page is opened without a MoEngage ID—for example, previewed directly rather than delivered through a campaign—MoEngage can't identify the user, so it can't prefill or save preferences.

</Note>

To confirm that updates are saved, check the **Subscription Categories** section of the [user profile](/user-guide/campaigns-and-channels/email/getting-started-with-email/configure-subscription-categories#view-user-preferences).

# Use a Fully Custom HTML Landing Page

If you host a fully custom HTML landing page instead of building it in the drag-and-drop editor, use the MoEngage JavaScript bridge to read and write subscription categories:

- `Moengage.getEmailSubscription()` fetches the user's current preferences so you can pre-fill the form.
- `Moengage.updateEmailSubscription(<subscription_object>)` writes the user's updated preferences back to MoEngage.

```javascript JavaScript
Moengage.updateEmailSubscription({
  is_globally_unsubscribed: false,
  categories: {
    "New_Product_Launches": true,
    "Price_drop_alerts": false
  }
});
```

For the full method reference, argument shapes, and examples, see [JavaScript Bridge for On-Site Messaging and Landing Pages](/developer-guide/components-for-sdk/javascript-bridge/javascript-bridge-for-on-site-messaging-and-landing-pages#email-subscription-preferences).
