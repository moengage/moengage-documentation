Before you use a recommendation in a live campaign, test it. Testing shows you exactly what a real customer would see, so you can catch a zero-result setup, a bad filter, or a mapping issue before it reaches your audience.

Testing works the same way for Basic recommendations, which cover Item Attribute, User Actions, and Catalog Alerts, and for Advanced recommendations, which cover all the AI-powered models.

# Where to Test a Recommendation

You can test a recommendation from two places:

- **While you create it** — the last step of the recommendation setup includes a **Test recommendation** panel.
- **From the Recommendations list** — open any existing recommendation and select **Test recommendation** to open it as a popup.

Both open the same testing experience.

At the top of the panel, MoEngage shows the total eligible audience for the recommendation, for example, "This recommendation is applicable to 3,434 users." This figure is the full qualifying pool, not the result count for any one test.

# Test Modes

MoEngage offers three ways to preview results:

| Mode | What it does |
| --- | --- |
| **By specific user** | Enter an email, mobile number, ID, or MoEngage ID to test recommendations for one exact user. |
| **Random eligible user** | Test users preselected at random from everyone who qualifies for this recommendation, one at a time. |
| **By item** | Enter a product ID to see what MoEngage recommends alongside that specific item. |

## Test by Specific User

To test a recommendation for a specific user, perform the following steps:

1. Select **By specific user**.
2. Select the identifier you want to search by — **ID**, **Email ID**, **Mobile Number**, or **MoEngage ID**.
3. Enter the value for that identifier.
4. Click **Show result**.

These are the same identifier options available in campaign personalization preview, so you can test with whichever ID you already have. You do not need to look up a MoEngage ID first.

<Note>
  If more than one profile matches what you entered, MoEngage shows how many profiles it found and which one it selected for the test, for example, "10 profile(s) found. Selected user with MoEngage ID: 692d3aacfacf07796b36d797." Click **View user** to open that profile and confirm it is the right one before you read the results.
</Note>

![Screenshot to be added: the identifier drop-down list showing ID, Email ID, Mobile Number, and MoEngage ID](/images/recommendations-screenshot-placeholder.png)

## Test with a Random Eligible User

To test a recommendation with a random eligible user, perform the following steps:

1. Select **Random eligible user**.
2. Click **Test for another user** to swap in a different randomly selected eligible user.

MoEngage picks a user at random from everyone who qualifies and shows their MoEngage ID directly, so you do not need to enter anything. Click **View user** to open that person's full profile.

![Screenshot to be added: the Random eligible user mode showing the selected MoEngage ID and the Test for another user option](/images/recommendations-screenshot-placeholder.png)

## Test by Item

To test a recommendation against a specific item, perform the following steps:

1. Select **By item**.
2. Enter a product ID.
3. Click **Show result**.

Testing by item is useful for models keyed off an item rather than a user, such as Similar Items, Frequently Bought Together, and Frequently Viewed Together.

![Screenshot to be added: the By item mode with a product ID entered and the results displayed](/images/recommendations-screenshot-placeholder.png)

# Recommendation Results

The right pane, **Preview of [X] items**, shows what the selected user, item, or random sample would be recommended. In this pane, you can perform the following actions:

- Search within the results by title, ID, or description.
- Switch between grid view and list view.
- Review each item's ID, name, short description, and price, exactly as they would appear in a real campaign.

![Screenshot to be added: the results preview with the search box, the grid and list view toggle, and an item ID highlighted](/images/recommendations-screenshot-placeholder.png)

If any recommended items cannot be matched to your catalog, the preview shows an expandable notice — "Some recommendation items could not be found in the catalog `{{catalog name}}`" — telling you how many are missing and listing the exact missing catalog item IDs.

Check that those IDs exist in an active feed and match the attribute mapped as the item ID. This is the most direct way to catch a catalog or event ID mismatch.

![Screenshot to be added: the expandable notice listing the missing catalog item IDs](/images/recommendations-screenshot-placeholder.png)

# Recommendation Conditions

The left pane, **Recommendation conditions**, lists every filter currently applied to the recommendation, grouped under **User action**, **Exclude user action**, **Item attribute** — each marked AND or OR — and **Sort Recommendation**. Click the arrow next to a group to expand its individual conditions.

Each group and each individual condition has its own checkbox. Select or clear any of them, and the preview on the right updates immediately. To find out why a particular item is missing from the results, turn conditions off one at a time until the item appears.

Click **Reset changes** to revert everything to the saved configuration. This link becomes active only after you change something.

![GIF to be added: selecting and clearing condition checkboxes on the left while the results update on the right](/images/recommendations-screenshot-placeholder.png)

# Apply or Discard Filter Changes

After you finish testing, click **Done**. If you changed any conditions, MoEngage asks whether to apply the configuration to the recommendation and warns that applying replaces the saved configuration.

- Click **Apply filters** to save your test-time changes as the recommendation's new live configuration.
- Click **Don't apply** to close the test view and keep the recommendation exactly as it was saved.

<Warning>
  **Apply filters** overwrites the saved recommendation for everyone, not just for this test. If you are testing to diagnose a problem rather than to make a permanent change, click **Don't apply**.
</Warning>

# Troubleshoot Zero Results

A recommendation can return no results even when it is configured correctly, usually because of timing or a data mismatch. Check the following causes, in order:

1. **The interaction happened before you mapped the event.** MoEngage starts counting an event toward recommendations from the moment you save its user action mapping, and does not backfill anything from before that point. If your test user's only relevant activity predates the mapping, test again with more recent activity.
2. **The item ID in your interaction event does not match any item ID in your catalog.** Check that the attribute mapped as the item ID has identical values in both the event and the catalog feed — same casing, no extra spaces, and the same string or number format. This is the same mismatch the missing-items notice flags for partial results, but when every interacted item is mismatched you get zero results instead of a partial list.
3. **No user action is mapped yet for the model you are testing.** [Map user actions](/user-guide/content/recommendations/getting-started/map-user-actions-settings) before you test a User Actions model or an AI-personalized model.
4. **The test user no longer exists, or has been merged into another profile.** Test with the surviving MoEngage ID instead.
5. **You searched with an identifier type your account has no data for.** Confirm you selected the identifier type that actually has activity for this user.
6. **The catalog used by this recommendation was deleted.** [Reconnect a catalog](/user-guide/content/recommendations/getting-started/catalogs) before you test again.

If none of these explain it, contact [MoEngage Support](https://help.moengage.com/hc/en-us/requests/new) with the recommendation name and the identifier you tested with.
