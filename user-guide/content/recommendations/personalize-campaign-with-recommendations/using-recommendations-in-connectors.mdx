By adding recommendations to your Connector campaigns, you can send each user's recommended items to a third-party system instead of the same payload for everyone. In the Connector channel, recommendations are inserted into the request payload using the [Jinja templating language](/user-guide/campaigns-and-channels/getting-started/message-personalization/jinja-templating-language).

At MoEngage, creating a Connector campaign is a three-step process.

1. Target users
2. Content
3. Schedule and Goals

You can personalize the campaign with recommendations in the second step 'Content'. Let us create a recommendation personalized Connector campaign.

<Warning>
  Ensure that you have created the desired recommendations. You can use only active recommendations for campaign personalization. Learn how to [create and manage recommendations](/user-guide/content/recommendations).
</Warning>

<Note>
  A Connector campaign calls an API rather than delivering a message, so it has no **Personalized preview**. To confirm your personalization resolves correctly, deliver a test campaign and check the payload the endpoint receives.
</Note>

# Create Connector Campaigns with Recommendations

To create a Connector campaign with recommendations, perform the following steps:

1. On the sidebar menu in MoEngage, hover over the **Engage** menu item <img alt="The Engage menu icon" src="/images/moengage_3a6ded.png" style={{ display: "inline-block", height: "20px", width: "auto" }} />. The **Engage** menu appears.
2. Click **+ New Campaign**.

   ![The New Campaign button on the Engage menu](/images/moengage_f884be.png)
3. On the **New Campaign** dialog box, under **OUTBOUND**, click **Connectors**.
4. Click **Periodic** campaign. You can follow the same steps for any other Connector campaign type. For more information about delivery types, refer to [Delivery Types](/user-guide/campaigns-and-channels/getting-started/introduction/delivery-types-moengage-channels).
5. Enter the basic campaign details, define the audience in step 1 'Target users', and click **Next**.
6. In step 2, on the **Content** tab, configure the endpoint, method, and headers for your connector.
7. In the request body, type **@** where you want the recommendation to appear. The personalization menu opens.
8. On the **Data personalization** tab, click the required set under **Product sets**.
9. Select a fallback option to control what happens when the recommendation is unavailable for a user.
10. Click **Done**.
11. Modify the inserted Jinja code to fetch the items you need, as described in the following section.
12. Deliver a test campaign and check the payload received at your endpoint.
13. Click **Next** at the bottom to move to 'Schedule and Goals', which is step 3 of campaign setup.
14. Set up the appropriate settings in **Schedule and Goals** and publish the campaign.

# Fetch a Single Recommended Item

Adding a product set on its own inserts every item in the set. To send one product instead, loop through the product set. The following example uses a product set named `ProductSet` with a recommendation named `Recommendations`.

To fetch the title of the first recommended item:

<CodeGroup>
```text JINJA
{% if ProductSet.Recommendations %}
{% for product in ProductSet.Recommendations[0:1] %}
{{product.title}}
{% endfor %}
{% else %}
MOE_NOT_SEND
{% endif %}
```
</CodeGroup>

To send the product's link in the same payload:

<CodeGroup>
```text JINJA
{% if ProductSet.Recommendations %}
{% for product in ProductSet.Recommendations[0:1] %}
{{product.link}}
{% endfor %}
{% else %}
MOE_NOT_SEND
{% endif %}
```
</CodeGroup>

`MOE_NOT_SEND` stops the request from going out when the product set is empty for a user, so your endpoint does not receive a payload with a missing product.

A product set contains a list of items, each with attributes such as `name`, `title`, `id`, and `image link`. To fetch an attribute inside the loop, type **@** and select the property from the personalization window.
