---
title: "Why Are Events For Specific Users Missing On The Dashboard?"
---

## Problem

Events for specific users are not reflecting on the MoEngage dashboard, while the rest of the user base is unaffected.

## Explanation

If expected events are missing for only a small set of users, those users may have breached the Fair Usage Policy (FUP) limits.

When a single user ID sends a high volume of requests in a short period and exceeds the MoEngage safety thresholds, MoEngage temporarily blocks tracked data for that user ID to protect platform stability. To prevent this issue, ensure that event tracking stays within both the user-level Fair Usage Policy (FUP) limits and the global application programming interface (API) rate limits.

## User-Level Fair Usage Policy (FUP)

If a specific user breaches any of the following thresholds, tracking for that user is temporarily blocked:

| Time Interval | Maximum Allowed Data Requests | Action Taken Upon Breach |
| --- | --- | --- |
| 1 minute | 100 requests | Blocks tracked data for that user for the next 1 hour. |
| 5 minutes | 300 requests | Blocks tracked data for that user for the next 1 hour. |
| 1 hour | 500 requests | Blocks tracked data for that user for the next 24 hours. |
| 1 day | 1,000 requests | Blocks tracked data for that user for the next 24 hours. |

### Global API-Level Rate Limits

In addition to individual user limits, the overall system integration must maintain the following global API rate limits:

- **Track Events:** Maximum 30,000 events per minute
- **User Updates:** Maximum 10,000 updates per minute

**Note:** For more details, refer to the official MoEngage documentation on [Fair Usage Policy (FUP)](https://www.moengage.com/docs/user-guide/data/key-concepts/fair-usage-policy-fup#fair-usage-policy-fup) and [API Rate Limits.](https://www.moengage.com/docs/api/event/track-event#rate-limit)

## Instructions

Perform the following steps to verify if a user has been blocked due to an FUP violation:

1. In the MoEngage dashboard, go to **Events & filters**.
2. Click the specific event that appears to be missing for the user.\
   \
   **Note:** Ensure the event is active and not blocked globally by checking the Data Management page first.

<Frame>
  ![Data Management](/images/Data-Management.png)
</Frame>

3. In the **Filter Users** section, in the **Filter users by** list, click **ID**, and type the affected user ID (for example, **12345**).

<Frame>
  ![Events And Filters](/images/Events-and-Filters.png)
</Frame>

4. In the **Behavior Options** section, in the **Analysis type** list, click **Total events**.
5. Select the relevant duration covering the period when the events went missing, and click **Apply**.
6. Review the Behavior chart. Hover over the data spikes to view hourly or minute-by-minute breakdowns.

<Frame>
  ![Behaviour Option](/images/Behaviour-option.png)
</Frame>

If the user spike shows a high concentration of requests (such as 535 events in a short window), the user has breached the 500-requests-per-hour limit. This confirms that subsequent events were blocked due to an FUP violation.
