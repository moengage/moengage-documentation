# Overview

Data archival is the systematic process of removing inactive or dormant user data to ensure that your marketing workspace remains lean, focusing exclusively on users who provide genuine engagement opportunities and business value.

MoEngage implements data archival to balance platform performance with global privacy standards:

- **Performance & Data hygiene:** MoEngage maintains a lean and high-performance environment populated exclusively by reachable and marketable users. This high-fidelity dataset ensures faster segmentation query and provides more accurate analytics, as your insights will reflect genuine user intent rather than being skewed by stagnant, non-functional records.
- **Regulatory Compliance (GDPR, CCPA, and India's DPDP Act):** The policy aligns with the GDPR principles of Storage Limitation and Data Minimization. User data should be kept only as long as there is a legitimate business purpose; once a user is no longer reachable or marketable, archiving their data reduces legal liability and protects user privacy. For how this supports India's Digital Personal Data Protection (DPDP) Act, 2023, see [Data Retention and India's DPDP Act, 2023](#data-retention-and-indias-dpdp-act-2023).

<Info>
  **Archival Frequency**

  Every 14 days, MoEngage runs a process to remove inactive and unreachable users, events and devices from MoEngage services. Each entity has a separate archival policy, and upon archival, the data points are deleted permanently.
</Info>

# Archival Criteria

## User Profiles

MoEngage classifies every user profile as **Registered** or **Anonymous** based on whether the profile has an active identifier. This is the same classification used for [Identity Resolution](/user-guide/data/user-data/unified-identity-identity-resolution) and shown elsewhere on your dashboard — archival doesn't apply a separate rule.

1. **Registered Users:** A profile that has at least one active identifier present.
   - In workspaces without Identity Resolution enabled, ID is the only active identifier — a user is Registered if ID is present.
   - In workspaces with Identity Resolution enabled (up to five identifiers can be configured, for example ID, Email ID, Mobile Number), a user is Registered if any one of the active identifiers is present.
   Because these represent known customers with a higher potential for long-term value, MoEngage archives Registered profiles after a longer period of inactivity.
2. **Anonymous Users:** A profile with none of the active identifiers present. To keep your workspace lean and focused on high-intent audiences, MoEngage archives Anonymous profiles after a shorter period of inactivity.

- **Activity:** Any interaction with your app or website (any standard or custom event) is a signal of intent and counts as activity. Sending a user attribute update — through the SDK, a Data API, or a file import — also counts as activity and resets the archival clock. {/* TODO: Confirm with eng whether unsetting an attribute also resets the clock, or only setting/updating one — the source Confluence page only confirms "attribute update" */}
- **Campaign Engagement:** The policy aims to retain users who actively interact with your communications. Interactions such as Opens or Clicks serve as engagement signals. System-generated and internal campaign-processing events (for example, delivery failures or control-group events) don't count as engagement — see the full list below.

Here is the summary of the rules that apply for archival:

| Type                              | User criteria                                                                                                     | Archival criteria                                                                                                                                                                                                                                    |
| :-------------------------------- | :------------------------------------------------------------------------------------------------------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Registered (Identified) users** | Users with at least one active identifier present (ID, or, in workspaces with Identity Resolution enabled, any configured identifier). | **Activity:** <ul><li>No custom or standard event, and no user attribute update, in the last DRP window (default 365 days)</li></ul> **Campaign engagement:** <ul><li>User interacted with no campaigns for the last DRP window (default 365 days)</li></ul> |
| **Anonymous (Guest) users**       | Users with none of the active identifiers present.                                                                  | **Activity:** <ul><li>Last seen is > 60 days</li><li>MoEngage did not track any custom or standard event for the last 60 days</li></ul> **Campaign engagement:** <ul><li>User interacted with no campaigns for the last 60 days</li></ul>            |

<Info>
  **Data Retention Policy (DRP)**

  Registered user profile retention is governed by your workspace's DRP — the same setting that governs event retention (see [Events](#events)). The default DRP is 365 days.

  Some workspaces have a custom DRP value for Registered user profile retention configured on request. To request a custom value, contact your MoEngage Customer Success Manager (CSM) or the Support team; changes are rolled out after review. {/* TODO: existing custom-override workspaces are slated to eventually move to a single standard DRP — confirm with PM whether/when to communicate this deprecation to customers, or keep this page silent on it until closer to the date. */}

  Anonymous user retention is fixed at 60 days and isn't covered by DRP.
</Info>

<Note>
  **Profile-based and hybrid pricing**

  If your workspace is on profile-based or hybrid pricing, MoEngage retains both Registered and Anonymous user profiles for 10 years. {/* TODO: confirm the customer-facing name for "profile-based/hybrid pricing" matches billing/contract terminology used elsewhere in docs or on the pricing page. */}

## Events

By default, events remain available for 60 days. This determines how far back you can look to analyse user behaviour, for example, "Users who purchased in the last 2 months".

The event retention period (also referred to as Data Retention Policy (DRP)) is extendable on a request basis. Contact your dedicated MoEngage Customer Success Manager or the Support team. This DRP setting also governs Registered user profile retention (see [User Profiles](#user-profiles)). It has no impact on device retention or Anonymous user profile retention, which continue to follow their own fixed windows.

<Info>
  1. The archival process runs periodically, so the actual archival period may be slightly higher (+14 days) than the mentioned number of days.
  2. The archival policy can be customised. For further assistance, contact your MoEngage Customer Success Manager (CSM) or the Support team.
  3. MoEngage allows ingestion of data beyond the Data Retention Policy (DRP), but the Segmentation service allows you to query the data only based on your DRP. The Data Storage services delete data beyond DRP periodically.
</Info>

## Devices

MoEngage archives devices that have been inactive for 60 days. Removing the inactive and unreachable devices ensures that your Push campaigns are processed faster and directed only at active devices.

# Data Retention and India's DPDP Act, 2023

India's Digital Personal Data Protection (DPDP) Act, 2023, sets guidelines for how the personal data of individuals in India is collected, processed, and retained. MoEngage provides APIs and controls that help you respond when your end users in India exercise their rights under the Act.

- **Retention:** MoEngage retains personal data only for as long as necessary to fulfill the purpose it was collected for. The archival policy described on this page supports this by automatically removing inactive user profiles, events, and devices from the platform.
- **Erasure requests:** When an end user asks you to delete their data, use the [GDPR/CCPA data request API](/api/gdpr/submit-a-gdpr-ccpa-data-request) to remove all personal data associated with that user from MoEngage.

For MoEngage's complete legal data-retention terms and the rights available to Indian data principals, including the grievance and Data Protection Officer contact, refer to the **Additional Information for Indian Residents** and **Data Retention** sections of the [MoEngage Privacy Policy](https://www.moengage.com/privacy-policy/).

# FAQs

<Accordion title="If an archived user comes back to the platform, does MoEngage retain the user consent and subscription status?">
  No. Once a user is archived, MoEngage removes that user from all MoEngage services. If the user returns, MoEngage treats them as a new user, and none of the earlier attributes are retained, including consent and subscription status.
</Accordion>

<Accordion title="Does updating a user attribute reset the archival clock?">
  Yes. Sending a user attribute update — through the SDK, a Data API, or a file import — counts as activity, the same as a standard or custom event, and resets the archival clock.
</Accordion>

<Accordion title="Does MoEngage check reachability (for example, valid email or mobile number) before archiving a user?">
  No. Archival is based only on inactivity — how long since the user's last event, attribute update, or campaign interaction. MoEngage does not check whether a user's contact details are valid or reachable.
</Accordion>
