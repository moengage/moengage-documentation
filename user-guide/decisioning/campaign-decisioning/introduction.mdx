# Overview

AI Campaign Decisioning, powered by Aampe, chooses the best message copy for each individual user within the Push campaigns you already build. You write several complete versions of a notification, MoEngage labels each version by what it says, and a Campaign Decisioning Policy selects the version most likely to achieve your goal for each user.

This reduces the need for manual A/B testing when you want the system to choose the best message variation for each user. Instead of picking one winning message for an entire audience, the system decides message-by-message, user-by-user, using the campaign workflow you already know.

<Note>
AI Campaign Decisioning is designed for scenarios where you have multiple message options and want the AI to select the best one per user. For single, ad-hoc broadcast announcements, Standard campaign delivery is simpler and equally effective.
</Note>

# Why Use AI Campaign Decisioning

- **Scale**: Manually optimizing campaigns for millions of users is impractical. Decisioning scales personalization with your user base.
- **Attention**: User attention is finite, and irrelevant messages cause fatigue. Decisioning helps you avoid "spray and pray" sending.
- **Efficiency**: With rising channel costs, decisioning helps you drive more engagement with fewer messages.
- **No manual A/B testing**: The system matches the right creative to each user automatically, instead of picking a single best-for-everyone variant.

# The Five Parts of the System

| Part | What it is |
| --- | --- |
| **Content Labels** | Your content vocabulary. A **Label Category** is a theme (for example, "Message Tone"), and a **Label** is a value within it (for example, "Playful"). See [Content Labels](/user-guide/decisioning/campaign-decisioning/content-labels). |
| **Campaign Decisioning Policy** | The container that governs decisioning — the goal, the reward event, who is eligible, and how many messages a user may receive. See [Create a Campaign Decisioning Policy](/user-guide/decisioning/campaign-decisioning/create-a-campaign-decisioning-policy). |
| **Message variations** | The complete versions of a message you write for one campaign (up to 150 across locales and platforms). |
| **Content Intelligence** | The step that auto-labels each variation and lets you review the labels. See [Content Intelligence](/user-guide/decisioning/campaign-decisioning/content-intelligence). |
| **Decisioning and guardrails** | At send time, the system picks the best variation per user, then the policy's send limits and your global frequency cap decide whether the message is sent. |

# How a Marketer Uses It

Set up your Content Labels and create a Campaign Decisioning Policy once. Then, for each campaign, add your message variations, auto-label them with Content Intelligence, schedule at a fixed time, send, and review the results. For details, see [Create a Campaign with AI Campaign Decisioning](/user-guide/decisioning/campaign-decisioning/create-a-campaign-with-campaign-decisioning).

# Measuring Impact

To measure lift, MoEngage assigns every user a persistent random bucket from 0 to 99 (the **Random User Bucket**, internal name `moe_rub`). You use this attribute in the segment builder to split users into treatment and control groups and compare engagement, conversion, and retention.

- The value is assigned once, uniformly at random, and does not change unless the user is deleted and recreated.
- It is read-only and cannot be overwritten from the dashboard or a CSV import.
- It is workspace-scoped, so the same user can have different buckets across workspaces.

Policy performance is also reported directly in the dashboard. See [Campaign Decisioning Policy Analytics](/user-guide/decisioning/campaign-decisioning/campaign-decisioning-policy-analytics).

# What's Not Supported

- AI-driven send timing (you set the send time manually).
- Email and SMS channels.
- Flows and Inform.
- Multi-level label hierarchies.
- Auto-generating a taxonomy from your business context.
