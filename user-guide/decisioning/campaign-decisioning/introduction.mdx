AI Campaign Decisioning, powered by Aampe, helps you select the best Push message copy for each end user.

Instead of sending the same message to everyone or running manual A/B tests, you create multiple complete message variations within a single campaign. MoEngage labels each variation based on its content, and the Campaign Decisioning Policy selects the variation most likely to achieve your goal for each end user.

<Note>
**Early Access**

AI Campaign Decisioning is available only for Push. To enable it for your workspace, contact your MoEngage Customer Success Manager (CSM) or the Support team.
</Note>

# Key Components

AI Campaign Decisioning includes the following components:

| Component | Description |
| --- | --- |
| Content Labels | Your content vocabulary. A Label Category defines a theme, and a Label is a value within that category. |
| Label Category | A category that groups labels under one theme, such as Message Tone. |
| Campaign Decisioning Policy | The setup that controls decisioning, including the goal, reward event, eligibility, and send limits. |
| Message Variations | The complete message versions you create within a single campaign, with up to 150 variations across locales and platforms. |
| Content Intelligence | Automatically labels each message variation and allows you to review the assigned labels. |
| Decisioning and Guardrails | At send time, MoEngage selects the best variation for each end user. The policy send limits and the global frequency cap then determine whether the message is sent. |

# Measuring Impact

To measure lift, MoEngage assigns every end user a persistent random bucket from 0 to 99. This attribute is called the Random User Bucket, with the internal name `moe_rub`.

You can use this attribute in the Segment Builder to split end users into treatment and control groups and compare engagement, conversion, and retention.

The Random User Bucket has the following characteristics:

- The value is assigned once, uniformly at random, and does not change unless the end user is deleted and recreated.
- The attribute is read-only.
- You cannot overwrite it from the dashboard or through CSV import.
- The attribute is workspace-scoped, so the same end user can have different bucket values across workspaces.

# Filter Events by Label in the Segment Builder

- Every event in the campaign analytics section, for example, Notification Clicked iOS and Notification Clicked Android, and every billable standard event includes one additional parameter: **Labels**.
- The **Labels** parameter is stored as an array.
- In the Segment Builder, you can filter events using the **Labels** parameter, for example, users who performed Email Opened with label X.

This helps you trace performance back to the labels driving it.

# Limitations

AI Campaign Decisioning currently supports only the Push channel. The following are not supported:

- Flows and Inform
- Multi-level label hierarchies
- Auto-generating a taxonomy based on your business context
