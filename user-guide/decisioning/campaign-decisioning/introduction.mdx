AI Campaign Decisioning, powered by Aampe, helps you select the best Push message copy for each end user.

Instead of sending the same message to everyone or running manual A/B tests, you create multiple complete message variations in one campaign. MoEngage labels each variation based on its content, and a Campaign Decisioning Policy selects the variation most likely to achieve your goal for each end user.

Use AI Campaign Decisioning when you have multiple message options and want MoEngage to select the best one for each end user. For a single, ad hoc broadcast announcement, Standard campaign delivery is simpler and equally effective.

<Note>
**Early Access**

AI Campaign Decisioning is available only for Push. To enable it for your workspace, contact your MoEngage Customer Success Manager (CSM) or the Support team.
</Note>

# Benefits

AI Campaign Decisioning helps you:

- Personalize messages at scale.
- Reduce irrelevant messaging and end-user fatigue.
- Improve efficiency when channel costs increase.
- Avoid manual A/B testing by automatically selecting the best variation for each end user.

# Components

AI Campaign Decisioning includes the following components:

| Component | Description |
| --- | --- |
| Content Labels | Your content vocabulary. A Label Category is a theme, and a Label is a value within that category. |
| Campaign Decisioning Policy | The setup that governs decisioning, including the goal, reward event, eligibility, and send limits. |
| Message Variations | The complete message versions that you create in one campaign, up to 150 across locales and platforms. |
| Content Intelligence | The step that auto-labels each variation and lets you review the labels. |
| Decisioning and Guardrails | At send time, MoEngage selects the best variation for each end user. The policy send limits and the global frequency cap then determine whether the message is sent. |

# Measuring Impact

To measure lift, MoEngage assigns every end user a persistent random bucket from 0 to 99. This attribute is called the Random User Bucket, and its internal name is `moe_rub`.

You can use this attribute in the segment builder to split end users into treatment and control groups and compare engagement, conversion, and retention.

The Random User Bucket has the following characteristics:

- The value is assigned once, uniformly at random, and does not change unless the end user is deleted and recreated.
- The attribute is read-only.
- You cannot overwrite it from the dashboard or by CSV import.
- The attribute is workspace-scoped, so the same end user can have different bucket values across workspaces.

# Limitations

AI Campaign Decisioning does not support the following:

- AI-driven send timing.
- Email and SMS channels.
- Flows and Inform.
- Multi-level label hierarchies.
- Auto-generating a taxonomy from your business context.
