Warehouse segments enable you to create segments on MoEngage based on data from your data warehouse without the hassles of copying or moving it to MoEngage.

Let's say that your brand wishes to offer exclusive discounts to loyal shoppers based on an engagement score that is computed with your proprietary logic. This data is stored and accessible only from your data warehouse. With Warehouse segments, you can access this data from the warehouse directly, build an audience on MoEngage, and send a campaign from MoEngage within a few clicks.

Because the data stays in your warehouse, you get access to it without syncing delays, and it remains inside your own security and compliance boundary.

# How to Set One Up

<Steps>
  <Step title="Connect your data warehouse">
    Grant MoEngage read access and save the connection in App Marketplace. Required for both methods below.

    [Connect Your Data Warehouse](/user-guide/segment/create-segments/warehouse-segments/connect-your-warehouse)
  </Step>
  <Step title="Choose how you define the audience">
    Write a SQL query, or build the segment from dropdown filters. See the comparison below.
  </Step>
</Steps>

# Two Ways to Define a Warehouse Segment

Both methods run against your warehouse and produce a custom segment you can target with a campaign.

| | [Using SQL](/user-guide/segment/create-segments/warehouse-segments/create-using-sql) | [Using filters](/user-guide/segment/create-segments/warehouse-segments/create-using-filters) |
| --- | --- | --- |
| Who it is for | Analysts and SQL users | Marketers |
| How you define the audience | A SQL query you write | Dropdown filters on mapped attributes and events |
| Setup needed | Warehouse connection | Warehouse connection, plus your tables mapped in [Warehouse Schemas](/user-guide/segment/create-segments/warehouse-segments/map-your-schema) |
| Warehouses | BigQuery, Snowflake, Databricks, Redshift | BigQuery, Databricks |
| Aggregations and custom SQL logic | Available | Not available |
| Segment type | Warehouse - SQL | Filter - external |

Use filters for everyday audience building, and SQL when your logic needs aggregations or transformations the filter builder does not cover.

<Warning>
  Queries run on your data warehouse directly, so you incur the compute costs your warehouse charges for them. This applies to both methods.
</Warning>
