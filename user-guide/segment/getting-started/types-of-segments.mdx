MoEngage provides several segment types to cover different use cases and data sources. Each type is suited to a particular kind of audience-building scenario.

Use this table to find the segment type that matches your goal, then follow the links for detailed setup steps.

| Segment type | What it is | When to use it |
| --- | --- | --- |
| [File](/user-guide/segment/create-segments/file-segments) | A static list of users uploaded as a CSV file. | You have a fixed, known list of users — for example, a migration list or an export from an offline database. |
| [Rule-based (filter)](/user-guide/segment/create-segments/rule-based-filter-segments) | A dynamic group defined by conditions on user attributes, events, and event attributes. | You want membership to update automatically as user data and behavior change. |
| [Affinity](/user-guide/segment/create-segments/affinity-segments) | A group based on behavioral patterns and preferences, such as how often or how consistently users take an action. | You want to target users by the strength of a behavior — for example, users who book rides at a certain hour at least 40% of the time. |
| [Custom](/user-guide/segment/create-segments/manage-segments) | A saved, named segment query you can reuse across campaigns, flows, and analytics. | You reuse the same audience logic in multiple places, or you combine file, rule-based, and other custom segments. |
| [RFM](/user-guide/segment/create-segments/rfm-segments) | Automatic buckets — such as Loyal, Promising, and At Risk — based on the recency, frequency, and monetary value of transactions. | You want to group users by transaction behavior without building rules manually. |
| [Warehouse](/user-guide/segment/create-segments/warehouse-segments) | An audience built directly from your data warehouse without copying data into MoEngage. Define it with SQL, or with dropdown filters if your warehouse tables are mapped in MoEngage. | Your segmentation depends on scores or data that live only in your warehouse, or you have not integrated the MoEngage SDK yet. |

## File Segment

A file segment is a static list of users uploaded as a CSV file. Use this when you have a fixed list of users that you want to target — for example, users migrated from another platform or a list from an offline database.

[Learn how to create File Segments.](/user-guide/segment/create-segments/file-segments)

## Rule-Based (Filter) Segment

A rule-based segment is defined by conditions applied to user attributes, events, and event attributes. MoEngage evaluates these rules against your data to produce a dynamic group of users. The segment membership updates as user data changes.

[Learn how to create Rule-Based Segments.](/user-guide/segment/create-segments/rule-based-filter-segments)

## Affinity Segment

An affinity segment targets users based on behavioral patterns and preferences within your app — for example, users who predominantly listen to a specific music genre, or users who book rides between certain hours at least 40% of the time.

[Learn how to create Affinity Segments.](/user-guide/segment/create-segments/affinity-segments)

## Custom Segment

A custom segment is a saved and named segment query that can be reused across multiple campaigns, flows, and analytics pages. Custom segments can combine file segments, rule-based segments, and other custom segments.

[Learn how to create and manage Segments.](/user-guide/segment/create-segments/manage-segments) You can also create and count custom segments through an AI assistant using the [MoEngage MCP segmentation tools](/user-guide/ai-and-intelligence/merlin-ai/moengage-mcp-server#segments).

## RFM Segment

RFM (Recency, Frequency, Monetary) segments automatically group users by their transaction behavior — how recently they engaged, how often, and how much they spent. MoEngage generates RFM segments automatically once you configure the model, placing users into buckets such as Loyal, Promising, At Risk, and others.

[Learn how to use RFM Segments.](/user-guide/segment/create-segments/rfm-segments)

## Warehouse Segment

A warehouse segment lets you build an audience directly from your data warehouse — BigQuery, Snowflake, Databricks, or Redshift — without copying data into MoEngage. Use this when your segmentation logic depends on proprietary scores or data that lives exclusively in your warehouse.

There are two ways to define one:

- **SQL editor** — write a query that returns a single column of user IDs. Works on any connected warehouse. [Learn how to create a segment using SQL.](/user-guide/segment/create-segments/warehouse-segments/create-using-sql)
- **Filter builder** — pick attributes and events from dropdowns, as you would for a rule-based segment. Requires your warehouse tables to be [mapped in MoEngage](/user-guide/data/warehouse-schemas) first, and supports BigQuery and Databricks. [Learn how to create a segment using filters.](/user-guide/segment/create-segments/warehouse-segments/create-using-filters)

<Note>
  Warehouse Segments do not require an SDK or API integration with MoEngage. If you have not yet integrated the MoEngage SDK, Warehouse Segments are a way to start creating audiences immediately.
</Note>

## Segment Processing

Segmentation computation timing varies by campaign type.

**One-time and periodic campaigns**: Segment membership is computed at the scheduled execution time, in seconds.

**Event-triggered campaigns**: Segment membership can be defined in three layers:

### Trigger Criteria

This layer qualifies users in real time based on their actions or inaction. You can include use cases like cart abandonment directly in the trigger criteria.

### User Properties

User property evaluation for segment membership in event-triggered campaigns happens in real time.

### Past Behavior Segmentation

#### Real-Time Segment Evaluation

Segments using data within the last 30 days — user attributes, user events, event attributes, and event duration — are evaluated in real time. This is available for Push, Email, SMS, WhatsApp (all event-triggered), In-Apps, On-Site Messaging, Personalize, and Flows.

#### Precomputed Segments

For historical event data beyond 30 days, MoEngage uses precomputed segments. Segment membership is calculated ahead of time (from 30 minutes to a few hours, depending on configuration), giving users a real-time experience at the moment of the event trigger.
