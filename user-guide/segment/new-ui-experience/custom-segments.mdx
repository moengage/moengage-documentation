Custom segments enable you to save user segment queries and provide a name for this query for ease of use. Now this custom segment can be used on multiple pages in the MoEngage dashboard instead of entering the entire query and creating the segment again.

# Create Custom Segment

In MoEngage, custom segments can be created in three ways:

### From the Segment Page

To create a custom segment, perform the following steps:

1. On the sidebar menu in MoEngage, hover over the **Segment** menu item <img alt="Screenshot 2025-06-16 at 3.25.14 PM.png"  src="/images/moengage_d125fa.png"  /> . The **Segment** menu appears.
2. Click **+ New Segment**.  
    <img alt="Screenshot 2025-06-13 at 2.52.15 PM.png"   src="/images/moengage_8fb993.png"   />   
   The **Create segment** page appears.
3. After entering the query and selecting the desired filters, click the **+ Actions** button and select **Create Custom Segment**.  
     
    <img alt="Screenshot 2025-06-17 at 12.35.11 PM.png" src="/images/moengage_c8af99.png" />   
   or  
   In the **Query results** section, for a selected query, you can select **Create Custom Segment**.   
    <img alt="2025-06-17_12-41-11.png" src="/images/moengage_f2fa11.png" />   
   The **Create a custom segment** dialog box appears.
4. In the **Segment name** box, type a name for your custom segment.  
    <img alt="Screenshot 2025-06-17 at 12.37.55 PM.png"  src="/images/moengage_31e7f2.png"  />
5. Click **Create**.

### While Importing Users

Custom segments can be created while importing users. The users in the segment remain fixed and hence this is a static custom segment. Click [here](/user-guide/data/imports/file-based-imports/import-user-data-using-csv) to know more.

### From MoEngage Analytics

Custom segments can also be created from Behaviour analysis, Funnel analysis and RFM Segments. These sections create a dynamic custom segment. [Click here to know more](/user-guide/segment/create-segments/rfm-segments).

# Using Custom Segment

On the MoEngage dashboard custom segments can be used in multiple different ways -

- Custom segments can be utilized to create a complex user segment. A custom segment can be used in creating user segments along with user properties and user activities.
- A custom segment can be used while creating other custom segments, hence complex nesting of custom segments is allowed. A custom segment can have up to 6 levels of recursion/nesting i.e. Custom Segment A definition can include Segment B which in turn can include Segment C, and so on. [File Segments](/user-guide/segment/create-segments/file-segments) are not counted towards the nesting limit.
- While creating/defining a new custom segment, up to 10 existing custom segments can be used in the new custom segment. [File Segments](/user-guide/segment/create-segments/file-segments) are not counted towards this limit.
- Custom Segments can be used to create a target audience while creating a campaign for different channels such as Push, Email, SMS, In-App, Facebook, Flows, etc.

### Custom Segment Analysis

Users of a custom segment can be analyzed on the MoEngage Analytics pages - [Behavior](/user-guide/analyze/analytics/behavior/behavior-overview), [Funnel](/user-guide/analyze/analytics/funnels/funnels-overview), [Retention](/user-guide/analyze/analytics/retention/retention-overview), [Session & Source](/user-guide/analyze/analytics/session-and-source/session-and-source-overview), [User Paths](/user-guide/analyze/analytics/user-paths/user-paths-overview) & [RFM Segments](/user-guide/segment/create-segments/rfm-segments). By default, all users are analyzed for the above-mentioned analysis. To analyze users of a specific custom segment, select the desired custom segment from the custom segment dropdown. Provide the other required parameter for the respective analysis and hit the 'Apply' button. This provides the desired analysis for a respective custom segment.

# Archive Segment

To archive a segment, perform the following steps:

1. On the sidebar menu in MoEngage, hover over the **Segment** menu item <img alt="Screenshot 2025-06-16 at 3.25.14 PM.png"  src="/images/moengage_d125fa.png"  />  . The **Segment** menu appears.
2. Click **All Segments**.  
    <img alt="Screenshot 2025-06-23 at 2.11.56 PM.png"  src="/images/moengage_ef53fc.png"  />   
   The **All Segments** page appears.
3. In the **Search custom segment** box, type the name of the custom segment that you want to archive.
4. For the selected custom segment, click the ellipsis and select **Archive**. <img alt="Custom_segment_archive.png" src="/images/moengage_80ee69.png" />

For custom segments:

- Archived custom segments are not available in the custom segments dropdown on the MoEngage dashboard. If an archived [Rule/Filter-based Segment](/user-guide/segment/getting-started/types-of-segments) is used in the campaign, the segment gets calculated based on the rule/filters. If an archived [File Segment](/user-guide/segment/create-segments/file-segments) is used in a campaign, the segment will return 0 users.
- Custom segments that have not run (query not executed) in the last 60 days are automatically archived.
- All the users from the archived [File Custom Segment](/user-guide/segment/create-segments/file-segments) are dropped after 30 days of archival. Hence after 30 days of archival, the archived custom segment returns 0 users.
- You can mark an expiry time for the file custom segments using [Custom File segment API](https://developers.moengage.com/hc/en-us/articles/4405027805844-Custom-File-Segment-API). After the expiry time, all existing users from the custom segment are dropped, and the custom segment is archived.
- Custom segments cannot have the same name, even when one of the segments is archived.
- `All Users` is reserved by MoEngage and cannot be used as a custom segment name.
- Custom segment names cannot contain the characters `:` `|` `*` `?` `\` `<` `>` `=` `$` `"`, cannot start with a period (.), cannot consist only of whitespace, and cannot exceed 200 characters. These rules apply to the name only, not to the values inside an uploaded file.
- A segment with an invalid or reserved name is rejected. When the segment is created through the API or an external integration, the rejection can be silent: the segment does not appear in the custom segment dropdown or shows zero users.

# FAQs

<Accordion title="Why Is the Custom Segment Count Less Than the Import User Count?">

### Problem

When you upload a set of users through the **Import users** feature, you may notice that the count of the corresponding custom segment is less than the total number of users uploaded.

### Explanation

The following reasons typically cause this discrepancy:

- **Duplicate users in the file:** If there are duplicate user IDs in the uploaded file, MoEngage will reject or ignore these duplicates. As a result, the total number of users in the dashboard will be less than the number of users uploaded.
- **Users are not part of the dashboard:** This scenario occurs when you attempt to update existing users through **Import users**. If some users you tried to upload are not included in the custom segment, search for those users on the Create segment page. If you cannot find them, those users are not yet part of the dashboard.

For more information, read [Import User Data Using CSV](/user-guide/data/imports/file-based-imports/import-user-data-using-csv) and [Custom Segments](/user-guide/segment/create-segments/manage-segments).

<Accordion title="Why Do Date Range Filters Fail Sometimes for Custom Attributes in Segmentation?">

### Problem

The data type of a custom attribute changes automatically, which alters the filters available during segmentation.

For example, if the custom attribute **Subscription Date** is ingested with the **datetime** data type, it should allow date-based filters such as **before**, **after**, or **between**. However, sometimes, the **datetime** data type may change to **string**. This results in string-based filters like **does not contain**, **contains**, **is empty**, or **not empty** appearing instead of date filters.

### Solution

Perform the following steps:

1. **Verify the data type of the custom attribute**: Check if the data type is incorrectly set to **string** instead of **datetime.** If so, change it to **datetime** to avoid causing issues when creating segments based on date ranges.
2. **Report the issue to the admin**: Inform the admin that multiple data types are being ingested for the same attribute. Request them to pin the correct data type (datetime).
3. **Create a new custom attribute**: Create a new attribute with a name similar to the existing one to track the date value.
4. **Import the values with the correct data type**: When importing data for the new attribute, ensure the datetime data type is used.

<Info>
After you create the new attribute and import the date values using the correct data type, you can create segments within a date range based on the custom attribute.
</Info>

</Accordion>
<Accordion title="Why Does the Error 'Custom Segment Name Already Taken' Occur?">

### Problem

While creating a custom segment, the following error occurs:

The custom segment name that you have provided is already in use by some other team. Please use a different custom segment name.

### Solution

Perform the following steps:

- Check if the custom segment is in the Archived list
- Verify if the segment has been archived for more than 180 days.
- Custom segments that have not been run (query not executed) in the last 60 days are automatically archived.
- Custom segments cannot share the same name, even if one is archived.

<Info>
The segmentation backend maintains segment referrals and prevents the creation of segments with the same name, even if the original is archived and not visible in the dashboard.
</Info>

</Accordion>
