# Overview

API keys are typically used as an authentication or authorization mechanism. They are unique identifiers associated with access to API resources.

API keys help ensure the security and accountability of API access, allowing you to manage and monitor usage effectively.

The multi-API key feature is currently supported for the following APIs:

| API | Supported Auth Types |
| --- | --- |
| Data APIs | Basic Auth, OAuth 2.0 |
| Segmentation APIs | Basic Auth, OAuth 2.0 |
| Push APIs | OAuth 2.0 |
| Campaign APIs | OAuth 2.0 |
| Offering APIs | OAuth 2.0 |
| Decision Policy APIs | OAuth 2.0 |
| Inform APIs | OAuth 2.0 |
| Dashboard & Analyze APIs | OAuth 2.0 |

To send data to MoEngage, you can use the Workspace ID and key for that particular API. Whenever a key is regenerated, the old key expires immediately and it takes some time for the new key to become functional, which may result in service interruptions. MoEngage provides multiple API keys to help you avoid this situation:

- **Generate a new key while the existing key is still available**: With multi-key support, the existing key remains active until the new key becomes functional. This allows you to rotate keys for security purposes without causing downtime. For example, if your team needs time to integrate a new key, the old key continues to work during that period. After the new key is integrated, you can archive the old one.
- **Use different keys for different teams**: You can create separate keys for different internal teams or external vendors, each scoped to the APIs they need. This provides granular access control and improves security across your organization.

# Authentication Types

MoEngage supports two authentication types for API keys:

- **Basic Auth**: The standard authentication method using an API key and secret. Suitable for server-to-server integrations where token expiration is not a requirement.
- **OAuth 2.0**: A token-based authentication method that issues short-lived access tokens. The token expiry time is customizable, and the backend validates access tokens automatically.

# Create a Key

<Info>
  - After the multi-API key feature is enabled, the existing API keys in the API dashboard are migrated to your new API key dashboard as legacy keys.
  - You can view the legacy key (autogenerated previously when the workspace was created and migrated to this new dashboard) details and continue to use them. However, archiving, editing, and regenerating legacy keys is not supported.
  - MoEngage recommends creating and using new keys, as legacy keys will be deprecated in the future.
</Info>

1. On the left navigation menu in the MoEngage dashboard, go to **Settings** \> **Account** \> **API keys**.
2. Click **+ Create new key**.
   <Frame><img src="/images/create-new-key.png" alt="Create new key button highlighted on the API Keys page" /></Frame>
3. In the **Create new key** dialog, enter the key details.
   <Frame><img src="/images/create-a-new-key.gif" alt="Animation showing the steps to create a new API key in the Create new key dialog" /></Frame>
4. Enter a name in the **Key name** box. The key name must not exceed 100 characters.
5. Under **Auth type**, select the method you want to use:

<Tabs>
  <Tab title="Basic Auth">
    1. Select **Basic Auth** to use the standard API key and secret for authentication.
    2. Under **Select APIs for access**, select the APIs you want to access using this key:
       - Data APIs
       - Segmentation APIs
       - Push APIs
       - Campaigns
       - Offerings
       - Decision Policy
       - Inform
       - Dashboard & Analyze
    3. Use **Select all** or **Deselect all** to manage selections. Click **View API documentation here** to open the relevant API reference.
  </Tab>
  <Tab title="OAuth 2.0">
    1. Select **OAuth 2.0** to authenticate using short-lived access tokens.
    2. In the **Access token expiration** field, enter the token lifetime in minutes. The value must be between 5 and 60 minutes. The recommended value is 15 minutes.

       <Info>
         This field is visible only when **Auth type** is set to **OAuth 2.0**.
       </Info>

       <Warning>
         The access token expiration value must be between 5 and 60 minutes. Values outside this range are not accepted.
       </Warning>

    3. Under **Select APIs for access**, select the APIs you want to access using this key:
       - Data APIs
       - Segmentation APIs
       - Push APIs
       - Campaigns
       - Offerings
       - Decision Policy
       - Inform
       - Dashboard & Analyze
    4. Use **Select all** or **Deselect all** to manage selections. Click **View API documentation here** to open the relevant API reference.
  </Tab>
</Tabs>

6. Click **Save**. After saving, the key is listed under **Active API keys**.

# View Active Keys

On the **API Keys** page, the **Active API keys** table shows the following columns:

| Column | Description |
| --- | --- |
| Key name | The name assigned to the key. |
| Auth type | **Basic Auth** or **OAuth 2.0**. |
| Created on | The date and time the key was created, along with the email address of the user who created it. |
| Key | The masked key value with a view button and a copy button. |
| Actions (<Icon icon="ellipsis-stroke-vertical" />) | Options to manage the key. See [Manage Keys](#manage-keys). |

You can search for keys using the search bar. The count of active keys is displayed above the table.

# Manage Keys

On the **API Keys** page, click <Icon icon="ellipsis-stroke-vertical" /> for a key to see the following options: <Frame><img src="/images/manage-key.png" alt="Key action menu showing View key details, Regenerate key, Edit key details, and Archive key options" /></Frame>

| Option | Description |
| --- | --- |
| [View key details](#view-key-details) | View the full details of the key. From the details panel, you can also access **Edit key details** and **Regenerate key**. |
| Regenerate key | Generate a new key. |
| [Edit key details](#edit-key-details) | Edit the key's name or API access settings. |
| Archive key | Archive the key. Archived keys cannot be unarchived. A maximum of 10 archived keys is maintained in the archived key list. |

<Warning>
  The old key expires immediately after regenerating. Replace the old key in your integrations to avoid errors.
</Warning>

### View Key Details

1. On the **API Keys** page, click <Icon icon="ellipsis-stroke-vertical" /> for the key you want to view.
2. Click **View key details**. The details panel shows:

| Field | Description |
| --- | --- |
| Key name | The name assigned to the key. |
| Auth type | **Basic Auth** or **OAuth 2.0**, depending on the method selected when the key was created. |
| Access token expiration | The token lifetime in minutes. |
| API key | The masked key value with a view button and a copy button. |
| Last updated on | The date and time the key was last modified, along with the email address of the user who made the change. |
| Created on | The date and time the key was created, along with the email address of the user who created it. |
| Select APIs for access | The APIs selected for this key, with checkmarks indicating the enabled options (Data APIs, Segmentation APIs, Push APIs, Campaigns, Offerings, Decision Policy, Inform, Dashboard & Analyze). |

From the details panel, you can click **Edit key details** or **Regenerate key** to perform those actions.

<Frame><img src="/images/edit-regenerate-key.png" alt="Edit key details and Regenerate key buttons on the key details panel" /></Frame>

### Edit Key Details

1. On the **API Keys** page, click <Icon icon="ellipsis-stroke-vertical" /> for the key you want to edit.
2. Click **Edit key details**.
3. In the **Edit key details** dialog, edit the available fields:

<Tabs>
  <Tab title="Basic Auth">
    | Field | Editable |
    | --- | --- |
    | Key name | Yes |
    | Auth type | No |
    | Select APIs for access | Yes |
  </Tab>
  <Tab title="OAuth 2.0">
    | Field | Editable |
    | --- | --- |
    | Key name | Yes |
    | Auth type | No |
    | Access token expiration | Yes |
    | Select APIs for access | Yes |
  </Tab>
</Tabs>

4. Click **Save**. The **Save** button remains disabled until you make a change.

### View Archived Keys

1. On the **API Keys** page, click **View archived keys**.
2. The archived keys list opens with the following columns: Key name, Auth type, Archived on, and Key.

# Audit Logs

<Frame><img src="/images/auditt-logs.png" alt="Audit logs page showing API key actions" /></Frame>

Admins use audit logs to track actions performed in the MoEngage dashboard. The audit logs include all actions related to API keys, helping admins identify who performed each action and when. The following actions are supported in **Audit logs**:

- Click <Icon icon="bars-filter" /> to filter audit logs based on **Team(s)**, **Action**, **Actor**, and **Date time Range**.
- Type a value in the **Search logs by** search bar to fetch the relevant audit logs.
- Click **Export audit logs** to receive the audit log report by email. The email includes a download link for the report.

For all actions related to API keys, the **Entity** column in **Audit logs** displays **API Keys**. The **Action** column shows the following values:

- **Create** is displayed when an API key is created successfully.
- **Update** is displayed when:
  - A key name is updated.
  - The API selection for a key is updated.
  - A key is regenerated.
- **Delete** is displayed when a key is archived.
